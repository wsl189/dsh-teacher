# @deepseek-ai/dsh-host-teacher-workbench

English | [中文](README.zh.md)

## Summary

Host-owned persistence, ordinary-conversation tool operations, question media, document generation, weather access, and timetable normalization for the Web teacher workbench. The plugin stores one schema-validated, revisioned document through `ctx.storageDomain` and exposes `teacherWorkbench/read` plus compare-and-set `teacherWorkbench/write` Remote methods. The companion `@deepseek-ai/dsh-tool-teacher-workbench` Consumer registers seven model-facing tools that let an ordinary agent read and change Daily Management, Timetable, Student Roster, Score Analysis, and Question Cutting through the same authoritative operations used by the browser. Dedicated question Remotes atomically save, read, replace, delete, assign, and render stored images without sending server paths to the browser. `teacherWorkbench/weather` resolves a configured district, county, or city through a Nominatim-compatible endpoint, fetches the forecast from Open-Meteo, validates both responses, and returns stable lookup, availability, or response errors without requiring the browser to contact either provider directly. When browser-side MinerU reconciliation finds no entries, `teacherWorkbench/normalizeTimetable` starts a short-lived child agent loop under the current session, selects `ctx.agentDefaultModel.currentToolSelection()`, exposes run-scoped source, matrix-submission, and line-splice patch tools, and accepts only a token for a matrix validated in that run before the browser may review rows. The optional `ctx.mobileNotifications` provider supplies a credential-free bot roster to `teacherWorkbench/listNotificationTargets`; the Remote returns only platform, opaque bot id, display label, and current connection state.

## Use this package

The version-10 document contains daily tasks, memos, ledger categories and entries, dated calendar items, normalized weekly timetable entries, lesson resources, classes and students, exams, family-notice templates and saved drafts, reusable record templates, authored teaching and headteacher records, class seating layouts, question-library folders, paper-batch metadata, nested student question folders, and student question assignments. Each seating layout belongs to one roster class, contains exactly one slot for every configured row and column, and may reference only that class's students without duplicate occupants; deleting a class removes its layout, while deleting a student clears that student's seat. Ledger entries reference one durable category, store a required local date and time, and represent CNY amounts as non-negative integer cents; deleting a category removes its entries in the same revisioned write. Every class belongs to exactly one catalog: roster classes own students and exams and supply Question Cutting and seating, normal timetable classes are selectable by Today, Week, and Morning/Evening Study, and grade-timetable classes are selectable only by Grade. The schema rejects ledger, student, exam, seating, or timetable references whose owner is absent or crosses those catalogs, while identical class display names may retain independent identities in each catalog. Each timetable entry occupies one unique class/type/weekday/period slot; deleting a class also removes its schedule. Question folders and assignments reference durable students and source images; deleting a folder, student, class, image, or batch removes its dependent metadata and best-effort cleans its owned files. Daily-management, teaching, and headteacher edits share one revision, so concurrent browser windows use the same compare-and-set conflict handling. Browser code never writes Local Storage; every accepted mutation lands in the storage backend selected for the `teacher_workbench` domain. Daily tasks, memos, ledger entries, and timed calendar items may carry one mobile reminder containing the selected platform and bot, a deadline-derived UTC instant, and either a one-time lead or fixed repeat interval. Memos and ledger entries retain an independent optional reminder deadline instead of reusing their edit or expense time. The Host recomputes timers from the durable document after startup and every write, retries unavailable delivery until the deadline, advances each occurrence only after provider acceptance, and stops projecting reminders for completed or deleted items; documents without reminder fields do not schedule or send anything.

## Question Image Storage and Output

Numbered layout landmarks from equal-sized selected pages are clustered into repeated horizontal lanes, including theory headings that are excluded as learner questions. When one page leaves a later lane empty, the next lane start limits the preceding region even without vertically overlapping foreign content; recognized owned content that crosses that start disables the inferred limit. This keeps a half-empty imposed spread near one printed-column width without introducing a document-specific gutter coordinate.

Visual review and local recuts retain the initial PDF-wide outlier-filtered width; revised source limits cannot reintroduce an excluded width before another review pass or final persistence.

Only the initial visual pass is a complete-group review. Every follow-up recut is crop-local, even when its affected ids happen to cover every current question in the group, so browser and ordinary-conversation callers keep only the affected pages and adjacent context. The Host uses the recut phase rather than id-count equality for the same classification, avoiding both an erroneous `a complete-group review must preview every core page` rejection and an unnecessary resend of every core-page preview.

Selected pages are copied into MinerU requests bounded by the provider's advertised page and byte limits; the Web bundle advertises five pages per normal request. When one multi-page layout request fails, the Host bisects that exact page set and retries each half, recursively reaching single-page requests when necessary. A single-page failure remains terminal because no safe geometry can be inferred without OCR, while a provider peak-memory failure on a dense batch no longer discards every selected page immediately.

After all semantic groups merge, `segmentQuestions` derives one normalized safe-lane width per question, uses the median as the majority baseline, and excludes a width more than `maxQuestionWidthOutlierExcessRatio` above that baseline from the PDF-wide maximum. The boundary child infers the document's own semantic question structure from source-page previews and OCR elements and submits the complete ordered question-head list; Host candidates are fallible recall hints and do not restrict which OCR text element may begin a question. Boundary timeouts, model failures, and exhausted validation attempts fail the group without inferring or saving an unverified replacement. The Host adds narrow structural safeguards: a recognized hierarchical section, answer heading, or answer/analysis block is an exclusive stop that cannot become a question head, and a bracketed source citation cannot become a standalone question unless it owns actual problem content. The Host validates opaque element references and ordering, assigns unclaimed elements through layout-derived horizontal lanes, and treats a model-selected per-question `stopBeforeElementId` as an exclusive hard ownership stop: it is the first outside element and cannot also be claimed as question content. An explicit attachment is rejected only when a vertically overlapping question head is horizontally closer than the claimed owner, so a right-column diagram is not blocked by a left-column head at the same height. Each region records the nearest right-side limit imposed by vertically overlapping content outside that question, inset by the configured padding without clipping owned content, and its bottom cannot pass a later accepted head in the same horizontal span even when an oversized OCR image box crosses that head. A whitespace gap between adjacent owned and foreign boxes is split at its midpoint; when neighboring head boxes overlap by no more than the configured padding, both crops instead share the later head's top as one hard cut line, so neither crop imports the other head. Automatic ownership ends before a trailing cluster separated by more than `maxQuestionAutoOwnedGapRatio` of the page height unless that cluster contains an explicit attachment. An explicit attachment seeds its horizontal lane through the next semantic or question stop; a page-bottom stem that continues at the top of a disjoint column becomes multiple source-safe slices concatenated in OCR reading order, rather than one rectangle containing the intervening page. A head-bearing slice keeps the question head's left coordinate even when an explicit ownership claim reaches into another column; a detached claimed block that extends farther left becomes a separate slice instead of moving that origin. This keeps detached answers, decorations, and later-paper material out of a final question while allowing the child to retain a distant diagram deliberately. Excluded source boxes that do not overlap an owned element are recorded as white erasures. Browser and ordinary-conversation renderers preserve each region's left, top, and bottom coordinates. The output right edge is always the fixed left edge plus the PDF-wide maximum non-outlier normalized safe-lane width; source sampling stops at each region's inset horizontal limit and the remainder stays white, so equal-width output preserves unrecognized answer lines without importing gutter or neighboring-column pixels. The first complete-group visual review compares every preliminary crop with every core source page. It may recover an independent question on any core page even when no Host candidate predicted it, and a crop containing several independent answer demands is defective rather than a valid collective question. Review metadata identifies pages by their exact `page-x` tool ids and flags detached same-page slices, erased or edge-touching source images, source sampling that extends beyond owned OCR content, and crops touching a physical page edge for explicit visual resolution. A verified crop must name its actual topmost, bottommost, leftmost, and rightmost non-white pixels, account for every required source visual, and resolve each flag; otherwise the reviewer records a crop-local defect. Later recuts receive only cited questions and their local source pages. In those crop-local passes, unlisted questions visible on a supplied page remain unchanged boundary context; the Host rejects every page-only missing-question finding and complete-group replacement. Clean crops finish without OCR calls. A review child that invents a final token before recording a defect is replaced by a fresh child with reset inspection and submission state. Semantic and schema failures share a bounded failed-call allowance; repeated valid evidence reads do not consume it. Once preliminary boundaries provide Host-validated crop geometry, preview preparation failures, unclean review stops, visual-review timeouts, model or provider errors, invalid output, thrown calls, and teardown failures no longer fail the PDF. Callers retain the current safe group, mark every question in the current review scope as unverified when no complete defect set exists, and continue later groups. Once complete crop-specific findings exist, repair exhaustion, timeout, or model stop returns only the cited question ids as unresolved so the warning remains crop-local. Recorded defects remain immutable during the review and require a validated repair followed by visual verification. For crop-specific defects, it reads OCR geometry and submits corrections for the cited stable heads; the Host validates those patches with all neighboring heads present, merges only cited geometry, preserves every untouched question, and extends the existing region directly when the only change is an omitted attachment. A `trim-right` finding may reduce only the cited slice's source-pixel limit; its fixed left edge and the PDF-wide output width remain unchanged, and white padding replaces the removed source area. A crop finding remains local even when it also cites its source page as visual evidence. Restoring an explicitly cited attachment also removes an overlapping white erasure while preserving unrelated erasures. A QR code, publisher resource label, or optional dynamic-demo block is page furniture unless the stem explicitly requires it; excluding its image also requires excluding a compact connected caption so no orphan label remains. A spurious crop can be removed locally through one crop finding that declares `remove-crop`; a source-page id may be included as visual evidence but is not required for local removal. A page-only finding is reserved for a wholly missing independent question with no one-question crop and must include that problem's visible `missingQuestionHead`; it may cite a larger crop that contains the missing problem's pixels, but it always requires a candidate-complete group replacement. Distinct missing heads on one page remain separate findings. The Host rejects a correction that leaves any cited crop unchanged. At most three local recuts are applied, followed by a final visual verification. A crop still unresolved after that verification is saved from its latest Host-validated regions, counted as unverified, and does not stop later groups.

Question-image hints and mandatory ownership decisions use only learner-owned core pages. Answer or explanation pages remain semantic stop context, so a solution-only diagram cannot invalidate an otherwise valid question draft.

Crop-local annotated pages cover every unrelated horizontal lane with an opaque gray mask. Masked pixels cannot support missing-content or contamination findings, while unmasked same-lane questions remain read-only boundary context and adjacent continuation pages remain available. Whenever visual review cannot finish, browser progress reports the number of unverified question crops and ordinary-conversation results report the number of affected groups; complete findings keep this scope to their cited crops, otherwise it covers the current review set. Each latest Host-validated crop is saved and later groups continue.

When a continuation page also contains multiple new questions, local lane reassignment retains page-leading option, subpart, or visible answer-demand elements under their previous-page ordinal owner. A later accepted question, section, answer, or explanation boundary still ends that continuation, so completing a split question does not import the next task.

Thin answer lines, boxes, and other response marks that OCR omits must be proven by visible crop pixels rather than inferred from the source prompt. A missing edge mark authorizes a crop-local vertical correction. A missing learner answer-demand clause or requested solution set is not a request to include a supplied answer; its expansion still requires source evidence and cannot cross a neighboring question head.

Every existing-crop defect declares whether correction must expand or trim its top or bottom, trim unrelated pixels from its source-sampled right edge, reassign referenced content, or remove a spurious crop. Mentioning a valid stem or subpart as a location reference does not make it the removal target; required-content protection validates the actual repair rather than rejecting those words. The Host rejects a boundary edit that moves in an undeclared direction. Content transferred across two adjacent crops requires complementary findings and geometry changes for those two crops; every uncited crop remains byte-for-byte unchanged and outside the next local review.

`teacherWorkbench/saveQuestionBatch` validates PNG, JPEG, or WebP payloads, generates opaque ids, and commits one bounded save part only after every image has reached owned storage. The first part creates the paper-batch metadata; a continuation names that opaque batch id, must repeat its source metadata and destination, and appends files and image metadata to the same library entry. Its required destination selects one of three physical locations: the configured library root, a root child derived from the source PDF name, or one current-root leaf. The Web question cutter uses the source-name child when its directory control remains blank and the selected leaf otherwise; saving to a scanned leaf adopts only that leaf's visible ancestry into durable folder relationships. Ordinary-conversation `segment_pdf` has no default: the current user request must explicitly name the question-library root or one complete existing leaf path, and the Host rejects a missing or model-guessed target before OCR begins. The paper-batch id never creates a storage directory. Large source papers are not subject to one part's aggregate byte ceiling because the browser saves successive semantic page groups and further divides a group by decoded image bytes when needed. `readQuestionImage`, `replaceQuestionImage`, `deleteQuestionImage`, and `deleteQuestionBatch` operate on files selected by the latest current-root scan; the Host resolves their opaque ids back to validated regular files below the active roots before each mutation. Metadata-backed targets also update their durable relationships, while scanned files without matching metadata remain fully editable and are reflected by the next scan. Renaming a durable library directory moves its physical subtree; deleting one atomically detaches the physical subtree and removes its batches and dependent student copies instead of reparenting any image. The model-facing image reader turns one resolved image into a durable attachment only for an image-capable route and reports the original pixel dimensions; rectangle erasure samples surrounding pixels and replaces the selected stored raster only after every rectangle passes bounds validation. `assignQuestions` creates independent copies in the selected current-root student directory; metadata-backed source and destination combinations retain durable assignment relationships, while every other combination is copied directly and discovered on the next scan, so later editing or deleting one student's copy cannot change the source batch or another student's work.

`generateQuestionDocument` builds a downloadable Word or PowerPoint document from selected batch or assignment images. `generateUploadedQuestionDocument` accepts browser-selected directory images without persisting them. `saveTemporaryQuestionSelection` replaces one currently visible student's previous temporary selection with independent image snapshots and atomically increments durable save counts and latest-save times for selected assignments represented in the revisioned document; all other current-root images are equally eligible without creating assignment metadata. `listTemporaryQuestionSelections` reports which requested current-root students have staged images. Every Office path orders images by the authoritative source question number, falls back to a question number parsed from the display file name, and only then uses natural file-name ordering; temporary-manifest reads reapply the same rule so selections staged by older versions are corrected at generation time. `generateStudentDocuments` returns one independent Word or PowerPoint artifact per eligible student visible below the current root, with per-student Word title, name, and date choices plus an explicit skipped list. Its omitted source follows the Question Cutting UI and reads temporary snapshots; assigned images require `source: 'assigned'`. A successful temporary-source generation removes that student's selection. Word output preserves the reference A4 margins and metadata flow; PowerPoint output preserves one top-left, non-upscaled image per 13.333-by-7.5-inch slide. Image dimensions, decoded byte limits, target references, containment, file names, and generated output are validated on the Host; temporary image bytes remain outside the durable document, while durable per-assignment usage statistics survive generation and restart.

Compact visual reviews put core pages and adjacent context on separate sheets. Each page header repeats the PDF page id and either `CORE` or `CONTEXT ONLY`; context pages remain visible for continuation checks but cannot supply missing-question claims for a core page.

OCR, repair-context, and preview queries can be repeated without consuming the failed-call budget; preview queries reuse stored attachments. Initial boundary and complete-group repair submissions retain their draft for per-element `corrections`, with every complete-result and repair-scope check preserved. A correction can replace the document-final `stopBeforeElementId` or explicitly clear it with `clearStopBeforeElementId`; an empty corrections array is allowed only for that final-stop edit, and all unlisted question decisions remain intact. `headConvention` is optional descriptive metadata. Missing-question findings require a complete group replacement and may omit `repairIntents`; existing-crop findings require nonempty intents. Invalid requests and child deadlines remain bounded.

Compact crop-local repair exposes only the context reader and `repair_question_crops_*`. Its flat `repairs` rows name a cited `cropId`, exact `pageId` when supplying coordinates, and only the changed geometry or content decisions. The Host resolves stable heads and zero-based page indexes before applying the existing validator. Uncited targets, conflicting rows, undeclared directions, clipped learner content, and silent image removal are rejected. A validated outside decision may remove an entire leading or trailing page slice and satisfy its trim intent; accompanying coordinates must still be in-page trims of an original slice, never an expansion or invented page. Trimming, reassignment, and removal contexts include all sampled OCR inside the crop, not just edge strips; required chunks remain bounded and must all be inspected. Local recovery retains this flat draft without exposing complete-group fields.

OCR transport does not select image-classification policy. The complete compact source uses the inline character limit independently of the expanded source-chunk count. Larger evidence uses required bounded reads; without supplied page previews it still uses Host-owned image geometry and prohibits model-directed pixel exclusions. Only a child that inspects supplied page images makes full visual image classifications. Both OCR-only paths require the same complete question decisions and later crop review.

## Configuration

Boundary recovery with a retained draft exposes only a dedicated correction tool plus required evidence readers. Its schema accepts an element-decision array, not a complete question list or root classifications. A short correction persona replaces the initial segmentation instructions, while the same validator, source-inspection requirements, and child limits remain authoritative.

In crop-local repairs, an explicitly retained image preserves its existing question owner even when OCR places it before the question head. The Host validates this ownership as an attachment before rendering; explicit conflicts, duplicate ids, cross-question ownership, and unauthorized image removal still fail. Complete-group replacement does not infer an old owner for a new question.

An element correction also removes that element's stale attachment assignments before applying its new role. Compact visual verifications require the same four edge descriptions and required-visual evidence as separate-image reviews. The Host does not substitute task evidence for unreported crop-edge observations; missing or empty edge evidence rejects the classification.

Repeated OCR opening delimiters preserve question-head, citation, and subordinate-item recognition without changing source text or coordinates. Qualified solve instructions such as solving an inequality about a real variable protect the cited parent question and keep its numbered subparts together. Context-head rejections include exact omit corrections. Compact boundary schemas omit pixel-exclusion operations. During a validated content-reassignment or vertical-trim repair, explicit outside markers stop both ownership and required-text preservation; bare stop coordinates or exclusions cannot reclassify learner text. Removing an unrelated image requires an authorized trim or reassignment finding and explicit image-and-caption exclusions. Visual attention requires source-to-crop checks for sampled tables through their bottom grid line and for unfinished OCR response tails that may precede an unrecognized drawn answer mark. A following visual review must verify the change. A selected question head cannot be attached to another question; a rejected ownership conflict cannot produce a headless crop.

Compact visual submissions report all classification-reference errors together and do not retain entries from an invalid-reference submission. Valid partial submissions that fill missing classifications or checks return `INCOMPLETE`, retain an unaccepted draft, and do not consume the failed-call allowance. Follow-up calls can supply only missing or corrected rows, attention checks, or image checks; omitted arrays leave the draft unchanged. Rejected calls share one allowance by normalized diagnostic category: repeating the same invalid decision exhausts it, while a correction that reaches a different diagnostic resets the repeat count. Forbidden tools share one category, and child deadlines still apply. Exhausted compact visual children can use the remaining configured recovery runs, carrying only validated draft rows and the last error into fresh image inspection; recorded defects cannot be discarded. Every crop and required check must be complete before acceptance; an omitted check is never inferred from other evidence. Crop metadata carries a bounded OCR head excerpt for identity matching, not as evidence that the corresponding pixels were cropped correctly.

Same-page ownership applies every relevant stop in its physical column, not the interleaved OCR array order; another column's head cannot truncate subparts or figures. A detached score label or recognized question prefix and its following unnumbered stem cannot become separate questions without an independent demand owned by the prefix. An explicit attachment cannot steal the next same-column question's body; the diagnostic names the attachment and both owners instead of treating the emptied head as a disposable label. Parenthesized questions with an explicit response demand in the head or its continuation before the next sibling become recall candidates after a section transition, while parented subparts remain inside their question; a following same-level item ends a standalone item even when OCR represents that heading as a table. Reference-summary transitions such as knowledge reviews, formula summaries, and method recaps suppress their numbered procedural subpoints from that standalone-question shortcut, while a later practice section can enable genuine response tasks again. When source previews first arrive with segmentation or the complete initial review, source pixels can extend an unfinished response crop through a nearby thin horizontal answer line omitted by OCR, bounded by the next source block and other crops. Recovery after the initial full-group classification returns revised geometry and requires re-rendering and a new local visual review; it never skips review of the other crops. No line is invented when the raster contains none, and later explicit visual repairs remain authoritative. Explicit image-and-caption exclusions are calculated against the final sampled rectangle after coordinate edits, so changing a boundary cannot silently restore excluded pixels.

Crop-local repairs preserve earlier accepted crop edges and erasures unless a recorded expansion or explicit content restoration authorizes adding pixels back. Removing another page slice cannot reconstruct previously removed furniture. OCR-only classification retains protected learner heads until pixel-backed review can remove a false positive. Short outline titles without a learner demand stop preceding ownership independently of textbook wording. Original watermarks, stamps, or scan defects overlapping required task pixels remain in the crop; cutting does not restore the source document. Separable unrelated blocks still require removal.

Text-bearing OCR images and tables participate in question-head and section recognition without changing their original raster boxes. A Chinese response blank represented by one underscore before punctuation is distinct from a mathematical subscript. Source sheets identify unsampled readable context with a translucent gray wash, while actual crops have separate labels and cyan frames. `sourceImageSampling` reports which final crops sample each OCR image. Every sampled image in a verified crop requires an `imageChecks` role and visible evidence: required task content, an overlapping source overlay, or unrelated content. Missing checks prevent acceptance; an unrelated classification requires a crop finding, and an unsampled source image cannot support an inside-crop check. Valid incomplete checks remain an unaccepted draft. An unfinished conditional conclusion remains learner-blank evidence without a subject-specific vocabulary. Bare parenthesized figure labels cannot stop their owner's content or borrow a later same-number question's demand. Boundary and review instructions preserve supplied reference formulas and data through the complete appendix, distinct from worked answers.

OCR image metadata includes recognized text and the crops for which the image is the question head. A retained head must be classified as required content, even when the box contains only text; only a justified whole-crop removal can discard it. A retained-image type error names the offending id, its actual type, and the valid core-page image ids. A vague claim cannot remove a crop protected by an OCR answer-demand heuristic, but pixel-backed review may override a false positive when it names the theory, method summary, answer, solution, or other non-task category and explicitly confirms that no independent learner answer demand is visible. A page-only missing-question finding is rejected when its own evidence says that no independent learner problem or answer demand exists; a clean zero-question page uses an empty findings list. Findings that say pixels still need checking or confirmation are not recorded as visual defects. Image-role diagnostics attribute the classification to the reviewer, not Host detection. Forbidden-tool diagnostics list the exact allowed names so a misspelled run suffix can be corrected without widening tool access. Omitting a target from a multi-target repair-context read returns the available ids without charging a failed call, while invalid supplied ids still fail. Direction errors report current and submitted edges plus the directions authorized by the finding.

Both inline and chunked OCR evidence label core and context pages, and both boundary personas request tool submissions without prose analysis. Rendered crops repeat their source Q labels beside stable crop ids. Each boundary or compact repair child has its own failed-call allowance. Exhaustion can start a fresh child within `maxQuestionBoundaryAgentRuns`, retaining the latest rejected draft and diagnostic while requiring fresh source inspection. The complete-draft allowance counts rejected, reference-valid drafts only: a corrected valid draft is still accepted after the allowance is used, while reaching the rejected-draft limit ends that child immediately instead of letting it repeat the same rejection. Individual correction calls never reset an allowance, and recorded visual defects cannot be withdrawn by recovery.

A recoverable boundary-child failure is isolated to its semantic page group. Other groups continue, while the failed group enters complete-page visual review as an empty preliminary group; that review can reconstruct Host-validated boundaries from the page evidence. If recovery still cannot converge, the group is reported as unverified and skipped while usable questions from other groups are saved. If every boundary group stops with a model or provider failure before producing geometry, the operation instead returns the first safe provider diagnostic and skips redundant empty visual reviews. Invalid requests and unavailable model or vision configuration remain terminal because retrying another group cannot correct them.

The question-cutting reasoning switch is available below Save directory in the PDF page-range panel, while storage fields remain in **Settings → Plugins → Plugin configuration → Document extraction** under the `teacher-workbench` settings namespace. The Web bundle defaults reasoning to off and media, source, and generated roots below `~/.dsh/teacher-workbench/`. A state write that adds a roster class, student, nested student folder, or durable library folder creates its complete physical hierarchy before the revision commits; a failed document commit removes only still-empty directories created by that operation. Retained metadata from another root is never materialized by an unrelated state write. The question workspace recursively projects every non-hidden directory below the current `segmentsRoot`, including empty directories and image-only leaves; direct images appear as a paper row inside their owning folder. It reads both `year/class/student` and `year/grade/class/student` hierarchies below `studentsRoot`, reuses durable identities only for matching physical paths, projects every non-hidden descendant directory below each visible student, and recursively reads its images. Durable classes, students, and folders absent from the current roots remain stored but do not enter the browse result. A student row aggregates images from the complete subtree, while a descendant row selects that exact directory. Changing either root switches the displayed collection without copying files from the previous root. Every class, student, descendant directory, paper, and image found below the current roots participates in the same create, rename, delete, edit, assignment, temporary-selection, and generation actions exposed for that item. The browser submits opaque identities from the latest scan, and the Host revalidates their regular-file or directory paths below the current roots before changing the filesystem. Metadata-backed mutations additionally update the revisioned document; physical items without matching metadata remain current-root content and are rediscovered after the operation. Renaming a durable student hierarchy also commits its display name and adjusted assignment paths with rollback of the physical move when the document write fails.

## Model Experience

### Ordinary-conversation workbench tools

#### What the model sees

With the companion Consumer mounted, every standard Web agent sees the seven schemas in the generated [tool catalog](../../../docs/tool-catalog.md#deepseek-aidsh-tool-teacher-workbench): `teacher_workbench_read`, `teacher_question_image_read`, and one mutation tool for each of Daily Management, Timetable, Student Roster, Score Analysis, and Question Cutting. The section reader returns stable ids from the authoritative revisioned document; Daily Management also returns credential-free `notificationTargets`. The image reader returns one stored batch or assignment raster with its source dimensions, after rejecting routes that do not declare image input. The Question Cutting mutation tool uses source-pixel coordinates to rotate or crop the image or erase up to 32 rectangles with sampled surrounding color; invalid or out-of-bounds edits fail before replacement. Before creating daily data, the Host rereads direct user text from the current agent turn and derives the destination only from literal routing words. A mismatched action such as `save_todo` for a request containing `备忘` or `备忘录`, or a creation request without a routing word, fails before persistence, so model-supplied classification cannot override the user. A reminder mutation must select an exact returned platform and bot id, and the Host rejects invented ids or an elapsed occurrence before committing the item. Mutations retry compare-and-set conflicts against the latest document and return the committed revision, a short summary, and created ids. Timetable mutations map Today, Week, and Study to the `timetable` catalog and the explicit Grade view to `gradeTimetable`; they reject cross-catalog class ids and duplicate imported slots, then read back the affected ids before reporting their confirmed view. Roster, timetable, and score tools consume the hidden OCR Markdown already injected for uploaded documents; an attached image may instead be read directly by a multimodal model. A conversation-uploaded PDF additionally carries an opaque `sourceId` that identifies Host-retained bytes without placing them in the Session log or prompt. The Question Cutting schema directs the parent agent to pass that retained source straight to `segment_pdf`, without pre-extracting it through document-reading, shell, or filesystem tools or creating workspace scratch and sidecar files. If a parent nevertheless creates one, the mutation tool removes only the matching `<pdf-stem>.extract.txt` regular file in the owning Session workspace when it was created or modified during the current turn; an older same-named user file is preserved, and cleanup also runs after a failed cut. Question segmentation resolves the id, obtains MinerU geometry, runs the restricted boundary child, renders and stores crops on the Host, and returns the paper-batch id. `generate_folder_document` recursively reads an ordinary local image directory through `ctx.fs`, builds one naturally ordered Word or PowerPoint file without a roster student or assignment, writes it below `generatedRoot`, and returns its absolute path. Stored batch or assignment targets use `generate_document`; per-student output uses `generate_student_documents`. The latter matches the browser when fields are omitted: it reads temporary selections, uses an empty Word title, and prints neither name nor date; `source: 'assigned'` explicitly selects every assigned image.

#### Token effect

The seven tool schemas extend every ordinary Web model request. Section reads and direct document mutations add only their tool calls and bounded JSON results; a successful stored-image read also adds one durable image attachment to that result and later conversation history. PDF question segmentation also incurs MinerU work and the question-boundary child calls described below; Office generation does not make another model request.

#### KV Cache effect

The stable tool names and schemas become part of the ordinary conversation prefix. Uploaded OCR text, current workbench rows, and tool results vary in the request suffix. Question-boundary child caching remains independent of the parent conversation.

### Timetable normalization child

#### What the model sees

A fresh child receives the upload name, a destination captured when extraction starts, current class/grade/type/teacher defaults, known class names, a run-scoped source tool, a matrix-submission tool, a line-splice patch tool, and a compact final-output schema. A vision-capable route receives one overview plus overlapping enlarged views of a raster source; extracted PDF and Office content and image fallback use compact MinerU regions through the source tool. The child inspects the source, submits one complete source-oriented matrix, and repairs rejected draft lines through 1-based splices while the Host preserves every unlisted line and block. The final output contains only the token for a matrix accepted in that run. The parser tolerates an axis or fields keyword joined to its first argument by an opening parenthesis, but semantic and dimension failures still require an explicit draft repair. The Host accepts repeated local period headers in chronological data order and assigns their later rows distinct periods without assuming source coordinates. Class, Grade, and Study destinations change relevant record semantics but do not prescribe a document layout. Every uploaded string is untrusted data, ordinary tools remain hidden, and the result is returned to browser review rather than the parent conversation.

#### Token effect

Each attempt pays for an independent child run plus source, submission, and patch calls. The selected tool model's configured `contextWindow` and `maxTokens` govern every request; the timetable plugin does not replace either value. Raster uploads start enhanced OCR concurrently with direct vision so a direct timeout or invalid result can immediately start a text child. The Web bundle gives both direct vision and text children a 60-minute wall-clock deadline.

#### KV Cache effect

Independent of the parent conversation cache. Reuse requires the same tool-model route, fixed persona and schema, defaults, and MinerU source; changed source data establishes a different suffix or prefix according to the provider.

### Question-segmentation child

#### What the model sees

A fresh child receives a layout-neutral segmentation skill, exact OCR source-chunk indexes, source-page preview ids, fallible semantic hints, run-scoped evidence tools, and one boundary-submission tool. A Host-accepted submission ends the child without a separate output tool. Source chunks expose opaque element ids, page dimensions, element type, bounding box, and extracted text; previews show the rendered page without becoming a coordinate source. The child inspects every chunk and preview, infers the source's own semantic question convention, and submits every independent top-level task while keeping its subparts, figures, and cross-page continuation together. Each selected head must create an answer obligation rather than merely introduce a numbered definition, formula, method, theory summary, worked solution, or answer. A prompt-bearing worked example still creates a question; its crop ends before the printed answer or analysis. A fully classified group may contain zero questions. The child may use a question-local exclusive `stopBeforeElementId` for the first unrelated element before the next task, `additionalElementIds` when OCR order leaves unmistakable content outside its owner, and, only after inspecting supplied page images, explicit exclusions for non-question elements inside an otherwise valid interval. The Host does not require a numbering syntax, sequential labels, or a fixed column count; exact hierarchical section and answer headings remain enforced safety stops, and citation-only bracket labels require owned problem content. It sorts valid heads by OCR order, validates references, ordering, contradictory ownership, and non-empty geometry, and derives every rectangle without accepting model coordinates. A vertical edge falls at the midpoint of any whitespace gap between owned content and the nearest foreign element; adjacent head boxes with a small overlap share the later head's top as their hard cut line. After preliminary rendering, a separate visual-review child receives every core page for its first complete-group pass, then local source pages for later crop-only passes, with crops in a separate image stream. Its `page-x` labels are authoritative even when printed footer numbering differs; zero-based OCR `pageIndex` remains available only for coordinate edits. A crop-local pass classifies only its listed crop ids; other visible questions remain unchanged, and the findings tool rejects `missingQuestionHead` or any page-only recovery. Each crop label states that a blank white suffix is intentional equal-width padding, and the reviewer may report adjacent-column contamination only for pixels visible in the crop itself. A zero-question group still receives source-page review. Every accepted crop records the visible `answerDemand`, actual topmost, bottommost, leftmost, and rightmost non-white content, and the source-to-crop check for every required diagram or table. The Host adds `visualAttention` when one crop concatenates source slices across a large same-page gap, erases or clips a recognized source image, samples an unowned strip to the right, or reaches a physical page edge where headers and footers may appear; a verified record must resolve every flag in `attentionEvidence`. A crop without one independent task or with an unresolved visual defect is defective. After inspecting every requested image, the reviewer submits one complete `verifiedCrops` and `findings` classification; the Host withholds acceptance for incomplete coverage and rejects invalid references; valid incomplete draft rows can be corrected without repeating the whole classification. A valid defect overrides a contradictory verification of the same crop; once the complete classification records it, repair and a new review are required. A clean classification accepts the images without opening OCR. JSON-encoded arrays are decoded only in schema-declared array fields before the same strict validation; this does not invent omitted fields, coerce evidence text, or accept malformed items. Compact crop-local defects unlock complete sampled OCR and the flat `repairs` tool keyed by stable `cropId`, with exact `pageId` labels for coordinates. Other visual-repair paths use corrections keyed by stable source head; validation retains every neighboring head and the returned complete group retains every omitted correction target unchanged. A crop-cited finding stays local when it includes a page id for evidence. A confirmed spurious crop is deleted locally with `remove: true` in compact repairs, or `removedCropIds` in full revisions, when its crop finding declares `remove-crop`; a source-page id may accompany that finding as evidence but is not required. A page-only finding is valid only for a wholly missing question that has no listed crop, must identify it with `missingQuestionHead`, and is the only finding type that unlocks a candidate-complete replacement draft; naming a neighboring crop in its evidence does not downgrade it to a local crop defect. The Host requires every cited crop to change, reports only changed or cited identities, and the caller rerenders that subset for the next review. Generic protected-head evidence includes compound example-variant labels such as `引例变式 N`, explicit requests such as `分别求`, named outputs such as an expression, solution set, domain, range, or monotonic interval, and an answer blank written as `=.`. These signals protect a visible independent task from a false-negative model classification without assigning any document-specific coordinates.

##### Local repair submission

```markdown
Submit one repairs array. Each row uses cropId and flat fields: pageId, top, bottom, rightLimit, stopBeforeElementId, additionalElementIds, outsideBoundaryElementIds, excludedElementIds, retainedImageElementIds, or remove. Omit unused fields.
```

##### Outside-block ownership guidance

```markdown
Boundary drafts distinguish retained non-head content from blocks belonging to no question. `outsideBoundaryElementIds` accepts the first text, equation, table (including an empty-text table), or nonempty other-text element of a title, preamble, summary, answer, or other outside block. The marker is omitted and stops preceding ownership until the next question head; markers before a later head do not block that question's attachments. Image-headed questions do not receive a conflicting automatic retained-image decision. After a rejected complete draft, `corrections` replaces only the named element decisions, preserving unlisted decisions and revalidating the complete result. Each replacement selects one role; a question replacement includes its complete attachment and stop fields. Corrections cannot be mixed with complete-draft fields, skip required candidates, or reset rejection limits. Diagnostics identify conflicting element ids, repeated drafts retain the original diagnostic, and terminal boundary errors include the last rejection. No question draft is inferred after a failed child.
```

##### Crop-edge evidence guidance

```markdown
Verification evidence names the crop's actual topmost, bottommost, leftmost, and rightmost visible non-white content. A detached watermark, publisher mark, answer block, or other unrelated lower pixels make only that crop defective even when a large white gap separates them from the question. Registration fields, binding or trim lines, vertical page labels, printed page numbers, running headers or footers, a QR code, publisher resource label, or optional dynamic-demo block are unrelated unless the problem explicitly tells the learner to use them; an excluded image and its compact caption form one removable visual block.
```

##### Core-page ownership guidance

```markdown
Within an overlapping semantic group, only `corePageIndexes` own question heads and require candidate or image decisions. Adjacent inspection pages remain visible as read-only continuation evidence; their detected question heads stop automatic ownership without being resubmitted or reclassified. The same ownership controls visual completeness review, so an independent problem headed on an adjacent page does not count as a missing crop in the current group.
```

#### Token effect

Each browser-queued PDF captures one reasoning choice before segmentation begins, and every boundary, visual-review, and repair request from that queue task overrides the mutable Host default with the captured value. Callers that omit the per-operation override use the Host default at request time. When the captured choice is on, those children retain an enabled reasoning effort when the selected model advertises one; a route without an enabled advertised effort uses its provider default. A captured off choice strictly selects Off for a reasoning model; a reasoning model without an advertised Off effort cannot start question cutting, while a model without reasoning metadata receives no reasoning effort. Their logical tool requirement still sends each accepted result through a Host validator. Each cut pays for one boundary child and at least one visual-review child per semantic page group, including groups whose preliminary crop list is empty, plus bounded OCR calls when correction is necessary, accepted boundary or review tokens, and final structured output. If the initial child ends without returning a token accepted in its own run, one fresh recovery child starts by default with reset inspection and submission state. The Web bundle assigns at most four selected pages and 300 fallible candidates to each group, inspects one adjacent selected page on each available side, and processes up to five independent groups concurrently. Cross-group questions therefore retain continuation context while completed groups merge in source order. When the complete serialized group fits the 24,000-character Web limit, every OCR element travels in the initial compact request; larger groups retain bounded source and page-preview tools instead of sending a candidate-focused subset. Independently answerable `题 N 变式 N`, `变式 N`, example, and worked-example labels remain generic recall hints. The child inspects the complete evidence and returns the complete ordered question list with a 32,768-token output cap, including genuine OCR-damaged or unrecognized heads absent from those hints. The Host still requires an explicit question or non-question decision for every hinted candidate, validates protected answer-demand evidence, and automatically owns images geometrically during the OCR-only compact pass. The later visual child receives compact annotated review sheets directly and uses an 8,192-token output limit and short identifying clauses rather than full problem transcriptions. Each page or crop sheet contains at most two images in one row, so provider-side image scaling does not collapse several rows of question pixels. Actual-height cells avoid fixed-height whitespace. A compact review that fits the 20-image admission limit attaches every listed sheet to the initial child request and exposes only the findings submission tool, removing the former image-fetch model round trip while preserving the same visual evidence and Host validation. The child submits every complete crop in `verifiedCrops` with its exact single visible `answerDemand` and visible task evidence; it may omit `findings` only when that list covers every requested crop. The Host-side source pipeline reuses accepted rendered crops for persistence. A defect names its visible pixels in `issue`, declares every applicable `repairIntents` value, and may add separate `evidence`. A child admits at most 50 inspected pages, 5,000 OCR elements, 300 questions, and five reference-valid complete drafts. The Web default gives each child a five-minute deadline, renewed for a separate repair child, not for the whole PDF. Three repeated failed tool calls in one normalized diagnostic category stop that child; reaching a different diagnostic resets the consecutive-failure count. Boundary and incomplete compact visual-classification stages may use their remaining configured fresh-child runs with retained drafts and diagnostics. Missing accepted boundaries still fail the group because no crop geometry exists. If every boundary group stops with a model or provider failure before producing geometry, the operation returns the first safe provider diagnostic instead of running redundant empty visual reviews. After preliminary crops exist, an unsuccessful visual stage instead saves the current safe group as unverified and continues; complete crop-specific findings narrow the warning to cited question ids, while a pre-finding failure marks the current review scope. A confirmed zero-question selection completes without creating an empty batch. At most three local crop revisions are applied; each follow-up sends only cited or geometrically changed crops. A still-unresolved crop keeps its latest safe revision and later groups continue. A validated removal-only repair needs no further rendering when it leaves no changed crops. A submission with unknown or duplicate element references still consumes tool steps and wall-clock time, and the failed-call budget, but does not consume the complete-draft allowance. The selected tool model's configured context and output limits remain authoritative outside the compact boundary override.

#### KV Cache effect

Independent of the parent conversation cache. The fixed skill and schemas form a reusable prefix, while the run-specific tool names and OCR source establish a different request suffix for each cut.

## Known Limitations and Deferred Work

- **Whole-document writes** — compare-and-set keeps cross-module edits atomic, but very large school-wide datasets should move to independently revisioned tables before multi-user deployment.
- **JSON base64 media transport** — browser reads, replacements, and generated downloads carry complete payloads in memory; configured per-image and per-save-part limits bound each request, but streaming is not exposed.
- **Retained conversation sources require lifecycle policy** — uploaded PDFs are content-addressed below `sourcesRoot` so a later tool call can read the exact source; automatic expiry and garbage collection are not implemented.
- **Agent-generated Office files are Host paths** — ordinary-conversation generation writes below `generatedRoot` and reports an absolute path; a browser download handoff for those paths is not implemented.
- **Weather requires Host network access** — location queries go to the configured geocoder and Open-Meteo supplies current conditions plus the next twelve hours; either provider or the Host outbound network can be unavailable without affecting saved workbench data.
- **Question cutting requires vision and recoverable OCR evidence** — the configured tool route must accept images. Numbered gaps on landscape pages can recover missing groups through targeted half-page parsing, and visual review can correct boundaries around recognized content, but a wholly absent unnumbered question still has no trusted element id or geometry to recover.
