# @deepseek-ai/dsh-host-teacher-workbench

English | [中文](README.zh.md)

Host-owned persistence, ordinary-conversation tool operations, question media, document generation, weather access, and timetable normalization for the Web teacher workbench. The plugin stores one schema-validated, revisioned document through `ctx.storageDomain` and exposes `teacherWorkbench/read` plus compare-and-set `teacherWorkbench/write` Remote methods. The companion `@deepseek-ai/dsh-tool-teacher-workbench` Consumer registers seven model-facing tools that let an ordinary agent read and change Daily Management, Timetable, Student Roster, Score Analysis, and Question Cutting through the same authoritative operations used by the browser. Dedicated question Remotes atomically save, read, replace, delete, assign, and render stored images without sending server paths to the browser. `teacherWorkbench/weather` resolves a configured district, county, or city through a Nominatim-compatible endpoint, fetches the forecast from Open-Meteo, validates both responses, and returns stable lookup, availability, or response errors without requiring the browser to contact either provider directly. When browser-side MinerU reconciliation finds no entries, `teacherWorkbench/normalizeTimetable` starts a short-lived child agent loop under the current session, selects `ctx.agentDefaultModel.currentToolSelection()`, exposes run-scoped source, matrix-submission, and line-splice patch tools, and accepts only a token for a matrix validated in that run before the browser may review rows. The optional `ctx.mobileNotifications` provider supplies a credential-free bot roster to `teacherWorkbench/listNotificationTargets`; the Remote returns only platform, opaque bot id, display label, and current connection state.

The version-10 document contains daily tasks, memos, ledger categories and entries, dated calendar items, normalized weekly timetable entries, lesson resources, classes and students, exams, family-notice templates and saved drafts, reusable record templates, authored teaching and headteacher records, class seating layouts, question-library folders, paper-batch metadata, nested student question folders, and student question assignments. Each seating layout belongs to one roster class, contains exactly one slot for every configured row and column, and may reference only that class's students without duplicate occupants; deleting a class removes its layout, while deleting a student clears that student's seat. Ledger entries reference one durable category, store a required local date and time, and represent CNY amounts as non-negative integer cents; deleting a category removes its entries in the same revisioned write. Every class belongs to exactly one catalog: roster classes own students and exams and supply Question Cutting and seating, normal timetable classes are selectable by Today, Week, and Morning/Evening Study, and grade-timetable classes are selectable only by Grade. The schema rejects ledger, student, exam, seating, or timetable references whose owner is absent or crosses those catalogs, while identical class display names may retain independent identities in each catalog. Each timetable entry occupies one unique class/type/weekday/period slot; deleting a class also removes its schedule. Question folders and assignments reference durable students and source images; deleting a folder, student, class, image, or batch removes its dependent metadata and best-effort cleans its owned files. Daily-management, teaching, and headteacher edits share one revision, so concurrent browser windows use the same compare-and-set conflict handling. Browser code never writes Local Storage; every accepted mutation lands in the storage backend selected for the `teacher_workbench` domain. Daily tasks, memos, ledger entries, and timed calendar items may carry one mobile reminder containing the selected platform and bot, a deadline-derived UTC instant, and either a one-time lead or fixed repeat interval. Memos and ledger entries retain an independent optional reminder deadline instead of reusing their edit or expense time. The Host recomputes timers from the durable document after startup and every write, retries unavailable delivery until the deadline, advances each occurrence only after provider acceptance, and stops projecting reminders for completed or deleted items; documents without reminder fields do not schedule or send anything.

## Question Image Storage and Output

After all semantic groups merge, `segmentQuestions` derives the maximum normalized safe-lane width from every accepted MinerU-backed question region's fixed left edge to its horizontal limit. The boundary child infers the document's own semantic question structure from source-page previews and OCR elements. The Host adds narrow structural safeguards: a recognized hierarchical section, answer heading, or answer/analysis block is an exclusive stop that cannot become a question head, and a bracketed source citation cannot become a standalone question unless it owns actual problem content. The Host validates opaque element references and ordering, assigns unclaimed elements through layout-derived horizontal lanes, and treats a model-selected per-question `stopBeforeElementId` as an exclusive hard ownership stop: it is the first outside element and cannot also be claimed as question content. An explicit attachment is rejected only when a vertically overlapping question head is horizontally closer than the claimed owner, so a right-column diagram is not blocked by a left-column head at the same height. Each region records the nearest right-side limit imposed by vertically overlapping content outside that question, inset by the configured padding without clipping owned content, and its bottom cannot pass a later accepted head in the same horizontal span even when an oversized OCR image box crosses that head. A whitespace gap between adjacent owned and foreign boxes is split at its midpoint; when neighboring head boxes overlap by no more than the configured padding, both crops instead share the later head's top as one hard cut line, so neither crop imports the other head. Automatic ownership ends before a trailing cluster separated by more than `maxQuestionAutoOwnedGapRatio` of the page height unless that cluster contains an explicit attachment. An explicit attachment seeds its horizontal lane through the next semantic or question stop; a page-bottom stem that continues at the top of a disjoint column becomes multiple source-safe slices concatenated in OCR reading order, rather than one rectangle containing the intervening page. A head-bearing slice keeps the question head's left coordinate even when an explicit ownership claim reaches into another column; a detached claimed block that extends farther left becomes a separate slice instead of moving that origin. This keeps detached answers, decorations, and later-paper material out of a final question while allowing the child to retain a distant diagram deliberately. Excluded source boxes that do not overlap an owned element are recorded as white erasures. Browser and ordinary-conversation renderers preserve each region's left, top, and bottom coordinates. The output right edge is always the fixed left edge plus the PDF-wide maximum normalized safe-lane width; source sampling stops at each region's inset horizontal limit and the remainder stays white, so equal-width output preserves unrecognized answer lines without importing gutter or neighboring-column pixels. The first complete-group visual review compares every preliminary crop with every core source page, so it can recover a page whose questions were all omitted. Review metadata identifies pages by their exact `page-x` tool ids and flags detached same-page slices, erased or edge-touching source images, source sampling that extends beyond owned OCR content, and crops touching a physical page edge for explicit visual resolution. A verified crop must name its actual topmost, bottommost, leftmost, and rightmost non-white pixels, account for every required source visual, and resolve each flag; otherwise the reviewer records a crop-local defect. Later recuts receive only cited questions and their local source pages. In those crop-local passes, unlisted questions visible on a supplied page remain unchanged boundary context; the Host rejects every page-only missing-question finding and complete-group replacement. Clean crops finish without OCR calls. A review child that invents a final token before recording a defect is replaced by a fresh child with reset inspection and submission state; an unclean child stop after those bounded fresh runs returns the listed crops as unresolved instead of failing the complete PDF. Recorded defects are likewise returned as unresolved so the caller's next pass stays crop-local and cannot erase the observation through a new full-group review. For crop-specific defects, it reads OCR geometry and submits corrections for the cited stable heads; the Host validates those patches with all neighboring heads present, merges only cited geometry, preserves every untouched question, and extends the existing region directly when the only change is an omitted attachment. A `trim-right` finding may reduce only the cited slice's source-pixel limit; its fixed left edge and the PDF-wide output width remain unchanged, and white padding replaces the removed source area. A crop finding remains local even when it also cites its source page as visual evidence. Restoring an explicitly cited attachment also removes an overlapping white erasure while preserving unrelated erasures. A QR code, publisher resource label, or optional dynamic-demo block is page furniture unless the stem explicitly requires it; excluding its image also requires excluding a compact connected caption so no orphan label remains. A spurious crop can be removed locally only through one finding that contains both its crop id and one of its source-page ids. A page-only finding is reserved for a wholly missing independent question with no existing crop and must include that problem's visible `missingQuestionHead`; it may cite a neighboring crop that contains the missing problem's pixels, but it always requires a candidate-complete group replacement. Distinct missing heads on one page remain separate findings. The Host rejects a correction that leaves any cited crop unchanged. At most two local recuts are applied, and a still-unresolved crop saves the second result instead of failing the complete PDF.

Thin answer lines, boxes, and other response marks that OCR omits must be proven by visible crop pixels rather than inferred from the source prompt. A missing edge mark authorizes a crop-local vertical correction.

Every existing-crop defect declares whether correction must expand or trim its top or bottom, trim unrelated pixels from its source-sampled right edge, reassign referenced content, or remove a spurious crop. The Host rejects a boundary edit that moves in an undeclared direction. Content transferred across two adjacent crops requires complementary findings and geometry changes for those two crops; every uncited crop remains byte-for-byte unchanged and outside the next local review.

`teacherWorkbench/saveQuestionBatch` validates PNG, JPEG, or WebP payloads, generates opaque ids, and commits one bounded save part only after every image has reached owned storage. The first part creates the paper-batch metadata; a continuation names that opaque batch id, must repeat its source metadata and destination, and appends files and image metadata to the same library entry. Its required destination selects one of three physical locations: the configured library root, a root child derived from the source PDF name, or one current durable leaf. The Web question cutter uses the source-name child when its directory control remains blank and the selected leaf otherwise. Ordinary-conversation `segment_pdf` has no default: the current user request must explicitly name the question-library root or one complete existing leaf path, and the Host rejects a missing or model-guessed target before OCR begins. The paper-batch id never creates a storage directory. Large source papers are not subject to one part's aggregate byte ceiling because the browser saves successive semantic page groups and further divides a group by decoded image bytes when needed. `readQuestionImage`, `replaceQuestionImage`, `deleteQuestionImage`, and `deleteQuestionBatch` resolve only the files owned by validated metadata and configured roots. Renaming a durable library directory moves its physical subtree; deleting one atomically detaches the physical subtree and removes its batches and dependent student copies instead of reparenting any image. The model-facing image reader turns one resolved image into a durable attachment only for an image-capable route and reports the original pixel dimensions; rectangle erasure samples surrounding pixels and replaces the selected stored raster only after every rectangle passes bounds validation. `assignQuestions` creates independent copies below a sanitized academic-year/class/student hierarchy and any selected nested folder, so later editing or deleting one student's copy cannot change the source batch or another student's work.

`generateQuestionDocument` builds a downloadable Word or PowerPoint document from selected batch or assignment images. `generateUploadedQuestionDocument` accepts browser-selected directory images without persisting them. `saveTemporaryQuestionSelection` replaces one student's previous temporary selection with independent image snapshots and atomically increments the selected assignments’ durable save count and latest-save time, while `listTemporaryQuestionSelections` reports which requested students have staged images. Every Office path orders images by the authoritative source question number, falls back to a question number parsed from the display file name, and only then uses natural file-name ordering; temporary-manifest reads reapply the same rule so selections staged by older versions are corrected at generation time. `generateStudentDocuments` returns one independent Word or PowerPoint artifact per eligible roster student, with per-student Word title, name, and date choices plus an explicit skipped list. Its omitted source follows the Question Cutting UI and reads temporary snapshots; assigned images require `source: 'assigned'`. A successful temporary-source generation removes that student's selection. Word output preserves the reference A4 margins and metadata flow; PowerPoint output preserves one top-left, non-upscaled image per 13.333-by-7.5-inch slide. Image dimensions, decoded byte limits, target references, containment, file names, and generated output are validated on the Host; temporary image bytes remain outside the durable document, while their per-assignment usage statistics survive generation and restart.

## Configuration

| Field | Meaning |
|---|---|
| `reminderRetryMs` | Delay before retrying a due mobile reminder whose provider is absent or rejects delivery. |
| `segmentsRoot` | Root for durable question-library directories and their direct cropped-image files. |
| `studentsRoot` | Root for readable grade/class/student assignment copies. |
| `sourcesRoot` | Private content-addressed root for conversation-uploaded source documents. |
| `generatedRoot` | Private root receiving Word and PowerPoint files generated by agent tools. |
| `maxSourceDocumentBytes` | Maximum decoded size of one retained conversation source document. |
| `maxQuestionImageBytes` | Maximum decoded size of one accepted question image. |
| `maxQuestionBatchBytes` | Maximum combined decoded size of one automatically saved part; the Web default is 96 MiB and it is not a whole-PDF limit. |
| `questionSegmentationBatchPages` | Maximum selected pages owned by one semantic segmentation group; the default is four. |
| `questionSegmentationBatchCandidates` | Maximum fallible question-head candidates owned by one semantic group; the default is 12, which keeps visual review focused while leaving one unusually dense page indivisible. |
| `maxQuestionBoundaryAgentRuns` | Maximum fresh children used by an initial-boundary or crop-review stage that has not returned an accepted token; the default total per stage is two. |
| `maxQuestionAutoOwnedGapRatio` | Maximum page-height ratio between automatically owned elements; a farther trailing cluster requires an explicit attachment claim. The default is `0.18`. |
| `maxQuestionRecutAttempts` | Maximum local recuts applied to one defective question before its last result is saved; the default is two. |
| `maxQuestionVisionImagesPerToolCall` | Maximum source previews or crops returned by one visual tool call; the default is four. |
| `questionSegmentationAgentTimeoutMs` | Wall-clock deadline for one question-segmentation child; the Web default is 60 minutes. |
| `geocodingEndpoint` | Nominatim-compatible location-search endpoint. |
| `geocodingCacheEntries` | Maximum number of resolved locations retained in memory. |
| `maxTimetableSourceCharacters` | Maximum MinerU characters admitted to one timetable-agent request. |
| `maxTimetableEntries` | Maximum structured timetable rows accepted from one run. |
| `timetableAgentTimeoutMs` | Wall-clock deadline for a text/OCR timetable-agent run. |
| `timetableVisionAgentTimeoutMs` | Wall-clock deadline for a direct-vision timetable-agent run. |

The question-storage fields are available in **Settings → Plugins → Plugin configuration → Question workspace storage** under the `teacher-workbench` settings namespace. The Web bundle defaults media, source, and generated roots below `~/.dsh/teacher-workbench/`. A state write that adds a roster class, student, nested student folder, or durable library folder creates its complete physical hierarchy before the revision commits; a failed document commit removes only still-empty directories created by that operation. The question workspace recursively projects every non-hidden directory below the current `segmentsRoot`, including empty directories and image-only leaves; direct images appear as a paper row inside their owning folder. It reads both `year/class/student` and `year/grade/class/student` hierarchies below `studentsRoot`, merges matching directories with roster records, projects every non-hidden descendant directory below each student, and recursively reads its images. A student row aggregates images from the complete subtree, while a descendant row selects that exact directory. Changing either root switches the displayed collection without copying files from the previous root. Filesystem-derived classes, papers, images, and roster edits remain read-only. Directory creation, rename, and recursive deletion are the narrow exceptions: a browser submits an opaque identity retained by the latest scan, the Host revalidates the target below the current root, and then changes that physical directory. Renaming a durable student hierarchy also commits its display name and adjusted assignment paths with rollback of the physical move when the document write fails.

## Extension Points

The plugin provides `ctx.teacherWorkbench` and optionally consumes `ctx.mobileNotifications`, whose `listTargets()` and `send()` methods are implemented by dsh-im without exposing credentials or private conversation identifiers. Browser consumers use the generated Remote contribution through `@deepseek-ai/dsh-api-remotes` rather than importing Host runtime code. Optional same-process scheduled-task UIs may call `listScheduledReminders()` to obtain read-only, credential-free rows derived from active workbench reminders; that projection does not transfer execution or persistence ownership.

`geocodingEndpoint` selects the Nominatim-compatible search endpoint, and `geocodingCacheEntries` bounds the in-memory location cache. Cache misses are serialized at no more than one geocoding request per second; repeat weather refreshes reuse the resolved coordinates while fetching current forecast data again.

## Model Experience

### Ordinary-conversation workbench tools

#### What the model sees

With the companion Consumer mounted, every standard Web agent sees the seven schemas in the generated [tool catalog](../../../docs/tool-catalog.md#deepseek-aidsh-tool-teacher-workbench): `teacher_workbench_read`, `teacher_question_image_read`, and one mutation tool for each of Daily Management, Timetable, Student Roster, Score Analysis, and Question Cutting. The section reader returns stable ids from the authoritative revisioned document; Daily Management also returns credential-free `notificationTargets`. The image reader returns one stored batch or assignment raster with its source dimensions, after rejecting routes that do not declare image input. The Question Cutting mutation tool uses source-pixel coordinates to rotate or crop the image or erase up to 32 rectangles with sampled surrounding color; invalid or out-of-bounds edits fail before replacement. Before creating daily data, the Host rereads direct user text from the current agent turn and derives the destination only from literal routing words. A mismatched action such as `save_todo` for a request containing `备忘` or `备忘录`, or a creation request without a routing word, fails before persistence, so model-supplied classification cannot override the user. A reminder mutation must select an exact returned platform and bot id, and the Host rejects invented ids or an elapsed occurrence before committing the item. Mutations retry compare-and-set conflicts against the latest document and return the committed revision, a short summary, and created ids. Timetable mutations map Today, Week, and Study to the `timetable` catalog and the explicit Grade view to `gradeTimetable`; they reject cross-catalog class ids and duplicate imported slots, then read back the affected ids before reporting their confirmed view. Roster, timetable, and score tools consume the hidden OCR Markdown already injected for uploaded documents; an attached image may instead be read directly by a multimodal model. A conversation-uploaded PDF additionally carries an opaque `sourceId` that identifies Host-retained bytes without placing them in the Session log or prompt. Question segmentation resolves that id, obtains MinerU geometry, runs the restricted boundary child, renders and stores crops on the Host, and returns the paper-batch id. `generate_folder_document` recursively reads an ordinary local image directory through `ctx.fs`, builds one naturally ordered Word or PowerPoint file without a roster student or assignment, writes it below `generatedRoot`, and returns its absolute path. Stored batch or assignment targets use `generate_document`; per-student output uses `generate_student_documents`. The latter matches the browser when fields are omitted: it reads temporary selections, uses an empty Word title, and prints neither name nor date; `source: 'assigned'` explicitly selects every assigned image.

#### Token effect

The seven tool schemas extend every ordinary Web model request. Section reads and direct document mutations add only their tool calls and bounded JSON results; a successful stored-image read also adds one durable image attachment to that result and later conversation history. PDF question segmentation also incurs MinerU work and the question-boundary child calls described below; Office generation does not make another model request.

#### KV Cache effect

The stable tool names and schemas become part of the ordinary conversation prefix. Uploaded OCR text, current workbench rows, and tool results vary in the request suffix. Question-boundary child caching remains independent of the parent conversation.

### Timetable normalization child

#### What the model sees

A fresh child receives the upload name, a destination captured when extraction starts, current class/grade/type/teacher defaults, known class names, a run-scoped source tool, a matrix-submission tool, a line-splice patch tool, and a compact final-output schema. A vision-capable route receives one overview plus overlapping enlarged views of a raster source; extracted PDF and Office content and image fallback use compact MinerU regions through the source tool. The child inspects the source, submits one complete source-oriented matrix, and repairs rejected draft lines through 1-based splices while the Host preserves every unlisted line and block. The final output contains only the token for a matrix accepted in that run. The parser tolerates an axis or fields keyword joined to its first argument by an opening parenthesis, but semantic and dimension failures still require an explicit draft repair. The Host accepts repeated local period headers in chronological data order and assigns their later rows distinct periods without assuming source coordinates. Class, Grade, and Study destinations change relevant record semantics but do not prescribe a document layout. Every uploaded string is untrusted data, ordinary tools remain hidden, and the result is returned to browser review rather than the parent conversation.

#### Token effect

Each attempt pays for an independent child run plus source, submission, and patch calls. The selected tool model's configured `contextWindow` and `maxTokens` govern every request; the timetable plugin does not replace either value. Raster uploads start enhanced OCR concurrently with direct vision so a direct timeout or invalid result can immediately start a text child. The Web bundle gives both direct vision and text children a 60-minute wall-clock deadline.

#### KV Cache effect

Independent of the parent conversation cache. Reuse requires the same tool-model route, fixed persona and schema, defaults, and MinerU source; changed source data establishes a different suffix or prefix according to the provider.

### Question-segmentation child

#### What the model sees

A fresh child receives a layout-neutral segmentation skill, exact OCR source-chunk indexes, source-page preview ids, fallible semantic hints, run-scoped OCR and image tools, one boundary-submission tool, and `structured_output`. Source chunks expose opaque element ids, page dimensions, element type, bounding box, and extracted text; previews show the rendered page without becoming a coordinate source. The child inspects every chunk and preview, infers the source's own semantic question convention, and submits every independent top-level task while keeping its subparts, figures, and cross-page continuation together. Each selected head must create an answer obligation rather than merely introduce a numbered definition, formula, method, theory summary, worked solution, or answer. A prompt-bearing worked example still creates a question; its crop ends before the printed answer or analysis. A fully classified group may contain zero questions. The child may use a question-local exclusive `stopBeforeElementId` for the first unrelated element before the next task, `additionalElementIds` when OCR order leaves unmistakable content outside its owner, and explicit exclusions for non-question elements inside an otherwise valid interval. The Host does not require a numbering syntax, sequential labels, or a fixed column count; exact hierarchical section and answer headings remain enforced safety stops, and citation-only bracket labels require owned problem content. It sorts valid heads by OCR order, validates references, ordering, contradictory ownership, and non-empty geometry, and derives every rectangle without accepting model coordinates. A vertical edge falls at the midpoint of any whitespace gap between owned content and the nearest foreign element; adjacent head boxes with a small overlap share the later head's top as their hard cut line. After preliminary rendering, a separate visual-review child receives every core page for its first complete-group pass, then local source pages for later crop-only passes, with crops in a separate image stream. Its `page-x` labels are authoritative even when printed footer numbering differs; zero-based OCR `pageIndex` remains available only for coordinate edits. A crop-local pass classifies only its listed crop ids; other visible questions remain unchanged, and the findings tool rejects `missingQuestionHead` or any page-only recovery. Each crop label states that a blank white suffix is intentional equal-width padding, and the reviewer may report adjacent-column contamination only for pixels visible in the crop itself. A zero-question group still receives source-page review. Every accepted crop records the visible `answerDemand`, actual topmost, bottommost, leftmost, and rightmost non-white content, and the source-to-crop check for every required diagram or table. The Host adds `visualAttention` when one crop concatenates source slices across a large same-page gap, erases or clips a recognized source image, samples an unowned strip to the right, or reaches a physical page edge where headers and footers may appear; a verified record must resolve every flag in `attentionEvidence`. A crop without one independent task or with an unresolved visual defect is defective. The reviewer may accumulate one verified or defective crop record at a time and finalize after complete coverage, while a complete-array submission remains available; dense groups therefore do not require one oversized JSON call. A clean finalization accepts the images without opening OCR, and before any correction is accepted the child may replace a mistaken finding after closer inspection. Crop-specific defects unlock the OCR source and local corrections keyed by stable source head; validation retains every neighboring head and the returned complete group retains every omitted correction target unchanged. A crop-cited finding stays local when it includes a page id for evidence. A confirmed spurious crop is deleted locally through `removedCropIds` only when one finding contains both its crop id and a source-page id. A page-only finding is valid only for a wholly missing question that has no listed crop, must identify it with `missingQuestionHead`, and is the only finding type that unlocks a candidate-complete replacement draft; naming a neighboring crop in its evidence does not downgrade it to a local crop defect. The Host requires every cited crop to change, reports only changed or cited identities, and the caller rerenders that subset for the next review.

##### Crop-edge evidence guidance

```markdown
Verification evidence names the crop's actual topmost, bottommost, leftmost, and rightmost visible non-white content. A detached watermark, publisher mark, answer block, or other unrelated lower pixels make only that crop defective even when a large white gap separates them from the question. Registration fields, binding or trim lines, vertical page labels, printed page numbers, running headers or footers, a QR code, publisher resource label, or optional dynamic-demo block are unrelated unless the problem explicitly tells the learner to use them; an excluded image and its compact caption form one removable visual block.
```

##### Core-page ownership guidance

```markdown
Within an overlapping semantic group, only `corePageIndexes` own question heads and require candidate or image decisions. Adjacent inspection pages remain visible as read-only continuation evidence; their detected question heads stop automatic ownership without being resubmitted or reclassified. The same ownership controls visual completeness review, so an independent problem headed on an adjacent page does not count as a missing crop in the current group.
```

#### Token effect

Each cut pays for one boundary child and at least one visual-review child per semantic page group, including groups whose preliminary crop list is empty, plus progressive image calls, bounded OCR calls when correction is necessary, accepted boundary or review tokens, and final structured output. If the initial child ends without returning a token accepted in its own run, one fresh recovery child starts by default with reset inspection and submission state. The Web bundle assigns at most four selected pages and 12 fallible candidates to each group and inspects one adjacent selected page on each available side, so a cross-group question remains whole, only the group containing its inferred head saves it, and a dense workbook review does not accumulate dozens of crops in one child context. Image tools return at most four page previews or crops per call by default. A child admits at most 50 inspected pages, 5,000 OCR elements, 300 questions, five reference-valid complete drafts, and 60 minutes. At most two local recuts are applied to a defective image; each follow-up sends only cited or geometrically changed crops, and the second result is retained if the reviewer still reports a defect. A submission with unknown or duplicate element references still consumes tool steps and wall-clock time, but does not consume the complete-draft allowance. Source calls return at most 18,000 serialized characters apiece so dense layouts do not enter one oversized tool result. The selected tool model's configured context and output limits remain authoritative.

#### KV Cache effect

Independent of the parent conversation cache. The fixed skill and schemas form a reusable prefix, while the run-specific tool names and OCR source establish a different request suffix for each cut.

## Known Limitations and Deferred Work

- **Whole-document writes** — compare-and-set keeps cross-module edits atomic, but very large school-wide datasets should move to independently revisioned tables before multi-user deployment.
- **JSON base64 media transport** — browser reads, replacements, and generated downloads carry complete payloads in memory; configured per-image and per-save-part limits bound each request, but streaming is not exposed.
- **Retained conversation sources require lifecycle policy** — uploaded PDFs are content-addressed below `sourcesRoot` so a later tool call can read the exact source; automatic expiry and garbage collection are not implemented.
- **Agent-generated Office files are Host paths** — ordinary-conversation generation writes below `generatedRoot` and reports an absolute path; a browser download handoff for those paths is not implemented.
- **Weather requires Host network access** — location queries go to the configured geocoder and Open-Meteo supplies current conditions plus the next twelve hours; either provider or the Host outbound network can be unavailable without affecting saved workbench data.
- **Question cutting requires vision and recoverable OCR evidence** — the configured tool route must accept images. Numbered gaps on landscape pages can recover missing groups through targeted half-page parsing, and visual review can correct boundaries around recognized content, but a wholly absent unnumbered question still has no trusted element id or geometry to recover.
