# @deepseek-ai/dsh-client-ui-teacher-workbench

English | [中文](README.zh.md)

## Summary

Teacher-workbench feature for the dsh Web GUI. It contributes the first sidebar action through `sidebar.primary.section`, an in-app teaching surface through `shell.overlay`, and a feature-owned row in General settings. The expanded sidebar disclosure shows eight module rows before the remaining entries scroll. The overlay follows the rendered sidebar and details widths, so selecting a disclosed module replaces only the visible center content while keeping the application sidebar available. The surface begins directly with the active module instead of repeating a Workbench header; every explicit Session or New Session navigation dismisses it and reveals the still-mounted conversation, including reselecting the current Session. Opening the surface always reloads the authoritative Host document so changes made through ordinary-conversation tools replace any cached browser snapshot.

## Use this package

The surface begins with Daily Management. A right-aligned summary beside the module heading shows the current time, date, configured location, and current weather; selecting it opens the full time and next-twelve-hours forecast. Today, Important, and Urgent each occupy an equal-width independent task card. Memos, Ledger, and Calendar form a second three-card row. The Ledger card opens a full-board view whose categories can be added or deleted; each category accepts manual or voice descriptions, a CNY amount, and a required local date and time, while existing entries remain editable. Creating inside a task card assigns that exclusive category, and editing preserves it without exposing a classification control. Important and Urgent rows expose a ten-color marker picker, while Today rows omit the marker. The expanded calendar combines Gregorian dates, lunar dates, statutory holidays, and date-specific items; it also accepts images, PDF, DOCX, PPTX, and XLSX school calendars through the shared OCR Remote, projects recognized dates and activities into an editable review list, and persists only selected rows in one revisioned write. HTML table projection respects row and column spans so responsibility metadata remains separate from dated activities. The task time icon opens one deadline-and-reminder editor: after a future deadline is set, a user may select a one-time lead or repeated frequency plus one platform and one bot from the optional dsh-im roster. Both reminder modes accept a manually editable number followed by a minutes, hours, or days selector; an empty or out-of-range draft blocks saving without replacing the text while it is being edited. Memos expose the same controls in their editor; each ledger composer has a reminder button, and existing ledger entries retain the controls in their edit dialog. Their reminder deadlines are independent of memo edit times and ledger occurrence times. An elapsed deadline disables reminder activation with inline guidance but does not block saving ordinary edits. For a deadline less than thirty minutes away, activation chooses the greatest whole-minute lead whose occurrence remains in the future. Calendar agenda rows expose a dedicated reminder action and reuse the same controls. Leaving reminder fields disabled preserves ordinary records without notification.

The Timetable module switches among Today, Week, Grade, and Morning/Evening Study views. Week, Grade, and Study show each distinct time range once beneath its row label; hovering over a lesson shows its exact time. Today and Week can select one class or filter all durable entries to the teacher name from dsh settings; personal views retain the class label for every lesson. Today, Week, and Study share one normal timetable class catalog, while Grade owns an independent class catalog and projects only its selected grade. Classes recognized or created in Grade therefore never appear in Today, Week, Study, rosters, score analysis, or Question Cutting; roster classes are likewise absent from timetable controls. Class creation uses an icon-only control in every editable view. Week and Study use an icon-only control to delete the selected normal class, while Grade exposes icon-only deletion on each class row; every icon keeps an accessible label and tooltip. Confirmation identifies that the class and all of its timetable entries are removed, and a successful selected-class deletion advances the picker to the next available class. Creating a timetable class asks for its name and grade. Course creation has no toolbar action: selecting an empty Week, Grade, or Study cell opens the lesson editor with that cell's class, weekday, period, and study type where applicable. Week, Grade, and Study accept images, PDF, DOCX, PPTX, and XLSX. Every upload is interpreted by an independent tool-model child. MinerU supplies text and tables for PDF and Office files; raster extraction includes an enhanced overview and detail regions that preserve headers when a regular grid is available. Image-capable children can request the original image and enlarged views through a dedicated tool when extracted text needs confirmation. If image extraction fails, they can use those views directly. The child receives the selected destination and required entry fields, identifies the document’s layout, reads the complete source in bounded pages, and submits validated entry batches for review. Each import creates and releases its own hidden parent and child, so no current conversation is required. The header icon hides the recognition dialog; closing it or navigating away leaves processing active in the browser plugin. Every Timetable view offers progress or results, and completion never reopens a hidden dialog. Edited rows remain available until imported or explicitly cleared; failed imports retain the review for retry. Only one pending recognition or review is accepted at a time. Reloading or closing the browser clears this transient task state. The destination, class catalog, grade, and defaults are captured before asynchronous work starts, so changing views cannot reroute an import. The browser still requires an editable review of class, grade, type, weekday, period, times, subject, teacher, and location before one bulk write. A selected row needs a class name and a course or study supervisor; class names have no required suffix. Accepted entries replace an occupied class/type/weekday/period slot instead of creating contradictory schedules.

The Question Cutting module preserves the reference application's top bar, current-year/class hierarchy, layered drawers, and operating flow while omitting its wrong-question analysis, image-search workspace, and duplicate settings button. The top bar contains only the module title and actions; it does not render a centered paper-name field. Its class hierarchy reads roster-style directories from the current student root, so normal and grade-timetable classes cannot appear there. Its surfaces use DSH design tokens, so backgrounds, labels, borders, controls, masks, and accents follow the active light or dark appearance instead of keeping the standalone application's black-and-orange palette. Double-clicking a class opens its student drawer flush with the workspace's left edge; inside that drawer, a single click opens images, a double click expands or collapses nested folders, and a triple click creates a subfolder. Selecting a student shows every assigned question across that student's root and nested folders. Selecting a student folder shows its direct images and every descendant's images; Select All and Temporary Save use that same subtree and exclude sibling folders and other students. Student and folder labels remain centered between fixed inset row actions. Selecting the same student or folder again closes its image drawer. Student images and the question library are mutually exclusive: opening either closes the other before displaying its own drawer. The library tree projects only physical library directories, shows no more than seven Unicode characters from each folder name, and exposes the full name on hover. When images exist directly in the configured root, one Question-library root row represents that physical directory. Paper-batch names never become directory-tree nodes; selecting a directory opens every image stored directly there across all batches, while an independent disclosure arrow expands descendants. Leaf folders omit an expansion placeholder; only folders with descendants show a disclosure arrow. Its header creates root folders; a single folder click opens direct images when present or otherwise opens or closes the row, a double click creates a child, a triple click renames it, and the row delete action recursively removes that folder hierarchy, its batches, and dependent student copies. Selecting the same open directory closes its image drawer. Closing the class drawer also closes its image drawer first. Selecting a PDF opens the reference page-range sheet with an initially unselected save-directory control that lists only existing leaf paths; blank page input means every page, and comma-separated pages or ranges such as `1-5,8` are accepted. The browser reads the selected OCR provider's current limits, copies only those source pages into bounded PDF batches, bisects an oversized batch, and rasterizes a single copied page only when it cannot fit. The original PDF therefore remains browser-held regardless of its byte size. Each batch calls the shared `ocr.layout` Remote for MinerU page geometry, then the module starts one short-lived question-boundary agent loop with the configured tool model and built-in semantic skill. The child reads bounded chunks of provider-neutral OCR elements, infers the current PDF's question-head convention, and submits top-level heads plus any out-of-order continuations, figures, and excluded headings by opaque element id before returning an accepted token. Numbering may use any syntax, restart, repeat, vary by chapter, or be absent. The Host rejects mismatched or invented ids, unexcluded recognized section or answer headings, and empty crops; it normalizes valid heads by authoritative OCR order and assigns unique source-order display numbers, maps accepted ids back to trusted two-dimensional coordinates, and clamps padding against neighboring content. PDF.js then rasterizes the original browser-held PDF and vertically joins regions for a question that genuinely crosses pages. When no directory is selected, the Host creates or reuses one physical root child named after the PDF and stores every crop directly there; an explicit leaf selection stores the crops directly in that leaf. The paper-batch id never creates a storage directory, and batch metadata remains responsible for grouping, continuation saves, and deletion. The current-root image library supports selection, preview, rectangular erasure, rotation, Save As, overwrite, and deletion. Opening the library from the top bar saves selected images to a browser-chosen local directory with collision-safe names; opening it from a student or nested folder instead assigns the selected images directly to that target. In a student's image drawer, Save temporarily adds checked images to that student's staged selection across folders. Saving the same image again refreshes its snapshot; different images with the same name remain distinct. The displayed total includes all staged folders, and Clear staged images removes only that student's snapshots. Student staging and Toolbox generation have no fixed image-count limit; existing image-size checks still apply. Every image card retains its save count and latest save time. The Toolbox Word and PowerPoint entries first open the reference directory picker, naturally order its images, generate one artifact named after that directory, and present Save or Retry. The class drawer retains separate Word and PowerPoint actions and enables them only when at least one student has temporary images: Word opens independent title/name/date rows with bulk controls, PowerPoint starts immediately, and both consume only each student's staged snapshots, remove successful selections, and return one file per student instead of a ZIP. Saving generated Office files uses the composed native or in-app directory picker to select an existing directory on the computer running DSH, then writes each artifact through the authenticated Host service. The in-app picker identifies that computer explicitly. Directory whitespace is preserved, existing files receive numbered suffixes, and success reports the selected directory. Save and Close remain disabled while choosing and writing. Cancellation or write failure retains the generated bytes; partial failures retain only unsuccessful artifacts for retry. Compositions without a Host picker use the browser file or directory picker and report failures without falling back to downloads. Failed browser writes abort their stream. Progress distinguishes staging, document generation, destination selection, and file writing; rejected staging or generation requests release the controls and retain the selection or request for retry. Student copies remain independent of the source batch and appear through the same class/student drawer flow.

When the original PDF itself exceeds the OCR provider's file ceiling, the bounded-copy path is skipped. PDF.js opens the browser `File` through a temporary Blob URL and rasterizes one selected page at a time below that ceiling, so a hundreds-of-pages source is not first duplicated into one JavaScript `ArrayBuffer`. The Blob URL, PDF.js document, page objects, and canvases are explicitly released when their owning extraction or cutting phase settles.

Configured-root directory rows retain the reference application's physical-directory gestures. A student or descendant row uses three clicks to create a child and four or more clicks to rename the selected directory; a question-library directory uses two clicks to create a child and three or more clicks to rename it. Every directory row reveals its delete action on hover or keyboard focus. Every class, student, directory, paper, and image returned by the current-root scan exposes the applicable create, rename, delete, edit, assignment, and temporary-save actions without an origin-based read-only mode. Every non-hidden library directory remains one folder node even when it contains images and has no child directory, so these actions apply throughout the complete tree. Batch metadata is merged behind its owning directory row and never adds a child node; one row can therefore open direct images from several PDFs saved into the same directory. A library folder's disclosure marker stays at the fixed left inset while its name and image count remain centered. The browser submits only opaque identities from the latest scan; the Host revalidates each target below the current configured root before changing the filesystem. Adding a metadata-backed roster class, student, student folder, or library folder creates its physical hierarchy before the Web mutation succeeds. Renaming a metadata-backed student or student folder moves its current physical directory when present and updates stored assignment paths; metadata-backed library rename moves its physical subtree, while deletion atomically detaches the subtree and removes its batches and dependent student copies.

After OCR layouts are reassembled, a large selection is segmented in configurable four-page core groups. Each semantic child also inspects one adjacent selected page on either side; only questions whose inferred head belongs to the core group are rendered, preventing overlap duplicates while retaining page-boundary continuations. The boundary pass sends bounded OCR evidence instead of retaining a Base64 preview for every page. A recoverable boundary failure no longer cancels sibling groups: the failed group enters full-page visual review with no preliminary questions, where it can recover valid boundaries or be reported as an unverified skipped group. One reusable PDF.js reader reviews independent groups through the Host-advertised concurrency limit, while final rendering, numbering, and append saves remain serialized in source order. At most that many groups allocate inspection previews and review crops at once; a completed review lets those payloads become collectible while it waits for preceding groups, and its final crops are rendered and durably appended as soon as its source-order turn arrives. Any group above the Host's decoded-byte ceiling is divided into more save parts. The first non-empty part creates one paper batch and every later part appends to it, so all parts remain one metadata group behind the destination directory row while neither the source PDF's byte size nor the total crop bytes impose a whole-document limit.

The remaining modules provide daily lesson resources and observation templates, class rosters, roster-matched exam analysis, and template-driven teaching records. The final five Headteacher entries reproduce the reference workbench's Family Communication, Class Records, Talk Records, Seating, and Class Summary: family notices provide eight editable school-scene templates, fact-based WeChat drafts, copy, and saved reuse; the three record families provide independent template libraries and editable follow-up records; seating reuses or imports one roster, supports 3–8 rows and 4–10 columns, randomization and drag-and-drop adjustment, persists one layout per class, and exports a teacher-view image. Roster, score, and seating-roster import accept images, PDF, DOCX, PPTX, and XLSX through the shared OCR Remote, parse MinerU Markdown or HTML tables, coalesce repeated image fragments, and require review where an import can overwrite authored tabular data. Roster rows retain recognized standard and extra columns; score rows match the captured class roster by student number first and then by an unambiguous name. Task categories and colors, memos, ledger categories and entries, calendar items, timetable entries, teaching and headteacher data, seating layouts, question-batch metadata, and assignment metadata are read and written through the generated `teacherWorkbench` Remote; question bytes use dedicated Host media Remotes. Only disclosure, active-module, timetable filter, panel-expansion, import-review, open-drawer, page-sheet, editor-selection, drag state, image-selection state, and the question-cutting queue and progress history stay browser-local. Question Cutting does not search its image library or analyze wrong answers; timetable normalization and question-boundary detection are its model-backed second passes.

Current academic year, teacher identity, school, default subject, weather location, score thresholds, PDF render scale, and crop padding belong to the `ui-teacher-workbench` dsh settings namespace. The General settings row places its description above full-width Basic information, Score thresholds, and Question cutting groups. Render scale controls the PDF.js raster used for oversized OCR pages and final crop pixels; crop padding expands accepted question content in MinerU layout units without crossing adjacent elements. Each class may also retain its own academic-year directory, so multiple years survive reloads while legacy classes fall back to the configured current year. MinerU endpoint, backend, hybrid quality, language, timeout, size limits, and structured-layout batch size belong to the `dsh-ocr-mineru` plugin row in DSH plugin settings. Timetable, question-boundary, and example-proofreading children select **Settings → Models → Tool model**. The default-off question-cutting reasoning switch appears under **Settings → Plugins → Plugin configuration → Document extraction**; source, output, retry, deadline, and storage limits belong to the same `teacher-workbench` row. The weather location accepts a district, county, or city; adding the parent city or province after a comma disambiguates repeated names, for example `Pudong, Shanghai`. The expanded weather panel can update the location and loads validated forecasts through the Host `teacherWorkbench/weather` Remote, so browser cross-origin and privacy policies cannot block the provider request. Voice commands record one Blob with `MediaRecorder`, send it through the Host speech Remote, and pass the configured transcript into the ordinary task, memo, or ledger-entry editor; supplier access and credentials live under **Settings → Models → Service access**, and the speech model is assigned once under **Use cases** for Workbench, conversation, and QQ Consumers.

Workbench voice commands use the shared recorder to convert Chromium WebM and other supported browser containers to 16 kHz mono PCM WAV before the Host call when Web Audio decoding is available. The recorder also samples that Web Audio input: its neutral microphone glyph pulses and fills upward with the current level, and three seconds without audible input finishes recording and starts transcription. QQ messages already send WAV to the same configured ASR service, so the browser path does not depend on that local service also supporting WebM. Hosts without an AudioContext decoder retain the original MediaRecorder blob and require manual recording completion.

While Question Cutting is mounted, the browser rescans the configured student and library roots once per second while the document is visible and immediately after the tab regains focus. Successful directory creation, rename, deletion, image replacement, and assignment also force a fresh scan. Unchanged scans do not rerender the hierarchy; stable filesystem identities preserve expanded rows and valid selections, while removed directories and images disappear on the next scan. Each scan displays only physical directories below the current roots, even when durable records still describe an earlier root. Every visible image can be edited, deleted, assigned where applicable, and selected for temporary Office generation. Open image tiles reload when a changed scan arrives, so a filesystem operation cannot leave a transient missing-image result visible after the discovered-file map has recovered.

Rectangular image erasure samples only an eight-pixel exterior ring around the selection and fills with its median color, so selected dark text cannot turn a light paper background gray.

### Background Question Cutting

The PDF page-range panel places the persisted, default-off question-cutting reasoning switch immediately below the save-directory selector. Turning it off strictly disables reasoning; a reasoning model without an advertised Off effort cannot run question cutting. Confirming a PDF page range captures that PDF's reasoning choice, adds the browser-held file to a plugin-lifetime sequential queue, and immediately frees the upload action for another PDF. Queued PDFs may therefore mix enabled and disabled reasoning, and changing the persisted default for a later upload cannot affect an accepted task's boundary, visual-review, or repair stages. The center workspace lists every accepted file in upload order with its captured page-range label, current stage, integer percentage, saved-question count, elapsed time, and terminal error when applicable. Visual defects are repaired only for their cited question ids. After three local crop revisions, a still-unresolved question keeps its latest Host-validated crop, appears in the completed job's warning count, and does not stop later groups or queued PDFs. Once preliminary question boundaries exist, preview preparation, review timeouts, provider or model failures, thrown review calls, and invalid review output use the same fallback instead of failing the PDF: complete findings mark only their cited questions as unverified, while a failure before complete findings marks every question in the current review scope. One PDF executes at a time to avoid competing PDF.js, OCR, model, and durable-write work, while later uploads remain visible at zero percent with a zero elapsed timer until their turn begins; timing starts only when processing starts.

Each accepted task captures its selected pages, destination, render settings, and reasoning choice before asynchronous work starts. The Host owns a private processing Session, so cutting does not require an open conversation. Unmounting Question Cutting, opening another workbench module, or navigating to another conversation removes only the current view subscriber; it does not cancel the worker or change an accepted task's settings. Returning to Question Cutting reconnects the center panel to the same queue projection. Reloading or closing the browser still ends this in-memory queue.

For a large source, extraction streams selected pages through one temporary PDF.js reader, while segmentation keeps only OCR geometry. Visual review then uses another reusable reader for up to the Host-advertised number of independent semantic groups, while final rendering and persistence remain source ordered. The progress row reports durably completed groups; each non-empty group is appended after every preceding group, and completed reviews let their preview and review-crop payloads become collectible while waiting for that turn. This bounds browser image memory to the configured review window, preserves already-saved work, and saves the current safe group with an unverified warning when visual review fails. A recoverable preliminary-boundary failure is isolated to that page group and receives one full-page recovery review; if it remains unresolved, those pages are skipped with a group warning and later groups continue. OCR failure, invalid or unavailable model configuration, final crop rendering, and durable-write failure remain terminal because they cannot be corrected by isolating one semantic group.

### Question Crop Scale

Equal-sized selected pages contribute repeated question-head lane starts. An empty later lane caps the preceding region at the next start, while recognized owned content crossing that start keeps its complete source extent; a half-empty two-column spread therefore does not force every output canvas to the full spread width.

After every semantic group is merged, the Host returns the maximum MinerU-backed question-region width normalized to its source page. Each region also carries a right-side source limit derived from vertically overlapping content that belongs to another question. PDF.js keeps the region's own left, top, and bottom coordinates and samples at most one maximum width from that left edge without crossing the source limit. The output canvas still uses the maximum width and fills any unavailable right-hand area with white, so separate columns cannot leak into one another while equal-size pages retain one image width and raster scale.

### Extension Points

The package adds one `sidebar.primary.section`, one `shell.overlay` entry, and one `settings.general.item` row. It does not declare new child slots.

## Model Experience

Indirectly, through `@deepseek-ai/dsh-tool-teacher-workbench` ordinary-conversation operations and Host-owned timetable, question-boundary, and example-proofreading children. Those children receive the source text, images, or geometry required by their task, independently of user-conversation history.

#### KV Cache effect

The ordinary-conversation schemas contribute to the parent request prefix; Host-owned children retain independent request caches.

## Known Limitations and Deferred Work

- **Unfinished PDF cuts are browser-local** — module and conversation navigation preserve the plugin-lifetime queue, but a full page reload, browser exit, or application shutdown discards unfinished source files and progress rows. Already committed question images remain durable.
- **Recognized workbench documents require review** — OCR and model reconstruction can still produce incorrect dates, classes, periods, students, scores, or reading order. A timetable class label that does not end in `班` remains unselected until corrected; unmatched score rows are skipped, and raw uploads or unaccepted review data are not stored.
- **Printable score charts remain deferred** — score analysis provides durable exam tables, totals, rankings, rates, multi-exam tracking, and personal growth, but does not yet generate chart-based printable reports.
- **Question cutting still depends on OCR evidence** — the semantic child handles arbitrary or absent numbering, columns, page breaks, subquestions, and figures without a fixed page template, but cannot recover a question whose text and non-text OCR elements are all absent. Host validation rejects invented ids or included recognized section and answer headings.
- **Weather requires Host network access** — the configured geocoder resolves the location and Open-Meteo supplies current conditions plus the next twelve hours; an unavailable provider or Host outbound network does not affect saved workbench data.
- **Voice capture and ASR are separate dependencies** — the command is disabled without `MediaRecorder` or microphone capture, automatic silence completion and level fill require Web Audio, and transcription needs a configured supplier route plus a supported speech model assignment; localized notifications distinguish denied permission, missing microphones, device startup failures, unsupported recording requirements, empty audio, configuration, size, and provider failures. Capture uses the browser computer’s input device and its browser/system permissions; manual stop and manual entry remain available.
- **Holiday schedules are published per year** — the calendar shows Chinese statutory holidays and adjusted workdays for included years and reports when a year's schedule is unavailable; Gregorian dates, lunar dates, and personal items remain usable.
