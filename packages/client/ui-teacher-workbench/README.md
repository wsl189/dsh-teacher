# @deepseek-ai/dsh-client-ui-teacher-workbench

English | [中文](README.zh.md)

Teacher-workbench feature for the dsh Web GUI. It contributes a Workbench disclosure between New Session and workspace browsing, an in-app teaching surface in `shell.main`, and a feature-owned row in General settings. Selecting a disclosed module replaces the visible center content while keeping the application sidebar available. The surface begins directly with the active module instead of repeating a Workbench header; selecting or reselecting a Session, including New Session navigation, dismisses it and reveals the still-mounted conversation.

The surface begins with Daily Management. A right-aligned summary beside the module heading shows the current time, date, configured location, and current weather; selecting it opens the full time and next-twelve-hours forecast. Today, Important, and Urgent each occupy an equal-width independent task card alongside editable quick notes and an expandable calendar with Gregorian dates, lunar dates, statutory holidays, and date-specific items. Creating inside a task card assigns that exclusive category, and editing can move a task between cards. Important and Urgent rows expose a ten-color marker picker, while Today rows omit the marker. The expanded calendar accepts images, PDF, DOCX, PPTX, and XLSX school calendars through the shared OCR Remote, projects recognized dates and activities into an editable review list, and persists only selected rows in one revisioned write. HTML table projection respects row and column spans so responsibility metadata remains separate from dated activities.

The Timetable module switches among Today, Week, Grade, and Morning/Evening Study views. Today and Week can select one class or filter all durable entries to the teacher name from dsh settings; personal views retain the class label for every lesson. Today, Week, and Study share one normal timetable class catalog, while Grade owns an independent class catalog and projects only its selected grade. Classes recognized or created in Grade therefore never appear in Today, Week, Study, rosters, score analysis, or Question Cutting; roster classes are likewise absent from timetable controls. Class creation uses an icon-only control in every editable view. Week and Study use an icon-only control to delete the selected normal class, while Grade exposes icon-only deletion on each class row; every icon keeps an accessible label and tooltip. Confirmation identifies that the class and all of its timetable entries are removed, and a successful selected-class deletion advances the picker to the next available class. Creating a timetable class asks for its name and grade. Course creation has no toolbar action: selecting an empty Week, Grade, or Study cell opens the lesson editor with that cell's class, weekday, period, and study type where applicable. Week, Grade, and Study accept images, PDF, DOCX, PPTX, and XLSX through the shared OCR Remote and require an editable review of class, grade, type, weekday, period, times, subject, teacher, and location before one bulk write. Grade extraction retains peripheral OCR text so a grade label omitted from the main table Markdown can still name ordinal class columns; Study also accepts arrangements whose classes are columns and weekdays are rows, including separate morning and evening tables with subject abbreviations. A recognized class label must end in `班` before its row can be selected for import, so structural text such as a period or header remains unselected until corrected. Accepted entries replace an occupied class/type/weekday/period slot instead of creating contradictory schedules.

The Question Cutting module preserves the reference application's top bar, current-year/class hierarchy, layered drawers, and operating flow while omitting only its wrong-question analysis and image-search workspace. Its class hierarchy reads the roster catalog only, so normal and grade-timetable classes cannot appear there. Its surfaces use DSH design tokens, so backgrounds, labels, borders, controls, masks, and accents follow the active light or dark appearance instead of keeping the standalone application's black-and-orange palette. Double-clicking a class opens its student drawer; inside that drawer, a single click opens images, a double click expands or collapses nested folders, and a triple click creates a durable subfolder. Selecting a PDF opens the reference page-range sheet; blank input means every page, and comma-separated pages or ranges such as `1-5,8` are accepted. The module then calls the shared `ocr.layout` Remote for MinerU page geometry. A deterministic rule chooses a monotonic question-number chain near one shared left margin, converts adjacent markers into one or more page regions, uses PDF.js to rasterize and vertically join crops from the original browser-held PDF, and automatically saves the resulting batch. The durable image library supports selection, preview, rectangular erasure, rotation, Save As, overwrite, deletion, and copying selected questions to one roster student or nested folder. In a student's image drawer, Save temporarily replaces that student's previous generation selection with snapshots of exactly the checked images and shows the staged count. The Toolbox Word and PowerPoint entries first open the reference directory picker, naturally order its images, generate one artifact named after that directory, and present Save or Retry. The class drawer retains separate Word and PowerPoint actions and enables them only when at least one student has temporary images: Word opens independent title/name/date rows with bulk controls, PowerPoint starts immediately, and both consume only each student's staged snapshots, remove successful selections, and return one file per student instead of a ZIP. A single generated file uses Save As, while multiple results download individually without requesting write access to an entire directory, avoiding Chromium's protected-system-folder restriction. Student copies remain independent of the source batch and appear through the same class/student drawer flow.

The remaining modules provide daily lesson resources and observation templates, class rosters with spreadsheet-paste import, roster-matched exam analysis, and template-driven teaching records. Task categories and colors, notes, calendar items, timetable entries, teaching data, question-batch metadata, and assignment metadata are read and written through the generated `teacherWorkbench` Remote; question bytes use dedicated Host media Remotes. Only disclosure, active-module, timetable filter, panel-expansion, import-review, open-drawer, page-sheet, editor-selection, and image-selection state stay browser-local. Question search, wrong-question analysis, and an LLM second-pass filter are intentionally outside this module.

Current academic year, teacher identity, school, default subject, weather location, speech-recognition language, score thresholds, PDF render scale, and crop padding belong to the `ui-teacher-workbench` dsh settings namespace. Each class may also retain its own academic-year directory, so multiple years survive reloads while legacy classes fall back to the configured current year. MinerU endpoint, backend, hybrid quality, language, timeout, and size limits belong to the `dsh-ocr-mineru` plugin row in DSH plugin settings. Question batch and student roots plus per-image and per-batch byte limits belong to the `teacher-workbench` plugin row. The weather location accepts a district, county, or city; adding the parent city or province after a comma disambiguates repeated names, for example `Pudong, Shanghai`. The expanded weather panel can update the location and loads validated forecasts through the Host `teacherWorkbench/weather` Remote, so browser cross-origin and privacy policies cannot block the provider request. Voice commands request microphone access before starting the browser Web Speech API and pass recognized text into the ordinary task or note editor.

## Extension Points

The package occupies `sidebar.workbench`, adds one `shell.main` entry, and registers one `settings.general.item` row. It does not declare new child slots.

## Model Experience

None, as the workbench stores and renders teacher-owned operational data without adding prompt content, tools, or transcript events.

#### KV Cache effect

None; the package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **Roster import remains clipboard-only** — tab-separated spreadsheet data and ordinary quoted CSV are supported for class rosters; native workbook files are accepted only by calendar recognition, and charts suitable for printable reports are deferred.
- **Recognized calendars and timetables require review** — dense tables, merged cells, scans, and handwriting can produce incorrect dates, classes, periods, or reading order; a timetable class label that does not end in `班` remains unselected until corrected, and raw uploads or unselected rows are not stored.
- **Question detection is deterministic** — it expects a visible, increasing sequence of top-level Arabic question numbers near a common left margin. Unnumbered papers, Roman numerals, unusual columns, or ambiguous subquestion numbering may produce no cuts or coarse boundaries; the failure dialog offers retry but never invokes an LLM to guess missing structure.
- **Weather requires Host network access** — the configured geocoder resolves the location and Open-Meteo supplies current conditions plus the next twelve hours; an unavailable provider or Host outbound network does not affect saved workbench data.
- **Voice support is browser-dependent** — the voice command is disabled when the Web Speech API is absent; microphone permission, missing-device, no-speech, language, and recognition-network failures appear as localized notifications, while manual entry remains available.
- **Holiday schedules are published per year** — the calendar shows Chinese statutory holidays and adjusted workdays for included years and reports when a year's schedule is unavailable; Gregorian dates, lunar dates, and personal items remain usable.
