# @deepseek-ai/dsh-client-ui-teacher-workbench

English | [中文](README.zh.md)

Teacher-workbench feature for the dsh Web GUI. It contributes a Workbench disclosure between New Session and workspace browsing, an in-app teaching surface in `shell.main`, and a feature-owned row in General settings. Selecting a disclosed module replaces the visible center content while keeping the application sidebar available. The surface begins directly with the active module instead of repeating a Workbench header; selecting or reselecting a Session, including New Session navigation, dismisses it and reveals the still-mounted conversation.

The surface begins with Daily Management. A right-aligned summary beside the module heading shows the current time, date, configured location, and current weather; selecting it opens the full time and next-twelve-hours forecast. Today, Important, and Urgent each occupy an equal-width independent task card. Quick Notes, Ledger, and Calendar form a second three-card row. The Ledger card opens a full-board view whose categories can be added or deleted; each category accepts manual or voice descriptions, a CNY amount, and a required local date and time, while existing entries remain editable. Creating inside a task card assigns that exclusive category, and editing can move a task between cards. Important and Urgent rows expose a ten-color marker picker, while Today rows omit the marker. The expanded calendar combines Gregorian dates, lunar dates, statutory holidays, and date-specific items; it also accepts images, PDF, DOCX, PPTX, and XLSX school calendars through the shared OCR Remote, projects recognized dates and activities into an editable review list, and persists only selected rows in one revisioned write. HTML table projection respects row and column spans so responsibility metadata remains separate from dated activities.

The Timetable module switches among Today, Week, Grade, and Morning/Evening Study views. Today and Week can select one class or filter all durable entries to the teacher name from dsh settings; personal views retain the class label for every lesson. Today, Week, and Study share one normal timetable class catalog, while Grade owns an independent class catalog and projects only its selected grade. Classes recognized or created in Grade therefore never appear in Today, Week, Study, rosters, score analysis, or Question Cutting; roster classes are likewise absent from timetable controls. Class creation uses an icon-only control in every editable view. Week and Study use an icon-only control to delete the selected normal class, while Grade exposes icon-only deletion on each class row; every icon keeps an accessible label and tooltip. Confirmation identifies that the class and all of its timetable entries are removed, and a successful selected-class deletion advances the picker to the next available class. Creating a timetable class asks for its name and grade. Course creation has no toolbar action: selecting an empty Week, Grade, or Study cell opens the lesson editor with that cell's class, weekday, period, and study type where applicable. Week, Grade, and Study accept images, PDF, DOCX, PPTX, and XLSX. Every upload first passes through MinerU. Raster images request an enhanced whole-image pass plus overlapping detail regions, while PDF and Office files use their extracted content. Deterministic reconciliation parses the enhanced overview and the combined detail regions as separate candidates, keeps the candidate with more distinct timetable slots, and prefers the detail candidate on a tie. It joins split weekday headings, repeated class axes, split subject/teacher rows, and chronological local period blocks; Study tables derive their kind from titles inside or outside the table and reconcile class labels by grade and terminal class number, preferring the captured catalog and then the first complete source spelling. When these rules produce no usable entries, one text agent loop inspects the MinerU result, submits compact semantic matrix blocks without fixed layout assumptions, patches rejected draft lines, and returns the accepted draft token through structured output. The destination, class catalog, grade, and defaults are captured before asynchronous work starts, so changing views cannot reroute an import. The browser still requires an editable review of class, grade, type, weekday, period, times, subject, teacher, and location before one bulk write. A recognized class label must end in `班` before its row can be selected for import, and accepted entries replace an occupied class/type/weekday/period slot instead of creating contradictory schedules.

The Question Cutting module preserves the reference application's top bar, current-year/class hierarchy, layered drawers, and operating flow while omitting only its wrong-question analysis and image-search workspace. Its class hierarchy reads the roster catalog only, so normal and grade-timetable classes cannot appear there. Its surfaces use DSH design tokens, so backgrounds, labels, borders, controls, masks, and accents follow the active light or dark appearance instead of keeping the standalone application's black-and-orange palette. Double-clicking a class opens its student drawer; inside that drawer, a single click opens images, a double click expands or collapses nested folders, and a triple click creates a durable subfolder. Selecting a student shows every assigned question across that student's root and nested folders, while selecting a folder limits the image drawer to that folder. Student and folder labels remain centered between fixed inset row actions. Selecting the same student or folder again closes its image drawer. Student images and the question library are mutually exclusive: opening either closes the other before displaying its own drawer, choosing a batch opens its images beside the library folders, and selecting that batch again closes them. Closing the class drawer also closes its image drawer first. Selecting a PDF opens the reference page-range sheet; blank input means every page, and comma-separated pages or ranges such as `1-5,8` are accepted. The browser reads the selected OCR provider's current limits, copies only those source pages into bounded PDF batches, bisects an oversized batch, and rasterizes a single copied page only when it cannot fit. The original PDF therefore remains browser-held regardless of its byte size. Each batch calls the shared `ocr.layout` Remote for MinerU page geometry, then the module starts one short-lived question-boundary agent loop with the configured tool model and built-in semantic skill. The child reads bounded chunks of provider-neutral OCR elements, infers the current PDF's question-head convention, and submits top-level heads plus any out-of-order continuations, figures, and excluded headings by opaque element id before returning an accepted token. Numbering may use any syntax, restart, repeat, vary by chapter, or be absent. The Host rejects mismatched or invented ids, unexcluded recognized section or answer headings, and empty crops; it normalizes valid heads by authoritative OCR order and assigns unique source-order display numbers, maps accepted ids back to trusted two-dimensional coordinates, and clamps padding against neighboring content. PDF.js then rasterizes the original browser-held PDF, vertically joins regions for a question that genuinely crosses pages, and automatically saves the resulting batch. The durable image library supports selection, preview, rectangular erasure, rotation, Save As, overwrite, and deletion. Opening the library from the top bar saves selected images to a browser-chosen local directory with collision-safe names; opening it from a student or nested folder instead assigns the selected images directly to that target. In a student's image drawer, Save temporarily replaces that student's previous generation selection with snapshots of exactly the checked images and shows the staged count. The Toolbox Word and PowerPoint entries first open the reference directory picker, naturally order its images, generate one artifact named after that directory, and present Save or Retry. The class drawer retains separate Word and PowerPoint actions and enables them only when at least one student has temporary images: Word opens independent title/name/date rows with bulk controls, PowerPoint starts immediately, and both consume only each student's staged snapshots, remove successful selections, and return one file per student instead of a ZIP. Saving either class output opens one destination-directory picker and writes every per-student artifact there with collision-safe names. Student copies remain independent of the source batch and appear through the same class/student drawer flow.

After OCR layouts are reassembled, a large selection is segmented in configurable 20-page core groups. Each semantic child also inspects one adjacent selected page on either side; only questions whose inferred head belongs to the core group are rendered, preventing overlap duplicates while retaining page-boundary continuations. Groups are rendered successively, and any group above the Host's decoded-byte ceiling is divided into more save parts. The first part creates one paper batch and every later part appends to it, so the library displays one entry for the upload while neither the source PDF's byte size nor the total crop bytes impose a whole-document limit.

The remaining modules provide daily lesson resources and observation templates, class rosters with spreadsheet-paste import, roster-matched exam analysis, and template-driven teaching records. Task categories and colors, notes, ledger categories and entries, calendar items, timetable entries, teaching data, question-batch metadata, and assignment metadata are read and written through the generated `teacherWorkbench` Remote; question bytes use dedicated Host media Remotes. Only disclosure, active-module, timetable filter, panel-expansion, import-review, open-drawer, page-sheet, editor-selection, and image-selection state stay browser-local. Question search and wrong-question analysis remain outside this module; timetable normalization and question-boundary detection are its model-backed second passes.

Current academic year, teacher identity, school, default subject, weather location, speech-recognition language, score thresholds, PDF render scale, and crop padding belong to the `ui-teacher-workbench` dsh settings namespace. Each class may also retain its own academic-year directory, so multiple years survive reloads while legacy classes fall back to the configured current year. MinerU endpoint, backend, hybrid quality, language, timeout, size limits, and structured-layout batch size belong to the `dsh-ocr-mineru` plugin row in DSH plugin settings. Timetable and question-boundary children select **Settings → Models → Tool model**; source, output, retry, and deadline limits belong to the `teacher-workbench` plugin row alongside question-storage limits. The weather location accepts a district, county, or city; adding the parent city or province after a comma disambiguates repeated names, for example `Pudong, Shanghai`. The expanded weather panel can update the location and loads validated forecasts through the Host `teacherWorkbench/weather` Remote, so browser cross-origin and privacy policies cannot block the provider request. Voice commands request microphone access before starting the browser Web Speech API and pass recognized text into the ordinary task, note, or ledger-entry editor.

## Extension Points

The package occupies `sidebar.workbench`, adds one `shell.main` entry, and registers one `settings.general.item` row. It does not declare new child slots.

## Model Experience

Indirectly, through two Host-owned children. Timetable-agent fallback receives extracted Markdown and captured view defaults when MinerU rules find no entries. Question cutting sends provider-neutral MinerU text, equations, images, tables, and geometry to a semantic boundary child on every run. The exact model-visible prompts, validation protocols, output schemas, and Session events belong to `@deepseek-ai/dsh-host-teacher-workbench`.

#### KV Cache effect

No direct effect; the Host-owned child has an independent request cache from the parent conversation.

## Known Limitations and Deferred Work

- **Roster import remains clipboard-only** — tab-separated spreadsheet data and ordinary quoted CSV are supported for class rosters; native workbook files are accepted only by calendar recognition, and charts suitable for printable reports are deferred.
- **Recognized calendars and timetables require review** — OCR and model reconstruction can still produce incorrect dates, classes, periods, or reading order; a timetable class label that does not end in `班` remains unselected until corrected, and raw uploads or unselected rows are not stored.
- **Question cutting still depends on OCR evidence** — the semantic child handles arbitrary or absent numbering, columns, page breaks, subquestions, and figures without a fixed page template, but cannot recover a question whose text and non-text OCR elements are all absent. Host validation rejects invented ids or included recognized section and answer headings.
- **Weather requires Host network access** — the configured geocoder resolves the location and Open-Meteo supplies current conditions plus the next twelve hours; an unavailable provider or Host outbound network does not affect saved workbench data.
- **Voice support is browser-dependent** — the voice command is disabled when the Web Speech API is absent; microphone permission, missing-device, no-speech, language, and recognition-network failures appear as localized notifications, while manual entry remains available.
- **Holiday schedules are published per year** — the calendar shows Chinese statutory holidays and adjusted workdays for included years and reports when a year's schedule is unavailable; Gregorian dates, lunar dates, and personal items remain usable.
