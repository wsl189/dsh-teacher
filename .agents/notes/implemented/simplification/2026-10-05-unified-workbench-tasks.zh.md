# Agent Note: 统一工作台导航与任务

Status: implemented

[English](2026-10-05-unified-workbench-tasks.md) | 中文

## 问题

工作台作为浮层覆盖所选主面板。选择插件或自动化任务只改变 Layout，并不移除浮层，因此所选页面仍被遮挡。独立 cron 任务页还会显示已经由工作台通知运行时管理的提醒，与官方自动化任务入口重复。

## 决策

工作台注册带 key 的 `main` 面板，并通过 Layout 选择它。共享视图 store 保留展开状态与模块选择，活动面板只由 Layout 管理。因此插件、自动化任务和会话导航使用同一个挂载生命周期。

自动化任务拥有 root 列表 slot `schedule.manager.sources`，并把搜索与状态筛选传给各功能板块。工作台通过生成的 Remote 贡献现有活动提醒投影。持久写入和发送确认会发出 `teacherWorkbench/changed`；浏览器数据源在该事件或重连后刷新，丢弃被替代的读取，并在卸载与插件释放时移除订阅。选择提醒会返回原工作台面板进行编辑。

发行组合移除 `dsh-plugin-cron`、其工具、侧边栏、审阅后的归档和兼容补丁。现有工作台事项、通知发送与官方 Schedule 任务保留各自的存储和执行所有者。旧 cron 命令记录与历史仍保留在用户存储中，shell 命令不会转换为模型提示或通知。升级指南说明这项能力移除。

本决策部分取代[移动端工作台提醒](../feature/2026-08-22-mobile-workbench-reminders.zh.md)中的展示方式、[持久教师工作台](../feature/2026-08-17-durable-teacher-workbench.zh.md)中的面板位置，以及[内置扩展](../feature/2026-08-25-bundled-extensions-and-qq-speech.zh.md)中的 cron 交付。其持久化、通知和其余发行决策仍然有效。

## 考虑过的替代方案

**在每种导航事件后隐藏浮层。** 每个新增全局页面都需要另一条同步路径。标准主面板所有权提供单一选择与挂载约定。

**把工作台提醒复制到 Schedule 记录。** 工作台直接通知机器人，并遵循事项完成语义，区别于 Schedule 的会话提示。重复记录需要同步写入，可能重复发送或产生模型调用。

**保留第三方 cron 页面或静默转换命令任务。** 前者保留重复导航，后者改变执行方式、权限、结果与成本。移除内置命令调度器会保留旧数据，不宣称行为等价。

## 影响

- 一个自动化任务页面展示会话任务和活动工作台提醒。搜索与状态筛选适用于两个来源；未活动的工作台提醒仍在原事项中管理。
- 无需挂载浏览器，工作台提醒也会继续发送。只有目录订阅依赖页面生命周期。
- 现有用户存储不会被重写或删除。独立挂载的旧 cron 插件需要从自定义 profile 中明确移除。
- 未来的命令调度器需要明确的命令执行所有者与迁移约定，提醒目录不承担该职责。

## 测试

组合浏览器回归在浮层实现中选择插件后失败。它覆盖工作台、插件、自动化任务、返回工作台与再次选择会话。目录测试覆盖失效竞态、连接重置、重试、共享订阅和释放。组件测试覆盖四类提醒所有者及共用筛选。现有提醒运行时测试继续覆盖发送、持久确认、截止时间对齐与重启。

安装后载荷校验发现 `entities-6.0.1.tgz` 源码归档缺失，尽管解包后的构建完整；完整文件比对还发现一个插件文档视频缺失。NSIS 从应用归档中排除了配置的预压缩扩展名，但单独复制这些文件时跳过了 `node_modules`。因此桌面配置关闭这条单独复制路径，让依赖中的资源保留在普通应用归档中。解包载荷和安装后文件都必须通过校验，才能交付预览安装器。
