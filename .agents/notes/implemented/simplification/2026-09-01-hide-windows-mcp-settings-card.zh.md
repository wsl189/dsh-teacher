# Agent Note：隐藏内置 Windows-MCP 设置卡片

Status: implemented

[English](2026-09-01-hide-windows-mcp-settings-card.md) | 中文

## 问题

通用「插件配置」标签页把内置 Windows 桌面集成呈现为由用户管理的 Host 插件。安装版桌面已经拥有其运行时与启用默认值，因此这张额外卡片在产品不应展示 Windows 桌面控制配置项的位置暴露了实现设置、运行时可用状态与权限文案。

删除整个 Host 集成也会移除安装即用的桌面控制。忽略持久化值则会为曾主动关闭该集成的用户重新启用它。

## 决策

`dsh-client-ui-settings-plugins` 不为 `windows-mcp` 命名空间注册 `settings.plugin.item` occupant。其源码不包含 Windows 专用卡片、controller、样式、locale 键或导出的卡片 face；单元覆盖只把被服务的该命名空间视为有意无人认领的键。通用标签页渲染已服务 Host 命名空间与已注册卡片键的交集，因此被服务的 `windows-mcp` 命名空间不会产生配置行。

Host 插件、设置命名空间、安装版运行时、组合默认值与权限策略保持不变。受信任桌面运行时仍会默认启用该集成；未提供该运行时的部署保持关闭；已有持久化 `enabled` 值仍会覆盖组合默认值。通用「插件配置」标签页不展示该值或运行时状态。

包注册测试会服务 `windows-mcp`，同时断言只派发被卡片认领的命名空间。已组装 Web 场景及其归属本地的无障碍快照会断言 Windows 桌面配置行不存在。发行组合测试继续拥有运行时存在和缺失时的默认值，以及持久化关闭值覆盖。

## 考虑过的替代方案

**删除 Host 插件与设置命名空间。** 这会删除桌面能力及其持久化状态，超出本次呈现变更的范围。

**保留禁用或只读卡片。** 不需要的 Windows 桌面控制配置项仍会出现在「插件配置」中。

**忽略已有持久化值。** 这会在下次启动或升级时丢弃用户的主动选择。

## 结果

- 「插件配置」包含六张内置卡片，不再出现 Windows 桌面控制配置行。
- 桌面控制仍按受信任运行时、组合默认值与已有持久化用户值启动；该页面不再提供启用开关或运行时警告。
- Windows-MCP 工具目录、批准行为、进程权限与会话隔离保持不变。
- 生成的客户端 slot 目录为 `settings.plugin.item` 列出六个发行 occupant；其中没有 `WindowsMcpCard`。
