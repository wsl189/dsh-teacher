# Agent Note: 工具模型课程表整理

Status: implemented

[English](2026-08-20-tool-model-timetable-normalization.md) | 中文

## 问题

MinerU 可以提取文本与表格标记，但学校课程表并不共用一种可靠布局。合并单元格、转置的星期与班级、分开的早晚自习表、表格外围的年级标签、OCR 阅读顺序错误，以及一个文档中的多个班级，会让确定性 Markdown 解析器不断积累布局专用分支。错误行不能在没有复核的情况下成为持久课程表条目。

产品持有的后台 AI（人工智能）工作还需要一项区别于对话默认值的模型选择。自由填写提供方或模型会让设置指向已配置模型目录中不存在的路由，并把失败延迟到导入运行时。

## 决策

`agent-default-model` 设置分节把 `toolProvider` 与 `toolModel` 作为一组经过校验的字段存储。`currentToolSelection()` 返回该组合；两项都不存在时回退到当前默认提供方与模型。**设置 → 模型 → 工具模型**只列出凭据要求已满足的存活路由所提供的模型，并在一次带 revision 校验的变更中写入两项字段。UI 不接受自由填写模型 id。

识别开始前，浏览器会锁定“班级课表”“年级课表”或“早晚自习”目标及其班级目录与当前默认值。每份上传文件都会先经过 MinerU；栅格图片请求一份增强整图与相互重叠的细节区域，PDF 与 Office 文档使用提取内容。浏览器会把增强整图与合并后的细节文档作为两个独立候选，分别去重，保留具有更多不同课程表时段的候选，并在数量相同时优先采用细节候选。在每个候选中，它会把星期表头扩展到连续递增的班级区段，选择具有节次数据的轴而不是复合角标题，拼合分离的课程与教师行，并按来源顺序展开重复的局部节次序列。早晚自习分类会读取表内或表外标题。相同年级且末尾班号一致的班级标签优先使用锁定目录中的名称；目录中没有时使用来源中首个完整写法，因此早读与晚自习子表的括号差异不会拆分同一班级。非空的确定性结果会直接进入可编辑复核；只有结果为空时，才会把 MinerU Markdown 交给文本 agent 尝试一次。组装后的 Web 配置为该降级子 agent 分配 5 分钟，以便检查与修补。

每次尝试都会在当前存活 Session 下启动一个全新的 `spawn` subagent loop，使用工具模型选择、一个只在本次运行存在的只读来源工具、一个矩阵提交工具与一个按行 splice 的修补工具。agent 用紧凑行协议编码相关内容；每个区块声明常量、两条语义轴、共享单元格字段和用制表符分隔的数据行。agent 只提交一次完整矩阵；Host 会保留该草稿，并返回具体的解析、语义轴、维度、目标、字段和行数上限错误及相关的从 1 开始计数的行。后续工具调用只把被拒绝的行 splice 到已存草稿中，因此局部修正不会丢失无关的有效区块。最终结构化输出只携带同一次运行中已接受矩阵的不透明令牌。解析器还会规范化通过左括号与首个参数相连的协议关键字。目标指令只选择有效业务记录，不规定来源坐标、行列、样式或文件类型。通用的时间顺序规范化会把同一矩阵区块中的重复局部节次表头展开为不同的后续节次。

课程表子 agent 不设置 `maxTokens`。因此 agent loop 会从所选工具模型路由解析合计 `contextWindow` 与适配器配置的默认输出额度。课程表专用的固定输出额度会脱离模型设置占用输入容量，并可能使原本可用的请求被上下文窗口拒绝。

Host 会校验字段长度、星期、节次、时间、条目数量、目标类型、语义轴、矩阵维度、精确字段和校验令牌，再按班级／年级／类型／星期／节次去重。它会用来源年级与锁定的班级目录补全纯数字班级叶子，同时保留完整层级班级名。只有负责人的自习值班记录可以缺少课程与明确时段：Host 会补上“早自习”或“晚自习”业务标签，并按来源顺序编号同一星期的重复未编号安排；普通课程仍必须具有来源支持的课程和节次。服务缺失、父 Session 陈旧、输入过大、超时、模型失败，以及无效或空输出都会返回稳定失败。即使用户在提取期间切换视图，浏览器仍以锁定的导入目标与班级目录处理接受的行；不以“班”结尾的班级名称保持未选中，只有明确选择的行才会进入带修订号的批量导入。

## 已考虑的替代方案

**把每份课程表都交给 agent。** 密集年级表会消耗多轮模型请求，而且仍可能遗漏 MinerU 已经表示为规则行的区块。确定性整理可以快速处理已经识别出的表格关系；只有提取结构没有生成任何条目时才需要 agent。

**栅格上传优先由模型直接视觉识别。** 实测本地多模态路由处理所给密集年级表耗时更长，且返回的行不完整。MinerU 细节区域提供与模型提供方无关的首选路径，并允许成功导入完全不发起模型请求。

**使用对话模型选择。** 后台提取可能需要比交互对话更快或成本更低的路由，改变其中一项不应静默改变另一项。

**允许自由填写工具模型 id。** 这会接受拼写错误和不可用路由。把选择器限制为可用的已配置路由，可以让保存的选择立即可执行。

**立即导入结构化输出。** 模型重建具有概率性。可编辑复核仍是持久教师数据的授权点。

## 后果

- 一次栅格导入会执行一次增强 MinerU 运行，通常无需创建子 Session 就能进入复核。只有确定性整理没有识别出条目时才会产生一次子 agent loop。
- 发生降级时，来源元数据、MinerU 来源工具结果、校验调用与工作台默认值对模型可见，并记录在子 Session 中。
- 子 agent 只能调用本次运行唯一的只读来源工具、矩阵提交工具与按行 splice 的修补工具。文档内指令无法授权操作，其结果返回浏览器，不会注入父会话对话。
- 既有设置继续有效，因为工具模型组合缺失时会沿用默认模型。保存新的对话默认值会保留显式工具模型组合。
- 所选工具模型拥有降级请求的上下文容量与默认输出 token；课程表配置保留绝对来源字符安全上限、可接受行数上限与文本墙钟截止时间。
- 确定性解析器决定成功的 MinerU 优先导入；agent 只处理规则没有生成任何结果的提取来源。
- 复核仍为强制步骤，因为 OCR 与模型重建都可能出错。

## 测试

服务测试覆盖工具模型回退与持久化、子 agent 选择、目标 persona、紧凑矩阵解析、相连关键字规范化、保留草稿的行修补、工具限制、校验令牌约束、层级班级补全、自习值班归一化、重复未编号自习行、时段去重、超大输入、服务缺失和无效输出。OCR 测试覆盖增强的完整图片与六个重叠图片区域。客户端测试覆盖锁定的目标上下文、整图／细节候选择优、复合角标题、表内早晚自习标题、裁切与标点写法不同的班级名称对齐、MinerU 优先规则成功、规则结果为空后的 agent 降级、可编辑复核、批量导入与 Remote 接线。真实上传到已配置的 MinerU 端点后，所给单班本周课表得到 40 条已选记录，周一至周五各 8 节；所给早晚自习表得到 110 条已选记录，11 个班各有 5 条早读与 5 条晚自习；所给低分辨率年级课表得到 440 条已选记录，每班 40 条、每天 88 条。结果仍保留可见 OCR 错字，因此可编辑复核仍为必要步骤。
