# Agent Note: 可复用文档提取

Status: implemented

[English](2026-08-18-reusable-document-extraction.md) | 中文

## 问题

教师工作台需要从图片或 Office 文档校历中识别日期与活动，对话输入区则需要可供用户与模型讨论的提取文本。若两条流程都直接绑定 MinerU，会重复上传、上限、错误和传输行为，并让每个浏览器功能各自拥有供应商协议。若自动把 OCR 输出写入日历，还会在没有复核的情况下把不完美的表格识别变成持久教师数据。

文档字节与提取文本的耐久性要求不同。原始文件只需到达已配置的提取器。对话文本只在用户发送后对模型可见，因此必须经普通的已记录用户消息路径进入。日历活动必须进入现有带修订号的教师工作台文档，而不是独立 OCR 存储。

## 决策

`@deepseek-ai/dsh-ocr` 定义 `ctx.ocr`、提供方注册与执行时选择、稳定请求／结果／错误类型，以及 Typert `ocr.extract` Remote。它只在恰好存在一个本地可用提供方时自动选择；否则由显式 `provider` id 拥有选择。请求携带一份规范 base64 文档、名称与媒体类型，也可以要求提供方保留归类到主阅读顺序之外的文本。成功结果携带受限的阅读顺序 Markdown、提供方标识与截断标记。运行时把预期 `OcrError` 转为安全结果数据，并隐藏意外提供方诊断。

`@deepseek-ai/dsh-ocr-mineru` 注册 `mineru` 提供方 id，适配自托管同步 `/file_parse` API。其普通 DSH 插件配置拥有端点、后端、混合解析质量、语言、截止时间、上传上限、响应字节上限与 Markdown 字符上限；**设置 → 插件 → 插件配置**中的卡片通过带修订号的 settings 文档开放全部字段。提供方接受 PDF、受支持的光栅图像、DOCX、PPTX 与 XLSX；校验名称、规范 base64、扩展名、大小、HTTP 状态、响应字节、JSON 字段与非空 Markdown；不持久化源字节或提供方输出。请求丢弃文本的提取会在同一次 MinerU 调用中获取 `middle_json`，并在 Markdown 之前加入其中尚未出现的唯一丢弃文本行。

对话消费方用一枚回形针同时提供现有图片附件与可提取文档。提取 Markdown 会被追加到可见草稿的 `<document name="...">` 包装中，需要时携带显式截断标记。用户发送前可编辑或删除它。发送继续经现有 prompt 路径，因此包装与 Markdown 可从普通已记录 `user/message` 重建；原始文档字节不进入 Session 日志或模型。

教师工作台消费方仅在展开日历中开放校历识别。MinerU Markdown 与 HTML 表格会被确定性投影为带日期的复核行；HTML 投影先解析跨行和跨列单元格，再把事项列与负责人及部门元数据分离。教师可在一次 compare-and-set 变更追加已接受日历事项前选择、编辑或移除行。原始上传、提取 Markdown 与未选复核行保持浏览器瞬时状态；[持久教师工作台决策](2026-08-17-durable-teacher-workbench.md)仍拥有日历事项存储。

## 已考虑的替代方案

**由每个浏览器功能分别调用 MinerU。** 这会重复供应商 multipart 字段、格式校验、资源上限、诊断与设置，也阻止其他提取器同时服务两个消费方。

**把 MinerU 作为面向模型的工具。** 上传本地浏览器文件是人类输入操作，而不是模型自主工作。工具无法提供日历复核交互，并会在未上传文档时也向每个 agent 添加 schema。

**把原始文档发给对话模型。** 提供方文件能力并不一致，源文件比提取文本更大，原始文件持久化还需要持久附件与访问策略设计。当前消费方会在确切提取文本进入已记录消息前向用户展示它。

**立即导入每个识别日历行。** OCR 与表格阅读可能混淆合并单元格、元数据列或日期范围。可编辑复核能防止提供方输出在没有显式选择的情况下成为教师权威数据。

**把识别校历存入 OCR 专用数据库。** 这会把日历权威与修订冲突拆到两个存储中。已接受活动是普通 `TeacherCalendarItem` 值，归属现有带修订号的工作台文档。

**每次提取都包含丢弃文本。** 对话文档与校历不需要重复的页标题、页眉或页脚日期。由消费方选择是否启用，只会为依赖外围文本解释布局的工作流保留这些内容。

## 后果

- 一个已配置提取器同时服务对话与工作台消费方，更换提供方不改变它们的上传或结果类型。提取丢弃文本可能增加响应大小，但不需要第二次提供方调用。
- 已配置 MinerU 端点会收到完整所选文档。部署必须选择访问与保留策略适合这些文档的端点；默认仍为回环地址。
- Base64 JSON 传输会在浏览器与 Host 内存中保留一份完整文件，并扩大线上体积。提供方截止时间与字节上限限制工作量，但流式、进度、取消与提取缓存仍缺席。
- 对话文档文本只会作为可编辑的普通用户消息对模型可见，因此无需新事件类型即可复用现有 Session 耐久性与 KV 前缀行为。
- 日历识别宁可出现假阴性，也不做未复核写入。密集表格、扫描件、手写内容与无可识别日期的布局可能需要手动更正或不产生任何行。

## 测试

能力测试固定提供方选择、disposal、安全诊断、包含混合解析质量与可选丢弃文本的 multipart 字段、规范 base64、格式与大小拒绝、响应校验、截断和 MinerU 失败。客户端测试固定文档到草稿的包装、图片导入兼容、跨行跨列表格投影、正文日期引用、可编辑选择以及单次写入日历导入。组装后的 Web 组合展示 OCR 设置与两个浏览器消费方，关键无外部依赖启动不要求真实 MinerU 服务。
