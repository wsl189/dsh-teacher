# Agent Note: 可复用文档提取

Status: implemented

[English](2026-08-18-reusable-document-extraction.md) | 中文

## 问题

教师工作台需要从图片或 Office 文档中识别校历、学生名册与成绩表，对话输入区则需要可供用户与模型讨论的提取文本。若这些流程都直接绑定 MinerU，会重复上传、上限、错误和传输行为，并让每个浏览器功能各自拥有供应商协议。若自动写入 OCR 输出，还会在没有复核的情况下把不完美的表格识别变成持久教师数据。

文档字节与提取文本的耐久性要求不同。原始文件只需到达已配置的提取器。对话文本只在用户发送后对模型可见，因此必须成为与该提示关联的已记录插件上下文。已接受的日历活动、名册行与考试成绩必须进入现有带修订号的教师工作台文档，而不是独立 OCR 存储。

## 决策

`@deepseek-ai/dsh-ocr` 定义 `ctx.ocr`、提供方注册与执行时选择、稳定请求／结果／错误类型，以及 Typert `ocr.extract` Remote。它只在恰好存在一个本地可用提供方时自动选择；否则由显式 `provider` id 拥有选择。请求携带一份规范 base64 文档、名称与媒体类型，也可以要求提供方保留归类到主阅读顺序之外的文本。成功结果携带受限的阅读顺序 Markdown、提供方标识与截断标记。运行时把预期 `OcrError` 转为安全结果数据，并隐藏意外提供方诊断。

`@deepseek-ai/dsh-ocr-mineru` 注册 `mineru` 提供方 id，适配自托管同步 `/file_parse` API。其普通 DSH 插件配置拥有端点、后端、混合解析质量、语言、截止时间、上传上限、响应字节上限与 Markdown 字符上限；**设置 → 插件 → 插件配置**中的卡片通过带修订号的 settings 文档开放全部字段。提供方接受 PDF、受支持的光栅图像、DOCX、PPTX 与 XLSX；校验名称、规范 base64、扩展名、大小、HTTP 状态、响应字节、JSON 字段与非空 Markdown；不持久化源字节或提供方输出。请求丢弃文本的提取会在同一次 MinerU 调用中获取 `middle_json`，并在 Markdown 之前加入其中尚未出现的唯一丢弃文本行。

对话消费方为可提取文档提供独立文件控件，同时保留既有图片附件流程。选择 PDF、受支持的光栅图像、DOCX、PPTX 或 XLSX 后会立即启动 `ocr.extract`，并创建仅存在于运行时、状态为识别中、已就绪或失败的文件行。textarea 永远不会接收 Markdown。所有文件就绪前发送保持不可用；失败文件必须先移除。提示准入会先把每份就绪结果作为持久 `user/message` 注入，其 source 为 `mineru-ocr` 插件，`notice` 摘要点名文件，然后再排队或插话发送普通人类消息。源字节不进入 Session 日志或模型，成功准入后会清除瞬时文件行。子智能体续聊目前只接受文本，因此拒绝文档上下文。

同一输入栏还拥有语音采集。麦克风按钮用于切换一次 MediaRecorder 会话；长按空格 500 毫秒会启动同一录音器，松键时停止，短按空格仍是普通空格编辑。完整录音通过 `speech.transcribe` Remote 发送，最终转写文本在当前 selection 处进入输入状态机，且仍可由用户编辑。不支持录音的浏览器会禁用该控件，录制或 Host 转写失败通过本地化输入栏通知呈现。[内置扩展与 QQ 语音决策](2026-08-25-bundled-extensions-and-qq-speech.zh.md)持有共享的 QQ 后端提供方，并取代浏览器原生转写。

教师工作台消费方在展开日历、学生名册与成绩分析中开放文档识别。校历 Markdown 与 HTML 表格会被确定性投影为带日期的复核行；HTML 投影先解析跨行和跨列单元格，再把事项列与负责人及部门元数据分离。名册与成绩表接受 MinerU Markdown 或 HTML，跳过重复表头，并合并完全相同的图片分块。名册复核保留识别到的标准列与额外列。成绩复核先按学号、再按不重复姓名匹配异步工作开始时锁定的班级名册，把重复分块合并为每名学生一条记录，以文件名生成初始考试名称，并允许教师修改考试元数据。教师确认复核数据后才执行一次 compare-and-set 变更。原始上传、提取 Markdown 与复核数据保持浏览器瞬时状态；[持久教师工作台决策](2026-08-17-durable-teacher-workbench.zh.md)仍拥有已接受的日历、名册与考试存储。

## 已考虑的替代方案

**由每个浏览器功能分别调用 MinerU。** 这会重复供应商 multipart 字段、格式校验、资源上限、诊断与设置，也阻止其他提取器同时服务两个消费方。

**用面向模型的工具替代浏览器导入与复核。** 上传本地浏览器文件是人类输入操作，工具无法提供校历、名册或成绩复核。后续的[路径型文档读取器](2026-08-22-agent-document-reader.zh.md)补充了这些流程：它只在 `ctx.ocr` 存在时以提供方无关方式注册，并读取 agent 可访问的工作区路径，而不是仅存在于浏览器的文件。

**把原始文档发给对话模型。** 提供方文件能力并不一致，源文件比提取文本更大，原始文件持久化还需要持久附件与访问策略设计。当前消费方展示提取状态，并把确切提取文本记录为可检查上下文，而不把它暴露为可编辑提示文本。

**把 OCR Markdown 追加到可见草稿。** 这会让大型文档占满编辑器、向用户暴露实现包装，并使无关输入可能破坏已提取表格。独立瞬时文件行负责移除与状态，已记录插件上下文消息则保留模型实际看到的字节。

**立即导入每个识别工作台行。** OCR 与表格阅读可能混淆合并单元格、元数据列、身份、成绩或日期范围。复核能防止提供方输出在没有显式确认的情况下成为教师权威数据。

**把识别校历存入 OCR 专用数据库。** 这会把日历权威与修订冲突拆到两个存储中。已接受活动是普通 `TeacherCalendarItem` 值，归属现有带修订号的工作台文档。

**每次提取都包含丢弃文本。** 对话文档与校历不需要重复的页标题、页眉或页脚日期。由消费方选择是否启用，只会为依赖外围文本解释布局的工作流保留这些内容。

## 后果

- 一个已配置提取器同时服务对话与工作台消费方，更换提供方不改变它们的上传或结果类型。提取丢弃文本可能增加响应大小，但不需要第二次提供方调用。
- 已配置 MinerU 端点会收到完整所选文档。部署必须选择访问与保留策略适合这些文档的端点；默认仍为回环地址。
- 浏览器 Base64 JSON 传输会在浏览器与 Host 内存中保留一份完整文件，并扩大线上体积。提供方截止时间与字节上限限制工作量，但浏览器流式、进度、取消与提取缓存仍缺席；同进程路径读取器会单独转发工具取消信号。
- 对话文档文本会作为紧邻人类提示之前、带插件 source 的已记录用户角色上下文消息对模型可见。Session 重放无需新事件类型即可重建它，同时输入栏保持紧凑，用户也能在准入前移除文件。
- 工作台文档识别宁可出现假阴性，也不做未复核写入。密集表格、扫描件、手写内容、含糊的名册姓名与无可识别表头的布局可能需要手动更正或不产生任何行。

## 测试

能力测试固定提供方选择、disposal、安全诊断、包含混合解析质量与可选丢弃文本的 multipart 字段、规范 base64、格式与大小拒绝、响应校验、截断和 MinerU 失败。客户端测试固定对话文档状态机、发送门控、隐藏上下文载荷、语音按钮与长按空格手势、图片导入兼容、跨行跨列校历投影、Markdown 与 HTML 名册及成绩解析、重复分块合并、名册匹配、复核行为和带修订号写入。Host 测试固定上下文先于提示的注入顺序与 wire 上限。无外部依赖 Web 快照覆盖对话文件行、持久 `mineru-ocr` 上下文，以及组装应用中的名册与成绩持久化，且不要求真实 MinerU 服务。另一条已组装 Web 场景录制输入框音频，通过真实 speech Remote 调用确定性的 QQ 兼容 ASR 服务，并在不请求模型的情况下固定可编辑转写文本。
