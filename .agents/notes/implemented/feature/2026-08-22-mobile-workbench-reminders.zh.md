# Agent Note: 手机端工作台提醒

Status: implemented

[English](2026-08-22-mobile-workbench-reminders.md) | 中文

> 扩展[持久化教师工作台](2026-08-17-durable-teacher-workbench.zh.md)。其中的全局文档、比较后写入和浏览器持久化决策仍然有效。

## 问题

日常待办和带日期的日历事项可以保存截止时间，备忘录与账目则完全没有通知时间；这些记录都不会在浏览器之外产生通知。通用 cron 任务与 IM 机器人分别存在于独立插件中，两者都没有足够信息把工作台事项变成持久提醒：cron 插件不拥有事项完成状态或截止时间修改，工作台也没有一种不暴露凭据的方式，从一个平台的多个机器人中选择并寻址其中一个。

提醒状态必须跨 Host 重启保留，跟随编辑与完成状态而不遗留过期任务，并且不能把平台凭据或私聊标识复制到工作台文档或浏览器 Remote 载荷。未填写完整提醒配置的事项必须保持普通的仅截止时间行为。

## 决策

教师工作台文档版本 10 允许每个日常待办、备忘录、账目或日历事项携带一份提醒。备忘录和账目使用独立的可选本地提醒截止时间，不复用备忘录修改时间或账目发生时间。提醒记录平台、不透明机器人 id、显示名称、从截止时间派生的规范 UTC 时刻、配置时间、上次已接受时刻，以及一次性提前分钟数或固定重复间隔。它不含凭据或会话目标。浏览器待办、备忘录、账本与日历编辑器通过 `teacherWorkbench/listNotificationTargets` 获取不含凭据的机器人列表；待办的时间控件合并截止时间与提醒配置，备忘录编辑器显示同一组字段，账本新增区提供提醒按钮，日历议程行也提供独立提醒入口。两种提醒都接受可自由编辑的数值草稿以及分钟、小时或天单位，并在持久化前把有效值换算为整分钟。空草稿或无效草稿会保持可编辑状态并禁用所在表单的保存操作，而不会在输入期间强制改写数值。截止时间已经过去时，界面会禁用提醒开关并显示行内修改说明，普通事项修改仍可保存；未来截止时间小于默认提前量时，界面会选择仍在未来的较小整分钟提前量。日常管理的模型读取会通过 `notificationTargets` 返回同一列表。模型写入只能选择列表中完全匹配的平台和机器人 id，备忘录与账目写入还需要提供 `remindAt`；未知机器人、无效截止时间或已经过去的一次性提醒时刻会被拒绝，不能保存成表面上存在的提醒。

`TeacherReminderRuntime` 从权威文档投影计时器，而不持久化第二份任务表。它会在启动及每次已接受写入后重新计算，对较长延迟使用分段进程计时器，并通过与浏览器写入相同的操作队列串行确认提醒时刻。重复提醒从截止时间向前对齐。提供方失败或不可用时，会按配置间隔重试到截止时间；只有提供方接受消息后才推进提醒时刻。已完成或已删除待办、已删除备忘录或账目，以及已移除提醒字段会立即从投影中消失。备忘录、账目与日历事项没有完成状态，因此会一直符合条件直至截止时间。

可选 Cordis 服务 `ctx.mobileNotifications` 提供两个操作：`listTargets()` 返回平台、机器人 id、名称与连接状态，`send()` 接受平台、机器人 id 和完整文本。dsh-im Host 组合在九种手机渠道上实现该服务。每个渠道控制器通过已有连接测试使用的最近私聊目标发送；凭据与该目标始终只留在渠道内部。机器人离线或没有记住的私聊会话时会拒绝发送，教师工作台随后可以重试。

通用 `dsh-plugin-cron` 调度器继续作为所有权独立的运行时插件，用于模型或浏览器管理的 shell 命令；[内置扩展决策](2026-08-25-bundled-extensions-and-qq-speech.zh.md)则把它纳入每个标准 Web 与 Windows 组合。工作台提醒不会创建镜像 cron 记录：工作台文档是其唯一持久事实源，而 cron 只拥有无关命令的调度与执行历史。两个插件同时挂载时，cron 的浏览器端点会读取 `TeacherWorkbenchService.listScheduledReminders()`，并把不含凭据的行合并到定时任务页与侧边栏。这些行只读，展示下次提醒时刻与所选机器人名称，执行和管理仍只由工作台负责。

侧边栏通过 `sidebar.primary.section` 在 New Session 与工作区浏览器之间投影通用 cron 任务。其展开区列出已启用或进程内状态为正在执行的任务；空闲且已停用的任务只保留在管理页中。当前会话发生活动后会刷新，因此 Agent 创建工作台提醒时，其工具结果落地就会更新数量；定期刷新仍作为外部变更的兜底。点击收起轨道上的入口会同时展开侧边栏和任务区，点击任一任务行会打开管理页。

## 考虑过的替代方案

**为每份提醒创建一条 cron 记录。** 把事项名称、截止时间、完成状态、机器人选择和修改同步到第二个持久存储，会引入跨插件事务与过期任务恢复问题，还会迫使 shell 命令充当内部通知协议。从单一所有者派生计时器可以避免这些问题。

**在每个事项中保存 webhook URL、令牌或会话 id。** 这会通过工作台文档、浏览器 Remote、备份和面向模型的读取暴露密钥或私有路由数据。不透明机器人选择与仅 Host 可见的通知服务会把这些值留在 dsh-im 内部。

**只在工作台页面打开时发送。** 浏览器计时器无法跨导航、休眠、重启或另一台设备关闭页面继续运行。Host 计时器从持久状态派生，不要求浏览器保持挂载。

**为每个平台实现工作台专用适配器。** 平台字段与生命周期规则会散布到工作台 schema 和界面中。一个小型服务让 dsh-im 继续拥有渠道，也允许其他提供方实现相同操作。

## 结果

- 已配置提醒可跨 Host 重启保留，并跟随所属事项的截止时间修改、待办完成、删除和显式移除提醒，不需要第二次清理事务。
- 每个平台可选择多个机器人，但发送要求所选机器人此前观察过一个私聊会话；界面不开放群组目标或任意收件人输入。
- Host 停机不会补发截止时间已经过去的提醒。截止前提供方不可用时，某个时刻可能延迟发送，随后恢复按截止时间对齐的序列。
- 工作台状态保存机器人显示名称，以便离线编辑；发送使用不透明 id，因此机器人改名不会改变提醒目标。
- 通用 cron 任务以自身权限执行可信 shell 命令并保存历史。其浏览器列表可以显示工作台的只读投影，但 cron 不执行或修改这些提醒，也不会收到 IM 凭据。
- cron Host 通过工具和 HTTP 摘要投影临时的执行中状态。侧边栏会定期刷新已展开的任务区，因此很短的执行可能在两次刷新之间完成，而不显示执行中标记。

## 测试

Host 测试固定截止时间对齐、提供方发送、精确持久确认、确认后的抑制、待办、备忘录、账目与日历提醒投影、模型可见的目标发现、提醒的精确保存，以及对虚构机器人 id 的拒绝。控制器测试固定待办、备忘录与账目的本地截止时间到规范 UTC 的转换，以及修改截止时间但未提供替代提醒字段时移除提醒。组件测试固定单位换算、可编辑空草稿、重复频率范围、多个机器人之间的选择、备忘录与账目提醒配置、过期截止时间说明、普通编辑仍可保存，以及临近截止时间采用有效的较短提前量。dsh-im 测试固定不含凭据的目标投影、精确渠道路由、输入拒绝，以及共享令牌与飞书控制器系列的自定义消息发送。侧边栏测试固定主功能区 seat 与轨道展开回调；cron 集成测试固定任务执行期间的执行中状态发布、执行结束后的清理和只读工作台行。
