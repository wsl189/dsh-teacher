# Agent Note: Question Segmentation Workbench

Status: implemented

English | [中文](2026-08-19-question-segmentation-workbench.zh.md)

> Extends [Durable Teacher Workbench](2026-08-17-durable-teacher-workbench.md) and [Reusable Document Extraction](2026-08-18-reusable-document-extraction.md). Their storage and OCR ownership remain current; this decision adds structured layout extraction and a seventh workbench module.

## Problem

Teachers need to turn a PDF examination paper into durable per-question images, review those images, reuse them in printable material, and distribute independent copies to roster students. The reference segmentation application already demonstrates this workflow, but it is a standalone system with its own filesystem assumptions and also includes wrong-question analysis, question search, and an LLM second-pass filter that are outside the requested dsh module.

The existing shared OCR capability returns reading-order Markdown. Markdown is sufficient for conversation and calendar intake, but it cannot reliably map a recognized question marker back to source-page pixels. The version-4 teacher-workbench document also has no identities or relationships for paper batches and student copies, while storing large base64 images inside that whole-document compare-and-set state would make every unrelated edit rewrite the entire media library.

## Decision

[`@deepseek-ai/dsh-ocr`](../../../../packages/ocr/ocr) adds provider-neutral structured-layout types and the Typert `ocr.layout` Remote. A request carries the ordinary document metadata and bytes plus an optional inclusive, zero-based page range. A successful result contains ordered pages with source indices and dimensions; every normalized element contains a content family, reading-order text, and `[left, top, right, bottom]` bounding box in that page's coordinate system. Every registered provider implements both Markdown and layout extraction, so provider selection and stable error handling remain owned by one runtime.

[`@deepseek-ai/dsh-ocr-mineru`](../../../../packages/ocr/ocr-mineru) implements the new path by requesting `return_middle_json=true`, disabling unnecessary returned artifacts, and forwarding the range as `start_page_id` and `end_page_id`. It validates the complete response, parses `pdf_info`, maps range-relative `page_idx` values back to source-document indices, retains `page_size`, and normalizes usable line, span, and non-text block geometry without exposing MinerU's vendor JSON. The existing endpoint, backend, hybrid effort, language, timeout, upload limit, and response limit continue to come from the ordinary `ocr-mineru` DSH settings namespace.

[`@deepseek-ai/dsh-client-ui-teacher-workbench`](../../../../packages/client/ui-teacher-workbench) adds Question Cutting to its sidebar disclosure and main surface. Its module surface ports the reference application's top bar, current-year/class hierarchy, layered question-library and student drawers, page-range top sheet, image editor, and class-output flow. The class hierarchy reads only classes owned by the roster catalog, so normal and grade-timetable classes cannot enter this workflow. The port maps all application chrome to DSH design tokens so both light and dark appearances remain coherent; only document pixels keep an intentional white canvas. The former middle wrong-question-analysis and image-search workspace is deliberately absent. Double-clicking a class opens its student drawer. Student and folder rows collect clicks for 260 milliseconds: one click opens that row's images, two clicks expand or collapse its children, and three clicks open creation of a durable child folder. The browser accepts blank/all or comma-separated page syntax such as `1-5,8`, sends the selected PDF and enclosing page range to `ocr.layout`, chooses a monotonic sequence of top-level Arabic question markers near a common left margin, and turns each marker-to-next-marker interval into one or more page regions while retaining only explicitly selected pages. PDF.js rasterizes those regions from the original browser-held PDF at the configured scale, multi-page regions are vertically joined, and the batch is persisted automatically. The durable library supports preview, selection, rectangular erasure, rotation, Save As, overwrite, deletion, and per-student or nested-folder assignment. Toolbox Office actions open a browser directory picker, naturally sort selected images, generate one file named after the directory, and show Save or Retry. The class drawer exposes Word and PowerPoint separately: Word retains per-student title/name/date rows and bulk controls, PowerPoint generates immediately, and both return one independent artifact per eligible student for directory-picker saving.

[`@deepseek-ai/dsh-host-teacher-workbench`](../../../../packages/host/teacher-workbench) owns media persistence and document generation. Version 6 contains paper-batch, nested student-folder, and assignment metadata in the revisioned domain document and requires their students to belong to roster classes, while PNG, JPEG, and WebP bytes live below configured filesystem roots. The folder graph rejects unknown owners, cross-student parents, cycles, and duplicate sibling names. Batch writes use generated opaque ids, path-containment checks, decoded byte limits, temporary sibling directories, and atomic rename. Assignments are independent copies below sanitized academic-year, combined grade/class, student, and selected nested-folder directory names. Folder deletion cascades through descendants and assigned copies; class and student removal also removes dependent folders and assignments. Dedicated Remotes read or replace one validated image, save or delete a batch, assign selected images, generate from stored targets, generate directly from ephemeral directory uploads, and return independent per-student Word or PowerPoint artifacts with a skipped list. Word uses A4 with two-centimetre margins, optional centered 16-point bold title, optional right-aligned 9-point name/date metadata, and centered image paragraphs. PowerPoint uses 13.333-by-7.5-inch slides, one non-upscaled image per slide, and the reference 0.5-centimetre left and 1-centimetre top/right margins without added captions.

The `ui-teacher-workbench` settings namespace adds the current academic year, PDF render scale, and crop padding. `TeacherClass` optionally retains an academic-year directory so the reference multi-year hierarchy is durable; documents written before this field fall back to the configured current year. The Host registers a `teacher-workbench` settings section for batch root, student root, per-image bytes, and per-batch bytes; [`@deepseek-ai/dsh-client-ui-settings-plugins`](../../../../packages/client/ui-settings-plugins) exposes those fields in the ordinary plugin-configuration page. The Web composition defaults storage to `~/.dsh/teacher-workbench/segments` and `~/.dsh/teacher-workbench/students`. The feature intentionally contains no question search, wrong-question analysis, or LLM second-pass filter, and it adds no model-visible prompt, tool, or Session event.

## Alternatives considered

**Run the complete reference application unchanged inside dsh.** This would retain three explicitly excluded workflows and create a second settings store, persistence model, and access policy. The selected implementation ports its visible shell and operating flow as a native dsh module while keeping dsh-owned settings and persistence.

**Infer crop coordinates from Markdown.** Reading-order text does not preserve page dimensions or reliable source positions. String offsets cannot safely determine PDF pixel boundaries, particularly across pages or around figures and equations.

**Upload the PDF to a second segmentation service.** MinerU already receives the selected file and can return its structured middle representation. A second service would duplicate endpoint configuration, limits, transport, and failure behavior without adding an independent product requirement.

**Store image bytes inside the revisioned JSON document.** Every task, timetable, or roster mutation would then rewrite the complete question library, and domain snapshots would expand far beyond their relational metadata. Filesystem media plus durable ids keeps comparison and relationship validation small.

**Use an LLM to repair or rank detected boundaries.** That would add latency, nondeterminism, provider cost, and model-visible paper content. The requested scope excludes the second-pass filter, so uncertain layouts surface a deterministic failure with an explicit retry path instead.

## Consequences

- The installed MinerU plugin serves both Markdown Consumers and coordinate Consumers; the question module needs no separate OCR endpoint or vendor client.
- Question crops retain the visual quality of the original PDF render instead of embedding MinerU preview images, while recognition and crop scale remain independently configurable.
- Saved batch images and student copies survive browser reloads and use readable student directories, but operators must include both configured roots alongside the workbench domain document in backups.
- Click aggregation preserves the reference application's single-, double-, and triple-click gestures, but opening a row waits 260 milliseconds so the component can distinguish the intended operation.
- Deterministic detection favors inspectable behavior over guesses. Papers without a clean increasing Arabic top-level number sequence may produce no regions or coarse regions and require source cleanup or a different page selection.
- JSON base64 transport and synchronous MinerU parsing keep complete documents or images in memory. Configured limits bound accepted input, but streaming, resumable upload, progress, and browser cancellation remain deferred.

## Testing

OCR tests cover provider dispatch, the new Remote, page ranges, `middle_json` parsing, element normalization, malformed ranges, and invalid responses. Client tests cover marker-chain selection, exact comma/range page syntax, page-boundary regions, PDF crop orchestration, the reference top bar and roster-only hierarchy, single-, double-, and triple-click behavior, nested-folder creation and deletion, class/student/question-library drawer interactions, directory-based Toolbox generation, per-student Word controls, immediate class PowerPoint generation, module wiring, settings, and existing workbench projections. Host tests cover version-6 schema relationships, atomic batch persistence, nested assignment paths, image reads and replacement, student-copy isolation, cascade deletion, ephemeral upload generation, Word page XML, PowerPoint slide geometry, independent per-student artifacts, validation failures, and restart recovery. Contract typechecking, focused Vitest suites, Oxlint, Cordis configuration verification, generated Remote artifacts, composed Web build, rendered DOCX/PPTX inspection, and slide-overflow checks guard the integration boundary.
