# Agent Note: 教师工作台日常账本

Status: implemented

[English](2026-08-20-teacher-workbench-ledger.md) | 中文

## 问题

日常管理已有待办、备忘录与日历存储，但缺少记录保险保费、水电费等重复家庭支出的位置。复用备忘录会丢失分类归属、精确金额与复核这些支出所需的发生时间。

## 决策

版本 7 的 `teacher_workbench` 文档分别持有 `ledgerCategories` 与 `ledgerEntries` 集合。每条账目引用一个分类，存储教师填写的说明、必填的本地 `YYYY-MM-DDTHH:mm` 值，以及以整数分表示的非负人民币金额。Host schema 会拒绝经过 NFKC 与大小写归一化后重名的分类、重复标识、孤立账目、无效时间，以及非整数或负数金额。

日常管理将备忘录、账本与日历呈现为三张等宽卡片。选择紧凑账本卡片会打开占满板块的分类视图。用户可新增和删除分类，在每个分类中通过手动输入或浏览器原生语音输入新建账目，设置金额与发生时间，并编辑或删除已有账目。删除分类会在一次比较后写入文档变更中删除该分类及其拥有的全部账目。

新文档包含可删除的“保险保费”“水电燃气”和“其他账目”分类。根据仓库的预发布格式策略，存储 domain 版本检查会拒绝已有的版本 6 媒介。

## 考虑过的替代方案

**把账目存为备忘录。** 这种方案可复用一种数据类型，但必须从文本中解析分类、金额与时间，无法提供精确汇总和引用校验。

**存储十进制金额。** JavaScript 浮点值可能在重复编辑与汇总时产生舍入差异。整数分可保持持久化值与汇总计算精确一致。

**只在浏览器状态中保存分类。** 分类删除与跨窗口编辑不会参与工作台修订，持久化账目也可能失去可见的所有者。

## 后果

账本编辑使用与其他工作台数据相同的整份文档比较后写入路径，因此跨窗口冲突仍会明确呈现，分类删除与账目移除保持原子性。界面只呈现人民币，金额不能为负数，每条账目都必须设置本地发生时间。schema 变更把 domain 格式从 6 增加到 7，并按预发布策略拒绝旧存储而不迁移。

聚焦的 Host、控制器与组件测试固定 schema 校验、不可变发布、分类级联删除、整数分转换、紧凑卡片展开、语音录入、时间选择与账目编辑。无密钥 Web 快照通过交付应用新增分类和定时账目，检查 Host 持久状态，并验证重载后的紧凑汇总。
