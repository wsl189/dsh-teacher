# Agent Note: SQLite 点例收集

Status: implemented

[English](2026-09-08-example-collection.md) | 中文

## 问题

教师需要收集独立题目与解析及其原件、识别后的 Word 文本、可复用标签和描述，并在无需浏览试题切割层级的情况下找到它们。仅存于浏览器的文件会在刷新后消失，迟到的 OCR 结果也可能覆盖替换后的原件或恢复已删除的题目。

## 决策

教师工作台 Host 拥有独立的 `teacher_example_collection` 存储域。Web bundle 通过既有 SQLite 后端将其路由到 Harness 主目录下的 `teacher-workbench/examples.sqlite`。域版本 2 要求每道题包含独立的 `question` 和 `explanation` 文档记录。每份文档拥有源文件标识、字节、OCR 状态及 Word 修订号。请求显式选择一份文档；替换仅修改该文档，删除则在同一条记录提交中移除两组文件。可复用标签有独立目录。创建预设仅修改该目录，下拉选项行仅修改当前题目，因此添加共用预设不会将其分配给任何题目。预设行以最右侧的勾选图标表示选中。标签颜色按名称确定，在编辑区与搜索结果中保持一致。编辑区标签在悬停或键盘聚焦时显示取消按钮，触屏设备始终显示；取消时保留共用预设。保存期间通过 `aria-disabled` 阻止再次切换，同时保留焦点，因此选择标签不会收起下拉框。外部点击、焦点移出选择框及 Escape 可收起。目录读取不包含文件字节，预览仅请求所选文件。

Host 串行执行元数据修改，并在 OCR 前保存原件。识别使用既有 OCR 服务并遵循 Host 生命周期取消，通过独立的工具模型子 agent 对照原件校对返回文本，从通过验证的结果生成 DOCX，仅在源文件标识仍匹配时提交。识别按题目标识和文档类型去重，因此两份文档可并发识别。完成时保留当前元数据及另一份文档、拒绝截断输出，并在失败后保留原件及已有 Word。浏览器在目录和模块导航期间保留待保存的描述草稿，仅在对应保存成功后移除草稿。

重命名不改变数字目录顺序。搜索组合已保存的标签和文字描述；已存归一化笔迹只读展示，不会被识别成可搜索文字。描述和搜索共用既有语音 Consumer。聚焦的输入框与对应麦克风按钮共用录音器，长按空格 500 毫秒启动，短按在当前选区插入一个空格。输入法选词、带修饰键的快捷键、其他输入框和未聚焦的对话输入区不会接管该手势。松键、失焦、页面隐藏和卸载会结束或取消长按；权限在松键后才返回时也不会留下持续录音。描述编辑在 500 毫秒后、失焦或切换目录时保存，保留的失败草稿通过重试重新提交。搜索转写仅替换查询，等待提交搜索。采集失败通知区分权限拒绝、找不到输入设备、设备启动失败及不支持录音要求。目录、搜索和批注操作不增加模型可见输入或会话事件。校对输入、图片附件与结果使用普通子 agent 会话日志记录。

校对后的 TeX 括号分隔符会在代码、链接、插图及既有公式之外规范化，完整规范化结果仍需通过文本长度限制。Markdown 公式解析识别由美元符号分隔的完整表达式。KaTeX 提供 MathML，mathml2omml 将其转换为原生 Office 公式，保留 Word 中的可编辑性。相同 MathML 存于 DOCX 自定义属性 `dsh.example.mathml`；浏览器预览净化后渲染它，因为 docx-preview 会遗漏重音符号及组合上下标。此属性仅属于收集功能生成的文档，其 Word 字节不作为导入或编辑通道。新生成文件、已存文件读取与导出共用 DOCX 字体规范化，因此浏览器 CSS 不会掩盖下载文件的格式差异。正文使用 12 磅宋体/Times New Roman，公式使用 Cambria Math；移除 OCR 标题强调，同时保留表达数学含义的强调格式。转换器产生的无效正体样式会修正为 OMML 普通样式，公式文本属性遵循 schema 顺序。公式中的粗体小写拉丁字母和希腊字母在两种表示中统一使用粗斜体；仅从已存 MathML 重建受影响的公式，替换前要求公式数量一致且文本不变。OMML 粗斜体文本块不启用普通文本模式，使 Word 使用数学字形；浏览器预览应用相应字重。字体规范化还会重建支持的纯文本公式，仅在字节变化时提交派生产物，无需 OCR，也不修改题目元数据。不支持的 TeX 保持可见，供后续修正。

点例收集显式请求 OCR 图片资源。MinerU 返回有界的图片 data URL，Markdown 目标仅从这些返回字节解析。Word 写入器将插图解码为保持比例的嵌入 PNG。读取或导出含未解析引用的已有文件前，会从已存原件补图；补回的资源仅替换匹配的图片标记，保留原文和原生公式。仅补图时跳过校对以保留已存文本；完整重新校对会等待正在进行的补图，再启动自己的 OCR 与子 agent。识别流程负责并发补图去重，并在原件替换或题目删除后拒绝迟到提交。补图失败会保留旧 Word 供重试。编译器通过 docx 重新注册每张图片，在保留媒体字节与尺寸的同时分配输出引用；仅复制绘图 XML 会留下断开的引用或引用冲突。

搜索选择仅存于浏览器，限于可见且已生成题目 Word 的结果。导出按请求顺序取得已提交记录，并逐题放置解析或在新页集中附上解析。导出仅包含题目与解析原文，不添加标题、编号、标签或描述。未上传的解析会省略；记录缺失或已上传文档尚未完成识别时，整次操作失败。编译器接受收集功能生成的段落，裁去首尾空白，通过既有 docx 适配器导入 XML 和原生公式，并按同一顺序合并预览 MathML。相邻题目块与集中排列的相邻解析之间保留两个单倍行距空白段落；解析附录另起一页且不增加页首空行。完成必要的插图恢复和题头识别后，完整且已完成判定的文档合并不写入存储，也不调用模型或 OCR。

每个校对子 agent 都属于工作台自有的隐藏父 agent，独立于当前选中的对话。其目标是准确转写并匹配原件，绝不改写、解题或修正题目与解析原件中印出的错误。它接收完整 MinerU Markdown 与全部原始页面，使用支持图片输入的工具模型路由，并返回结构化最终 Markdown。配置的完整文本、页数、附件、栅格与时长限制会拒绝不完整处理；插图引用被改变时拒绝替换。

另一个全新的 spawn 子 agent 根据全部原始页面与精确的 Word 文本投影识别题头元数据，不接收父对话，只返回复制的开头前缀。原生公式以带标记的原子形式提供；Host 在删除节点前验证前缀一致性、公式边界、实质正文保留及图片保留，并从预览 MathML 中移除题头公式对应的节点。文档在 `dsh.example.headingReviewed` 中记录完成状态，包括无题头判定。首次读取或导出未标记的已有文件时执行识别，无需 OCR；后续预览、下载及两种导出形式复用处理后的字节。既有逐文档识别流程负责去重、等待取消结束，并在提交前检查原件标识和 Word 修订号。失败时保留已存 Word 字节与元数据。

教材排版使用明确的西文字体文本段，避免 Word 将相邻拉丁字母分配到中文字体。正文变量为斜体，段内明确声明的小写向量为粗斜体，数字、函数名与选项编号为正体。子 agent 保留原图的段落分组、选项行与插图顺序，并将数学符号输出为 TeX。Word 原生制表位将完整 A–D 选项序列与题干分开对齐；选项内部使用空格，使编号紧邻公式。选项前的独立答题括号并入前一段题干，正文使用 1.25 倍行距。插图位于所属来源的全部文字和选项之后，以专用图片段落居中。合并前按来源归组导入和补回的插图，图片段落样式在后续规范化时保留其位置。已存公式及媒体字节保持完整。浏览器将这些制表位投影为响应式列，因为固定页面坐标无法适应所有预览宽度。共用规范化保留来源的非空白字符，重复执行不产生变化，且无需 OCR。Markdown 空行不生成空段落，题间两行空白由导出编译器负责。Word 测试覆盖文本段样式、原文、选项排列、编译时的原生公式及幂等性；Client 与组装 Web 测试覆盖选项单元和预览资源释放。

项目所有者授权按 LGPL-3.0-or-later 发行 mathml2omml 0.5.0。转换器保持为独立的 Node 模块，用户可以替换接口兼容的修改版，无需应用签名密钥。[发行资料包](../../../../packages/host/teacher-workbench/third-party/mathml2omml/NOTICE.txt)随附完整 GPL 和 LGPL 文本、未修改的上游源码与构建配置、内含的 entities 源码、依赖许可声明以及重建和替换说明。许可声明生成器固定已审核的包标识、版本、许可、源码归档和许可文件；桌面安装包检查会拒绝缺失运行库或资料包的产物。这项限定版本的决定不授权无关的 copyleft 依赖，也不将 LGPL 归为宽松许可。

## 考虑过的替代方案

**将文件嵌入版本化工作台单例。** 每次班级、课程表或日常任务修改都会重新传输和写入无关题目文件。收集功能没有需要共同提交的名册或课程表引用。[工作台决策](2026-08-17-durable-teacher-workbench.zh.md) 仍然定义相互关联的教学记录。

**用正则表达式识别题头或重写整道题。** 题头格式多样，日期和括号内容也可能是实质条件。视觉识别只选择精确的开头前缀，Host 保留正文，不要求题头子 agent 重新输出正文。

**将原件和生成文件存于 SQLite 之外。** 文件删除和元数据删除需要跨介质清理及恢复。单条记录通过既有后端，原子地保存用户要求的原件、生成文档和元数据。

**仅保存识别文本，每次预览重新生成 Word。** 预览和下载无法读取同一份已保存产物，OCR 成功后仍然依赖后续转换可用性。持久化 DOCX 使重启后的预览和下载保持一致。

**将插图保留为外部引用。** MinerU 相对路径不是浏览器路由，下载的 Word 也不能依赖解析器临时文件。嵌入媒体使插图与生成文档归属同一 SQLite 记录及删除操作。

**将公式渲染为图片。** 图片无法通过 Word 原生公式编辑器修改。[KaTeX](https://katex.org/docs/options) 与 [mathml2omml](https://github.com/fiduswriter/mathml2omml) 库负责数学解析和转换；收集功能不自行维护 TeX 语法或 Office 公式转换器。

## 后果

题目在浏览器和 Host 重启后仍然存在，迟到的 OCR 不能恢复已删除数据。手写内容按原样保存，不承诺手写识别。Word 公式保持可编辑，不支持的 TeX 和 Markdown 表格仍为文本。存储域实现在 Host 内存中保留记录，因此即使浏览器目录读取不包含文件，大型收集库仍可能占用较多内存。

## 测试

SQLite 测试覆盖重启恢复、数字目录创建、原件/Word 删除、并发元数据修改、题目与解析同时识别、任一 OCR 期间替换原件、OCR 不可用或截断、无效文件，以及关闭存储前的取消。Word 测试验证原生向量箭头、分数、幂、独立公式、统一的正文与公式字体、数学强调格式保留，以及不重复写入或 OCR 的已存文本或原生公式规范化。Client 测试覆盖草稿保留、独立后台识别、乱序响应、公式匹配及已存 MathML 的净化。组装后的 Web 场景通过真实 Remote 和 MinerU 适配器向确定性的外部 provider fixture 上传图片和 PDF、渲染两组文档及其真实 DOCX 公式、检查题目搜索抽屉、只读渲染已存笔迹、刷新，导出选中题目的两种排列方式，并删除目录。插图测试验证请求返回的 provider 字节、恢复失败时保留旧文件、并发读取、期间替换原件或删除题目、仅含图片的段落，以及跨文档媒体引用。Web 场景渲染两组插图预览并下载含嵌入 PNG 的导出文件。导出测试覆盖顺序、两行留白、缺失解析、未完成内容、原生公式保留，以及不添加标题、编号、标签或描述和完整已存文档的离线导出。校对测试覆盖原图与 PDF 每页、所选模型路由、缺失图片能力、完整结果限制、截止时间、销毁、无效输出、插图引用变化及校对期间替换原件。组装场景记录实际子 agent 输入与结果工具 schema，执行自动和显式校对，并验证 Word 中修正的点名称与比例冒号。语音测试覆盖采集失败、重试、停止编辑后持久化、短按空格、光标位置、输入法选词、输入目标路由、等待权限时松键、失焦和销毁；浏览器合成音源通过外部 ASR fixture 验证原生录音、WAV 转换、Host speech Remote 及描述持久化。独立的浏览器场景验证搜索按钮及长按空格通过同一 provider 路由转写，且不修改描述。MinerU 与模型准确度及实体麦克风硬件仍由部署环境验证。
