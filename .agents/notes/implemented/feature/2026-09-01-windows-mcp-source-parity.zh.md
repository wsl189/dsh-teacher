# Agent Note：Windows-MCP 源码对齐与工具关联采样

状态：已实现

[English](2026-09-01-windows-mcp-source-parity.md) | 中文

## 问题

Windows-MCP 版本号相同并不能证明代码一致。用户提供的 0.8.5 源码含有 PyPI wheel 中缺失的区域截图和桌面修复。其 Scrape 工具还会请求客户端模型补全；不支持采样的客户端会返回原始网页，而非所请求的提炼结果。因此，发布相同的二十个名称并不能证明功能对齐。

共享 MCP 进程无法推断传入的采样请求属于哪个 DSH 会话。给它任意模型路由，或使用最近活跃的会话，会混淆调用方的权限、历史、取消和费用归属。

## 决策

构建在 `third-party/windows-mcp` 中固定用户提供包的完整 Python 树与二十项工具签名。既有哈希固定 wheel 闭包提供依赖和 distribution 元数据；已审阅源码替换 wheel 的实现。校验涵盖压缩包成员、源码与签名哈希、每项补丁摘要，以及应用补丁前后的签名。这样可保留区域参数、UI Automation 修复、滑块支持和隐藏子进程行为，无需维护第二套桌面实现。Windows 客户端超时允许上游 WaitFor 的最长等待。

上游源码之外保留两项已审阅改动：既有的 TheFuzz 替换，以及 Scrape 采样关联补丁。后者把 `tools/call` 元数据中每次调用的私有令牌原样放入 `sampling/createMessage` 元数据。仅靠 SDK 的 `relatedRequestId` 传输选项无法在 stdio 协议中标识父请求。补丁保留查询聚焦、DOM 模式、显式关闭采样和原始内容回退。

通用 MCP 采样默认关闭，部署必须提供精确的工具允许列表及输入／输出限制才能启用。Windows-MCP 只为已经要求[会话级 Full access](2026-09-01-windows-mcp-full-access.zh.md)的 Scrape 启用它。正在执行的工具可使用调用方已记录的提供方／模型路由完成一次补全。请求只含所提供的文本，不包含对话历史或工具；服务器的模型偏好不能选择其他路由。主动发起、重复、过期和外来令牌都会在模型分发前被拒绝。

调用方会话在流式输出前记录准备后的输入，并在结束后记录终止输出，事件名为 `mcp/sampling-request` 和 `mcp/sampling-response`。即使响应乱序完成，回放仍保留请求顺序。工具取消、超时、完成以及连接关闭都会停止嵌套采样；重连会等待模型完全结束。由于 SDK 会在请求成功后保留 abort 监听器，工具回复后会断开传输取消的转发。私有令牌绝不进入持久化日志。

[内置运行时归属](2026-08-31-bundled-windows-mcp.zh.md)、[默认启用](2026-09-01-windows-mcp-default-on.zh.md)、[MCP 桥接](2026-07-07-mcp-client-plugin.zh.md)与[重连](2026-08-06-mcp-client-auto-reconnect.zh.md)保留各自独立的理由。源码身份与辅助模型访问不替代这些决策。安装后的功能仍是私有 stdio 子进程；能力对齐不会开放上游 HTTP／SSE／OAuth 监听器、授予管理员权限，也不会让纯文本模型接收图片。

## 考虑过的替代方案

**只固定发布版本，或复制少数有改动的工具。** 版本号不能标识用户提供的实现，选择性复制也可能遗漏共享 UI Automation 或子进程修复。完整源码快照使覆盖范围和后续更新都可审计。

**为所有 MCP 服务器开放不受限采样。** 传入 stdio 请求没有可信的 DSH 会话身份。显式允许列表和单次使用的关联令牌把辅助调用限制在已获准的工具调用中。

**使用单独的模型端点，或注入 agent 的完整对话。** 两者都会引入与网页提取无关的凭据、路由、信息披露和回放语义。既有 LLM 服务只在调用方路由上接收受限且隔离的文本请求。

## 结果

- 更新源码时，必须一起审阅压缩包、工具签名、依赖闭包、补丁和 Windows 打包冒烟。TheFuzz 仍是有意保留的本地实现差异。
- Scrape 每次调用最多可额外消耗一次有上限的模型补全。模型拒绝、采样不可用或提取失败时，保留上游原始网页回退；超大请求会在向提供方分发前被拒绝。
- 源码测试校验完整固定树和拒绝路径。真实 FastMCP 冒烟覆盖关联、查询聚焦、DOM、关闭采样与失败回退；Windows 打包另行检查原生运行时与全部工具参数。
- 无密钥 TypeScript SDK 回放通过发行 SDK profile 覆盖区域、持久图片与已记录的提取。Python SDK 期望输出固定采样事件与提供方字节。单元测试覆盖调用方隔离、限制、取消、过期令牌和等待模型结束后重连。在线提供方效果与原生桌面操作分别需要凭据和 Windows；Linux 回放不能证明两者。
