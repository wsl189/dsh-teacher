# Agent Note：工具模型仅选择视觉模型

Status: implemented

[English](2026-09-09-vision-tool-model-selection.md) | 中文

## 问题

工具模型选择框提供了所有已配置的语言模型，但后台任务需要查看图片。模型名称不能证明图片支持能力，而浏览器目录遗漏了适配器解析后的输入能力。

## 决策

Session Controller 将精确模型解析结果中的可选 `inputModalities` 投影到 `ModelCatalogModel`。未知能力保持缺省。Models 设置中的工具模型选择框及其保存操作仅接受可用的已配置路由，且模型的输入能力必须明确包含 `image`。空分组不显示；没有候选项时，选择框提示用户到服务接入中添加视觉模型。过期选择显示重新选择提示，不改写设置。

[工具模型分配决策](2026-08-20-tool-model-timetable-normalization.zh.md)仍拥有成对存储与后台任务解析。默认对话保留完整的已配置目录。提供方编辑器仍是按模型声明图片输入能力的唯一入口；不增加工具专用的能力开关，也不根据名称推断。

## 考虑过的替代方案

- 匹配 `vision` 或 `VL` 等名称会排除有效的自定义 id，也会接纳误导性名称。
- 将缺失能力视为支持图片，会接纳不能接收图片的模型。
- 对所有使用场景选择框统一筛选，会不必要地移除普通对话的文本模型。

## 后果

设置中只能将明确支持图片输入的模型选为工具模型。已有注册表元数据与保存的连接状态决定可选资格。Host 和组件测试覆盖未知能力、纯文本能力、缺失凭据、未配置路由和过期选择。组合浏览器场景覆盖已保存的视觉模型选择，并保留普通对话中的文本模型选项。
