# Agent Note: 模型容量选项与请求预算

Status: implemented

[English](2026-09-09-model-capacity-selects.md) | 中文

## 问题

自由输入的上下文与输出字段要求用户手工填写 token 数，也可能在模型草稿中留下未完成的文本。简短连通性检查使用自己的小额度上限，因此检查成功不能证明配置的输出上限已经传到供应商。

## 决策

原生 DeepSeek 与通用模型编辑器共用一个容量选择器。上下文选项覆盖 32K 至 1M，输出选项覆盖 8K 至 64K。计数沿用编辑器的十进制 K/M 约定。选择模型默认值会移除覆盖。目录或已保存配置中超出档位的计数保留为明确的当前值选项；打开模型行或重命名模型不会对其取整。

上下文仍是供历史压缩使用的适配器元数据。输出仍是每个模型的请求默认值，显式调用预算优先。选择更大的上下文不会提高上游容量，剩余上下文的限制也可能缩小实际发送的输出上限。[适配器持有默认值的决策](../architecture/2026-07-30-adapter-owned-max-token-defaults.zh.md)继续持有这些语义。

这会修改[提供方声明决策](../architecture/2026-08-04-declaring-a-provider-from-the-models-page.zh.md)中的容量控件；模型发现、字段保留和设置归属仍由原文持有。

## 考虑过的替代方案

- 把现有数值取整到最近档位，会在无关编辑中改变供应商元数据。
- 移除默认值选项，会把可选覆盖变为必填配置。
- 把 16 token 的连通性探测当作输出预算验证，会掩盖不受支持的配置上限。

## 影响

浏览器覆盖通过正式组合保存并重新打开选择器。协议用例为每个预设保存所有可选预算，并使用本地上游响应检查真实序列化的 HTTP 请求。可选的真实接口用例从明确指定的 harness home 获取凭据，仅写入隔离的测试目录，并使用所选输出上限生成简短回复。缺少凭据时跳过用例，上游拒绝时用例失败。短请求验证请求接受情况与本地上下文解析，不验证填满整个上下文窗口或生成最大输出长度的能力。
