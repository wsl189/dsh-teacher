# Agent Note: Durable Teacher Workbench

Status: implemented

English | [中文](2026-08-17-durable-teacher-workbench.zh.md)

## Problem

Teachers need the reference desktop workbench's daily-management board, a linked course timetable, and four teaching workflows inside the dsh Web application. Daily management comprises tasks with deadlines and completion state, quick notes, time and weather, and a lunar and statutory-holiday calendar with date-specific items. The timetable must show today, one week, one grade, and morning or evening study while keeping the ordinary timetable linked and preventing Grade classes from entering unrelated modules. The other teaching workflows comprise lesson resources, class rosters, score analysis, and teaching records. Copying the reference application wholesale would also copy its browser storage, standalone configuration, and page structure, leaving the data outside dsh persistence and the controls outside the composed Web interface.

The workflows share one revisioned document, while class ownership differs by workflow: rosters, exams, and Question Cutting use roster classes; Today, Week, and Study use normal timetable classes; Grade uses its own classes. Their references must remain valid across edits, and concurrent browser windows must not silently overwrite each other. Weather and speech recognition also need deployment-varying parameters without creating a second configuration file.

## Decision

`@deepseek-ai/dsh-host-teacher-workbench` owns one schema-validated `teacher_workbench` storage-domain document. Version 6 of the document contains daily tasks, quick notes, dated calendar items, normalized weekly timetable entries, and all teaching modules' business data under one monotonic revision. Every class declares roster, normal-timetable, or grade-timetable usage. A timetable entry references a non-roster class, identifies its lesson or study type, weekday, and one-based period, and stores optional times, subject, teacher, and location. The schema rejects cross-usage references, unknown classes, and duplicate class/type/weekday/period slots; class deletion removes its schedule. A task carries one mutually exclusive Today, Important, or Urgent category plus one validated ten-color palette key. The generated `teacherWorkbench` Remote exposes a read and a whole-document compare-and-set write; a stale revision returns the current document so the client can reapply one mutation. The same namespace exposes a non-durable weather lookup that resolves district, county, or city text through a configurable Nominatim-compatible endpoint and requests the forecast from Open-Meteo. The Host validates both responses and returns stable business failures.

`@deepseek-ai/dsh-client-ui-teacher-workbench` contributes one `sidebar.footer.action`, one `shell.overlay` surface, and one `settings.general.item` row. The overlay receives the rendered sidebar and details widths and occupies only the center column above the still-mounted conversation, so selecting a disclosed module keeps the application sidebar available instead of opening a modal or repeating module navigation or a header inside the workbench. The sidebar disclosure exposes Daily Management, Timetable, and the five other teaching modules; its collapsed-rail action opens the active module directly. The workbench watches the runtime session-list selection and closes when the current Session changes or clears, so Session and New Session navigation restore the conversation. Daily Management places a right-aligned time, date, location, and weather summary beside its heading; selecting the summary opens the detailed time and forecast panel, while the calendar can independently occupy the dashboard for its detailed view. Three simultaneously visible cards own the Today, Important, and Urgent lists; creating within a card assigns that category, and task editing can move the row to another card. Important and Urgent rows expose an inline ten-swatch picker, while Today rows omit the marker.

Today, Week, and Morning/Evening Study project entries owned by the normal timetable catalog, while Grade projects entries owned by an independent grade-timetable catalog. Week owns ordinary class selection and timetable mutations. Today is read-only: it follows Week's selected class by default, and its editable teacher filter can instead match the current day's normal entries across every class by normalized teacher name. The filter stays synchronized with the dsh teacher-name setting, and Today displays the teaching class instead of location. Study filters the selected ordinary class by entry type. Class creation is icon-only in every editable view. Week and Study expose icon-only deletion for the selected normal class, while Grade exposes icon-only deletion per class row; each icon retains an accessible label and tooltip. The destructive confirmation names the class and its timetable-entry cascade, and a successful selected-class deletion advances to the next available class. Grade groups only grade-timetable classes with the selected grade, so its recognition and edits cannot populate any other view or teaching module. Timetable class creation accepts the class name and grade without asking for a subject. Course creation has no toolbar action. Empty cells in Week, Grade, and Study open the lesson editor with the cell's class where unambiguous, weekday, period, and study type prefilled; teacher-wide Week cells leave the class open for selection. OCR import is available from the editable Week, Grade, and Study views, uses the shared document extraction Remote, supports images, PDF, DOCX, PPTX, and XLSX, and exposes every recognized class, grade, type, weekday, period, time, subject, teacher, and location for review. The deterministic projection expands merged cells, maps stacked weekday and class headers across repeated table blocks, converts repeated morning and afternoon period numbers into one sequence, reuses configured class names, separates compact subject-teacher cells, and accepts Study tables whose class columns are crossed with weekday rows in separate morning and evening blocks. Grade extraction retains discarded peripheral text so a grade label omitted from the main Markdown can still name ordinal class columns. Rows remain unselected unless the class name ends in `班`. One import replaces occupied timetable slots atomically within its catalog. Only disclosure, open state, active module, timetable filters, panel-expansion state, and OCR review stay browser-local; tasks, notes, calendar items, timetable entries, resources, rosters, scores, templates, and records always pass through the Host service. [Isolate Grade Timetable Classes](../bug-fix/2026-08-20-isolate-grade-timetable-classes.md) owns the catalog split and OCR admission rule.

The client registers the `ui-teacher-workbench` settings namespace for teacher name, school name, default subject, weather location, browser speech-recognition language, score full mark, excellent threshold, and pass threshold. Cross-field validation requires `passScore <= excellentScore <= scoreFullMark`. These parameters use the ordinary dsh settings file and General settings lifecycle rather than a feature-specific configuration file. The Host plugin config selects the geocoding endpoint and bounds its in-memory location cache.

The implementation migrates workflow behavior rather than source presentation or storage. Each voice command requests microphone access before browser speech recognition starts, reports recognition failures through localized notifications, and supplies accepted text to the same task and note editors used for manual input. The browser requests weather through the Host Remote rather than contacting external providers across origins; validated responses are not persisted, and only the selected location text is a dsh setting. The Host caches resolved coordinates and serializes cache misses to the public geocoder's request limit. `chinese-days` supplies lunar dates, solar terms, statutory holidays, and adjusted workdays, while teacher-authored date items remain in the Host document. Rule-based school-calendar and timetable projection consumes MinerU Markdown or HTML tables, while every recognized row remains editable before persistence. Spreadsheet paste accepts tab-separated data and quoted CSV, score rows resolve against durable student identities, template-backed records retain their lifecycle state, and deleting an owner removes dependent data. The feature adds no model-visible input, so it adds no Session event.

## Alternatives considered

**Retain the reference application's Local Storage.** This leaves teaching data tied to one browser profile, bypasses dsh storage configuration, and cannot provide authoritative revision conflicts across windows.

**Put the feature directly inside the sidebar package.** The sidebar would own business state and a large product surface unrelated to its navigation responsibility, while other Web compositions could not add or remove the workbench as one plugin.

**Store each module independently.** Separate writes make class deletion, roster updates, exam references, and template deletion span several commits. The current data volume is small enough that one revisioned document gives simpler atomic relationship updates; independently revisioned tables remain appropriate if school-wide volume or multi-user write contention becomes material.

**Store a separate table for each timetable view.** Copies for Today, Week, and Study make an ordinary timetable edit depend on synchronization and permit contradictory rows after a partial failure. One normalized entry collection remains authoritative, while class usage gives Grade an independent catalog without duplicating the storage model.

**Copy the reference page and its configuration unchanged.** That preserves a standalone application instead of composing with dsh slots, settings, localization, Remote transport, and storage ownership.

**Copy the reference weather and calendar scripts.** The reference weather flow does not validate provider responses or reliably resolve Chinese district names, and maintaining holiday and lunar calculations locally would duplicate a maintained dependency. Validated geocoding plus Open-Meteo forecasting and `chinese-days` keep external data parsing explicit and avoid product-owned calendar calculation code.

## Consequences

- Daily-management and teaching data, including task classifications and color markers, survive reloads and follow the configured dsh storage backend, while ordinary dsh settings own deployment-varying teacher, weather, speech, and score parameters.
- Cross-module edits are atomic and invalid or cross-catalog identities are rejected before persistence; concurrent windows receive explicit revision conflicts instead of last-write-wins loss.
- Week and Morning/Evening Study share ordinary classes, while Grade and roster classes retain independent identities even when their display names match.
- Every accepted mutation currently rewrites one document. Large multi-user deployments may need table-level revisions without changing the six client modules.
- Weather sends configured location text from the Host to the selected geocoder and requires Host access to both that service and Open-Meteo. Speech recognition depends on browser support and microphone permission, and statutory-holiday coverage follows the years published by `chinese-days`. Browser cross-origin and privacy policies do not participate in weather requests; each unavailable capability leaves manual entry and durable workbench data usable.
- The reference application remains a behavior source only. Its visual structure, browser storage, and standalone settings are not runtime dependencies.
