# Agent Note: 自动模型连接验证

Status: implemented

[English](2026-09-09-automatic-model-connection-verification.md) | 中文

## Problem

供应商状态和接入套餐下拉框无法明确指出当前管理的是哪一份凭据与端点。凭据存在不能证明模型请求成功。每次编辑后要求单独测试，容易让连接失败被忽略；逐个验证所有模型又会为相同凭据和端点重复发送付费请求。

## Decision

服务接入将每条已保存的提供方线路展示为独立连接；预设提供供应商和套餐标签。添加目录拥有未配置预设与自定义创建入口。这一展示方式取代[供应商设置决策](../architecture/2026-09-01-supplier-grouped-model-settings.zh.md)中的供应商侧栏；独立配置、凭据、协议、媒体线路和使用场景分配仍遵循该决策的归属。

成功保存后，系统通过 Session Controller 使用一个已配置的对话或视觉模型，自动验证每条独立连接。结果标识连接字段、选定模型 ID 与凭据修订。新增目录模型、修改名称或模型容量会保留结果；端点、协议或密钥变化会使其失效。选定模型仍在目录中时保持稳定；删除后选择另一个。每条连接最多只有一个活动请求，由部署策略限制，并在配置替换或销毁后忽略过期响应。失败保留已保存的配置并提供重试，不继续测试其他模型。仅打开设置不会进行付费检查。

每次检查通过已注册适配器发送不含工具的简短请求，将输入、请求头、原始分片和响应记录到私有诊断会话。成功查询目录或已保存密钥不能替代成功的实际请求。连接已验证不意味着每个模型都经过测试，也不意味着该凭据拥有全部模型的访问权限。生图和语音线路不参与自动验证；仅含媒体模型的连接显示已配置，模型行显示名称与类型，不带验证状态。摘要统一标明测试模型，并从已保存状态派生模型数量和使用场景分配。跳转分配页面不会隐式修改选择。

## Alternatives considered

- 每次保存后手动验证会增加独立的用户必需操作，并让错误未被发现。
- 将目录发现或凭据存在视为成功，无法发现被拒绝的模型请求。
- 独立检查每个模型会为同一连接重复发送付费请求；复用结果而不使凭据变更失效，则可能错误地宣称新密钥有效。
- 自动生成图片或提交录音会增加另一种付费操作，也不能证明用户的实际任务可用。

## Consequences

已配置、验证中、已验证和失败分别表达不同事实。验证会在保存后产生少量模型请求并保留诊断日志。结果仅属于当前页面存储，不构成持久健康保证。单元测试覆盖实际适配器结果、取消、连接结果复用和过期响应；浏览器场景通过组装后的 Host 覆盖已保存连接及自动失败恢复。 [录制的诊断会话](../../../../snapshots/web/model-verification/session.jsonl)固定无工具输入与持久化输出，用于无密钥回放。
