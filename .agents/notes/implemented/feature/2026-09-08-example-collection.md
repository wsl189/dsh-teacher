# Agent Note: SQLite Example Collection

Status: implemented

English | [中文](2026-09-08-example-collection.zh.md)

## Problem

Teachers need to collect individual questions and explanations with their originals, recognized Word text, reusable tags, and descriptions, then find them without navigating the question-cutting hierarchy. Browser-only files disappear on reload, and a delayed OCR result can overwrite a replacement source or resurrect a deleted question.

## Decision

The teacher-workbench Host owns an independent `teacher_example_collection` storage domain. The Web bundle routes it through the existing SQLite backend to `teacher-workbench/examples.sqlite` under the Harness home. Domain version 2 requires separate `question` and `explanation` document records within each question. Each document owns its source identity, bytes, OCR status, and Word revision. Requests explicitly select one document; replacement changes only that document, while deletion removes both pairs in one record commit. Reusable tags have their own catalog. Creating a preset changes only that catalog; dropdown row toggles change only the selected question, so adding a shared preset does not assign it to any question. Preset rows indicate selection with a check and reveal a separate delete action on hover or keyboard focus. Preset deletion changes only the catalog; assigned tags remain on questions. Updates may retain those existing tags but require a current preset for every newly assigned tag. Tag colors derive from the name and remain consistent across the editor and search results. Editor tags expose a removal button on hover or keyboard focus, with persistent visibility on touch devices; removal preserves the shared preset. Pending saves suppress another toggle through `aria-disabled` while retaining focus, so selecting a tag does not dismiss the dropdown. Outside pointers, focus leaving the picker, and Escape dismiss it. Catalog reads omit file bytes, and previews request only their selected file.

An upload is an ordered, nonempty set of fragments from one question or explanation. Multiple files become one PDF before the source commit: PDF pages are copied, complete image pixels are embedded without added margins, and input plus output byte limits apply to the whole operation. Any invalid fragment rejects the batch without clearing the previous Word. Keeping one combined original preserves the existing durable document format and gives OCR one asset namespace, while one proofreading child can resolve continuation across every page. Per-fragment proofreading followed by Word concatenation would lose sentence, formula, and option context at cut edges. The child sees explicit continuation labels and must preserve all substantive source content; heading identification checks paragraph-leading source metadata throughout the document while preserving continuation subparts and steps. Original previews use the bundled PDF.js rasterizer to show all pages in order. Native PDF iframes can remain blank in embedded browsers despite valid source bytes. The preview releases each page canvas and its reader, suppresses late results after replacement or dismissal, and offers retry after render failure; downloads retain the saved PDF bytes.

The Host serializes metadata mutations and saves each source before OCR. Recognition uses the existing OCR service with Host-lifetime cancellation, proofreads the returned text against the original through an independent tool-model child, generates a DOCX from the validated result, and commits only when the source identity still matches. Recognition deduplicates by question identity and document kind, so both documents can run concurrently. Completion preserves current metadata and the other document, rejects truncated output, and leaves originals and any saved Word available after failure. The browser retains pending description drafts across directory and module navigation and removes each draft only after its matching save succeeds.

Numeric directory order survives renaming. Search combines saved tags and text descriptions; saved normalized pen strokes remain read-only and are not recognized as searchable text. Description and search use the existing speech Consumer. Their focused fields share the corresponding microphone button’s recorder for a 500 ms hold-Space gesture; short presses insert one space at the current selection. Composition, modified shortcuts, unrelated fields, and unfocused conversation inputs do not acquire that gesture. Release, blur, page hiding, and unmount finish or cancel the hold; permission that settles after release cannot leave a recording running. Description edits save after 500 ms, on blur, or on directory changes, with retained failed drafts resubmitted through Retry. Search transcripts replace only the query and wait for search submission. Capture failure notifications distinguish permission denial, missing inputs, device startup failure, and unsupported recording requirements. Directory, search, and annotation operations add no model-visible inputs or Session events. Proofreading inputs, image attachments, and results use normal child session logging.

Corrected TeX bracket delimiters are normalized outside code, links, illustrations, and existing math, with the complete normalized output checked against the text limit. Markdown math parsing identifies complete dollar-delimited expressions. KaTeX supplies MathML, and mathml2omml converts it to native Office equations, preserving editability in Word. The same MathML is stored in the DOCX custom property `dsh.example.mathml`; browser previews sanitize and render it because docx-preview omits accents and combined subscripts/superscripts. This property belongs only to collection-generated documents; editing accepts structured paragraphs, never arbitrary browser-supplied Word XML. Generated files, saved-file reads, and exports share DOCX typography normalization so browser CSS cannot conceal mismatched downloads. Body text uses 12-point SimSun/Times New Roman, equations use Cambria Math, and OCR heading emphasis is removed while mathematical emphasis remains intact. The converter’s invalid upright style is repaired to OMML plain style and equation run properties retain schema order. Bold lowercase Latin and Greek formula identifiers use bold italic in both representations; only affected equations are rebuilt from their saved MathML, with equal equation counts and unchanged text required before replacement. OMML bold-italic runs omit normal-text mode so Word uses mathematical glyphs, and browser previews apply the corresponding weight. Typography normalization also rebuilds supported text-only formulas, committing the derivative only when bytes change, without OCR or metadata changes. Unsupported TeX remains visible for correction.

The collection opts into OCR image assets. MinerU returns bounded image data URLs, and Markdown targets resolve only against those returned bytes. The Word writer decodes illustrations into proportional embedded PNGs. Printed illustration dimensions are bounded independently of OCR resolution: normalization resizes both drawing extents and picture transforms, including in edited paragraphs, while retaining media pixels and text formatting. Existing unresolved references trigger recovery from the saved source before a file read or export; recovered assets replace only matching image markers, preserving original text and native equations. Image-only recovery skips proofreading to preserve saved text; a full recheck waits for active recovery, then starts its own OCR and child. The recognition owner deduplicates concurrent recovery and rejects late commits after source replacement or deletion. Recovery failures retain the prior Word for retry. The compiler re-registers each image through docx, retaining its media bytes and dimensions while allocating output relationships; copying drawing XML alone would leave broken or colliding references.

Search selection is browser-local and restricted to visible results with generated question Word files. Export captures committed records in request order and pairs explanations inline or appends them on a new page. Only original question and explanation content is included; titles, numbering, tags, and descriptions are not added. Absent explanations are omitted; missing records or unfinished uploaded documents fail the whole operation. The compiler accepts collection-generated paragraph content, trims edge whitespace, imports its XML and native equations through the existing docx adapter, and joins preview MathML in the same order. Two single-spaced empty paragraphs separate question blocks and grouped appendix explanations; the appendix starts on a new page without leading blank lines. After required illustration recovery and heading identification, complete reviewed documents compile without storage writes, model calls, or OCR.

Each proofreading child belongs to the workbench-owned hidden parent, independently of the selected conversation. Its goal is accurate transcription matching the original, never rewriting, solving, or correcting errors printed in the question or explanation. It receives complete MinerU Markdown and all original pages, uses the image-capable tool-model route, and returns structured final Markdown. Configured whole-text, page, attachment, raster, and time limits reject incomplete processing; changed illustration references reject replacement.

A separate fresh spawn child identifies heading metadata from all original pages and an exact saved Word projection. It receives no parent conversation and returns paragraph indexes and exact copied prefixes. Native formulas appear as atomic labelled markers; the Host validates prefix identity, formula boundaries, retained substantive content, and image preservation before deleting nodes. It prunes matching preview MathML for removed heading equations. The document records version 2 completion in `dsh.example.headingReviewed`, including no-heading decisions; older records are reviewed again for later paragraph headings. First reads and exports review unmarked saved files without OCR; subsequent reads, downloads, and both export layouts reuse the reviewed bytes. The existing per-document recognition owner deduplicates this work, waits for cancellation, and checks source identity plus Word revision before commit. Failures retain saved Word bytes and metadata.

Textbook layout uses explicit Western-font runs so Word cannot assign adjacent Latin letters to the Chinese font slot. Plain variables are italic, locally declared lowercase vectors are bold italic, and digits, function names, and option labels are upright. The child preserves source paragraph groups, option rows, and figure order and emits all mathematical symbols as TeX. Native Word tab stops align complete A–D option sequences separately from the stem; spaces inside each option keep its label beside its formula. A standalone answer parenthesis before options joins the preceding stem. Body paragraphs use 1.25 line spacing. Illustrations follow all text and options in their source, right-aligned in dedicated figure paragraphs. Compilation groups imported and recovered illustrations within each source before joining blocks; figure paragraph styles preserve that placement during subsequent normalization. Saved equations and media bytes remain intact. The browser projects those tabs into responsive columns because fixed page coordinates cannot fit every preview width. Shared normalization preserves non-whitespace source characters and is idempotent; it needs no OCR. Markdown-only empty paragraphs are omitted, while the export compiler owns the two-line gaps. Word tests cover run styles, original text, option arrangements, native equations through compilation, and idempotence; client and assembled Web tests cover option cells and preview disposal.

The project owner authorizes distribution of mathml2omml 0.5.0 under LGPL-3.0-or-later. The converter remains an external Node module so users can replace it with an interface-compatible modified build without application signing keys. The [distribution packet](../../../../packages/host/teacher-workbench/third-party/mathml2omml/NOTICE.txt) ships the complete GPL and LGPL texts, unchanged upstream source and build configuration, the bundled entities source, retained dependency notices, and rebuilding and replacement instructions. The notices generator pins the reviewed identity, version, license, source archives, and license files; the workspace manifest check requires the packet in the publication file list, and the desktop payload check rejects an omitted runtime or packet. This version-specific decision does not authorize unrelated copyleft dependencies or reclassify LGPL as permissive.

Expanded Word windows use Tiptap for text and paragraphs and MathLive with locally embedded fonts for visual equation entry. The workbench dictionary owns supplemental menu translations and selects the MathLive locale while the dialog is open; closing restores the shared locale. A React palette renders high-school symbols inside the dialog and inserts LaTeX through MathLive at its preserved selection, including selected-text templates and placeholders. It uses no global virtual-keyboard container. Font-style menu entries have localized text labels; bold toggles preserve the selected variant and distinguish upright from mathematical italic letters. The accents row follows Roman numerals. Empty accent insertion selects an ordinary editable letter because MathLive 0.110 cannot enter accent placeholders. Slanted parallel lines use the compact double-solidus glyph (U+2AFD) in a text atom, preserving its proportions in MathML and Office equations; the dialog converts MathLive’s corresponding `\sslash` command to that atom before applying an edit. The menu inserts a two-row cases template with editable placeholders. Equation conversion promotes a plain brace preceding a one-sided matrix to a growing Office delimiter with left-aligned rows; the same conversion handles whole-equation bold changes. MathLive selection, active-structure, text-mode, fence, and caret colors consume resolved workbench tokens through its public CSS variables; its system dark-mode defaults can conflict with an explicitly light workbench. The menu excludes clipboard and select-all commands; their keyboard shortcuts remain available. Applied formulas use KaTeX, matching the Word writer, and are sanitized as complete MathML elements; standalone MathML fragments lose their mathematical namespace when parsed as HTML. Visible formulas use KaTeX HTML with locally embedded fonts and SVG radicals; accessible MathML is retained separately. Imported DOCX styles use an implicit CSS scope rooted at their preview container and ending before rendered equations. This keeps document span fonts, minimum heights, and transparent SVG fills out of KaTeX, and prevents simultaneously visible documents from overriding each other’s styles. Numbering counter resets attach to that scope root. Saved MathML is serialized as XML before supplying canonical TeX through the Word editor’s converter, preserving nonbreaking spaces as characters instead of HTML entity names; native MathML is retained when conversion is unavailable. Whole-equation bold uses a separate boolean in structured edits and an outer preview weight, leaving intrinsic MathML emphasis intact. Changing that weight rebuilds native math from the retained MathML, applies Office math styles and control properties, and preserves size; untouched equations retain their XML. Unsupported formulas are rejected before replacement. The toolbar supports fonts, sizes, bold, italic, underline, alignment, line spacing, indentation, undo, and redo. Chinese size labels map to numeric point values; the editor accepts text and equations from 5 to 96 points, preserving the sizes through saved Word and compilation. Font selection reads both Word font fields over the selected characters; mixed fonts are explicit, and caret formatting follows the surrounding script and stored typing marks. The editor font extension supplies both font faces in CSS and derives inline decorations over East Asian characters from the same script rules as the toolbar. These decorations assign the East Asian face directly, preserving its glyphs and line metrics even when the Western font also covers Chinese. They update with document changes and never enter the saved document. Its HTML metadata retains the two original font names across rich-text copying; the CSS family list is never saved as a single Word font name. Save and Ctrl/Cmd+S submit structured paragraphs; closing offers save or discard. Saved documents can be downloaded from their preview cards. The Host rejects stale source or Word revisions. Edited paragraphs retain user formatting in subsequent previews, downloads, and both export layouts. Unchanged native equations and images retain their XML or media; changed equations become native Office equations with matching preview MathML. Automatic proofreading still cannot rewrite questions, and manual editing calls no model.

The pinned MathLive 0.110 patch replaces only selected atoms at IME composition start and preserves their containing branch. Its deletion command can collapse a fully selected subscript, radical, or fraction, while composition inserts replacement text into that structure. The patch covers development and production ESM and CommonJS artifacts. Browser regressions compare committed IME input with direct keyboard input, including selected-letter replacement, undo/redo, and applied MathML.

Formula colors are already retained in preview MathML; mathml2omml 0.5.0 computes color grouping but omits native color properties. The pinned dependency patch writes inherited colors and backgrounds to native runs and structural control properties without changing equation conversion. Its corresponding source patch ships beside the upstream source and replacement instructions and is covered by the distribution digest and desktop payload gates. A second pinned patch adds foreground/background wrappers to mathml-to-latex 1.8.0 so saved previews and reopened equations retain those scopes, using color-string to normalize CSS colors. The Host normalizes opaque named/hex/RGB colors before conversion and repairs previously saved equations whose preview colors are absent from native Word, retaining equation size, bold, and paragraph formatting.

The pinned KaTeX patch recognizes MathLive `\mathbfit` as a font command, avoiding the token-around-row MathML produced by a whole-expression `\boldsymbol` alias. MathML-to-LaTeX emits `\mathbfit` for bold italics, retains number/operator variants, and reads legacy rows inside token elements; previews replace those invalid wrappers with rows before sanitization. The shared converter maps slanted inequalities, proper subset/superset, complement, quantifiers, not parallel, circle, and parallelogram to canonical glyph-preserving commands. Approximate underset relations lose their operator on reopening, a negated parallel command produces an unsupported math-mode combining accent, and generic square or big-operator mappings change the requested geometry. The dialog expands MathLive `\doubleprime` to two `\prime` symbols before validation and application because KaTeX does not accept the combined command. Prime operators emit `\prime` instead of apostrophe shorthand because their parent MathML already supplies the superscript; multiple apostrophes separated by converter whitespace create invalid repeated superscripts. Both token and operator mappings preserve these symbols across saved previews, repeated edits, downloads, and both export layouts. The editor converts complete TeX directly through the shared native-math writer, bypassing Markdown and temporary DOCX generation. Background-color commands may contain text-mode math delimiters and must remain one equation. KaTeX operator tokens carry explicit bold MathML while remaining upright; HTML uses the dedicated bold face when available and synthesizes weight on fallback glyphs otherwise. Without both representations, relation symbols lose emphasis on Apply or on subsequent edits and native Word conversion. The bold menu applies both mathematical variant weight and text font series so text-mode geometry glyphs respond to the same control. The text converter retains parallel/parallelogram weight without replacing their glyphs. Regression coverage applies and toggles menu bold on individual symbols next to regular ones, checks their rendered weights, then saves, reopens, edits, and exports them; coordinate expressions and malformed-command rejection remain covered.

Textbook complement uses the dedicated non-calligraphic ∁ glyph. Proper subset/superset and slanted not-parallel use literal text atoms: a subset derived from STIX Two Math supplies their Web outlines, and U+20E5 overlays U+2AFD for negation. The browser proper-set outlines use 70% scale and a 0.15-em lift; Cambria Math native runs use 80% size and a 0.08-em lift. These font-specific proportions keep the double underline close to the capitals. The saved MathML owns the equation size independently of those smaller runs, preventing cumulative shrinkage when a formula begins with a proper-set sign. This retains the slanted pair in Office readers that omit native border-box strikes. Native equations use Cambria Math because assigning text atoms to SimSun can yield missing glyphs. The complement uses an upright native math run, without normal-text mode or a document-specific font. WPS omitted the glyph when its normal-text run selected the embedded STIX subset, despite valid font parts and glyph outlines. Normalization splits mixed runs, preserves local size, color, and weight, and removes that owned font assignment and package part from saved documents. Set letters remain mathematical italics. The Office reader chooses the native glyph outline; structural export checks do not establish identical appearance across readers. Compound bold expressions emit MathML rows rather than nested token elements, whose structural children are invalid inside Office text runs. Mathematical alphabet and weight remain separate in conversion and canonical TeX; replacing a family with a bold variant loses number-set glyphs. Saved equations with malformed native text or missing alphabets rebuild from retained MathML with their size and whole-equation weight. Accent conversion retains vector, hat, bar, tilde, and dot commands rather than emitting an overset with a bare combining mark; MathLive cannot safely edit that mark as a separate formula. Native bars contain their base directly, and multi-letter function identifiers remain upright with local emphasis. N-ary signs retain bold in their native control properties. N-ary operands bind to their own native arguments; neighboring tokens merge only into runs so following text cannot fall outside `m:t` and disappear during compilation. The complete visible palette is exercised through real insertion, local bold, repeated saves, colored whole-equation bold, download, and both export layouts; downloaded native equations must retain text-only leaves and the exported equations must match them.

## Alternatives considered

**Embed files in the revisioned workbench singleton.** Every class, timetable, or daily-task mutation would retransmit and rewrite unrelated question files. The collection has no roster or timetable references requiring a shared commit. The [workbench decision](2026-08-17-durable-teacher-workbench.md) remains authoritative for its related teaching records.

**Detect headings with regular expressions or rewrite the full question.** Heading formats vary, and dates or parenthesized text can be substantive conditions. Visual identification selects only an exact prefix; the Host preserves the body instead of asking the heading child to reproduce it.

**Keep original and generated files outside SQLite.** File deletion and metadata deletion would require cross-medium cleanup and recovery. One record keeps the requested original, generated document, and metadata atomic through the existing backend.

**Store only recognized text and rebuild Word on every preview.** Preview and download would not read the same saved artifact, and successful OCR would still depend on later conversion availability. Persisting DOCX makes the preview and download agree after restart.

**Leave illustrations as external references.** MinerU-relative paths are not browser routes, and downloaded Word files cannot depend on temporary parser files. Embedded media keeps illustrations under the same SQLite record and deletion operation as the generated document.

**Render formulas as images.** Images would prevent edits through Word's native equation editor. The [KaTeX](https://katex.org/docs/options) and [mathml2omml](https://github.com/fiduswriter/mathml2omml) libraries own mathematical parsing and conversion; the collection does not maintain a TeX grammar or Office-math translator.

## Consequences

Questions survive browser and Host restarts, and late OCR cannot restore deleted data. Handwriting is preserved without promising handwriting recognition. Word equations remain editable, while unsupported TeX and Markdown tables remain text. The storage-domain implementation retains its records in Host memory; a large collection can therefore require substantial memory despite file-free browser catalog reads.

## Testing

SQLite tests cover restart recovery, numeric creation, original/Word deletion, concurrent metadata edits, simultaneous question/explanation recognition, source replacement during either OCR, unavailable or truncated OCR, invalid files, and cancellation before storage close. Word tests verify native vector accents, fractions, powers, display math, uniform body/equation typography, preserved mathematical emphasis, and normalization of saved text or native equations without repeated writes or OCR. Client tests cover draft retention, independent background recognition, out-of-order responses, equation matching, and sanitization of persisted MathML. The assembled Web scenario uploads images and a PDF through the real Remote and MinerU adapter against a deterministic external-provider fixture, renders both document pairs and their actual DOCX equations, checks the question search drawer, renders saved pen strokes read-only, reloads, exports both selected-question layouts, and deletes a directory. Illustration tests verify requested provider bytes, failed recovery retention, concurrent reads, late source replacement and deletion, image-only paragraphs, and cross-document media relationships. The Web scenario renders both illustration previews and downloads exports containing their embedded PNGs. Export tests cover ordering, two-line gaps, missing explanations, unfinished content, native formulas, and omission of added titles, numbering, tags, and descriptions, plus offline export of complete saved documents. Proofreading tests cover original images and every PDF page, selected-model routing, missing image capability, complete-result limits, deadlines, teardown, invalid output, changed illustration references, and replacement during correction. The assembled scenario records the actual child input and result-tool schema, exercises automatic and explicit proofreading, and verifies corrected point labels and ratio colons in Word. Voice tests cover capture failures, retry, debounce persistence, short spaces, caret placement, composition, field routing, release during permission acquisition, blur, and teardown; browser-generated synthetic audio exercises native recording, WAV conversion, the Host speech Remote, and description persistence against an external ASR fixture. MinerU and model accuracy and physical microphone hardware remain deployment verification concerns.
