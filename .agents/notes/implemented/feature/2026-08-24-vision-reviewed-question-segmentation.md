# Agent Note: Vision-reviewed question segmentation

Status: implemented

English | [中文](2026-08-24-vision-reviewed-question-segmentation.zh.md)

## Problem

OCR text and geometry identify where recognized elements occur, but they do not reliably identify a semantic transition inside the interval between two question heads. A combined workbook may place a chapter explanation, worked answer, or another paper's answer section after one problem and before the next. Treating the next selected head as the only possible end includes that unrelated material even when the head list itself is correct.

The first boundary draft also cannot prove that its rendered result is usable. A crop may cross into a neighboring column, omit a figure or complete question, retain an answer block, or stop too early despite satisfying element-reference validation. Saving immediately after one semantic pass makes those defects durable without letting the model inspect the actual pixels produced by its decisions.

Large scanned pages make each visual preview's Base64 payload several megabytes. A whole-string regular expression with a repeated capture can exhaust the JavaScript regular-expression stack before the boundary child starts, even though the preview bytes and configured size limits are valid.

## Decision

Both the browser and ordinary-conversation pipelines render every selected source page and supply those previews to each semantic page-group child through a run-scoped image tool. Canonical Base64 validation uses bounded-length checks and a byte round trip rather than a whole-payload regular expression. The child reads images progressively, with 20 images per call by default, and must inspect every page preview as well as every bounded OCR chunk before a boundary draft can be accepted. A route that does not declare image input cannot produce a model-accepted boundary, so the Host uses its deterministic answer-demand fallback instead of silently treating unchecked model output as accepted. Image tool results use stored attachments, so every model-visible preview remains reconstructable from the child Session log. A semantic group owns at most 20 selected pages and 300 fallible question-head candidates by default, then inspects one adjacent selected page on either side. Candidate density splits a workbook before the page limit while ordinary papers retain larger groups and cross-group continuation context. Boundary and review groups use the bounded concurrency defined by [the question-cutting throughput decision](2026-08-26-bounded-parallel-question-cutting.md).

The initial boundary stage admits a configurable number of fresh child runs, two by default. A child that ends with an invented, stale, or otherwise unaccepted final token contributes no model draft; the next child receives an explicit recovery instruction while source-inspection, accepted-token, and submission-deduplication state reset. If the bounded stage still has no accepted draft, the Host validates deterministic geometry for only candidates with visible learner answer-demand evidence. The wall-clock deadline still bounds the complete stage.

A question draft may name a `stopBeforeElementId` inside its own object. That id is an exclusive boundary naming the first OCR element outside that question, while the root `stopBeforeElementId` still marks the first element outside the complete inspected document range. The same element cannot be both a stop and an `additionalElementIds` claim. Fallible recall candidates are not forced to become questions, but every candidate must be classified as a selected head, retained non-head content, or excluded pixels; the Host rejects a silent omission. Prompt-bearing worked-example labels participate in that recall set, while the child still decides their semantic role. A semantic group may submit zero questions after classifying all candidates, so numbered definitions, formulas, method steps, theory summaries, and answer prose do not force a fabricated crop. A recognized hierarchical section, answer heading, or bracketed/colon-prefixed answer or analysis block is automatically excluded and becomes the nearest applicable hard stop even when the child omits it. The Host rejects selecting that transition as a question head. It also rejects a bracketed source citation as a standalone question when no non-head content belongs to it; the same label remains valid when it owns a stem, options, subparts, table, or figure. The Host validates ordering, element identity, and contradictory ownership, derives initial rectangles from OCR geometry, and treats the per-question stop as a hard ownership limit even during same-page column reassignment. Where consecutive owned and foreign boxes leave a vertical gap, the crop edge uses the gap midpoint instead of touching the foreign box. When adjacent question-head boxes overlap by no more than the crop padding, both regions share the later head's top as one hard cut line so neither crop imports the other head. A selected next head remains a hard crop boundary even when an oversized owned image box crosses it; a semantic heading that only shares the vertical band of a spatially separate owned diagram is erased without clipping the diagram. Automatic ownership stops before a trailing element cluster separated by more than `maxQuestionAutoOwnedGapRatio` of the page height unless that cluster contains an explicit attachment. An explicitly claimed attachment also seeds its horizontal lane through the next semantic or question stop. If a page-bottom stem continues in a disjoint page-top column, the Host renders those lane clusters as separate source-safe slices and concatenates them in OCR reading order instead of sampling the intervening page rectangle. This structural safeguard keeps detached answers, anti-piracy copy, and later-paper material away from a final question while preserving a deliberately claimed distant diagram. An attachment claim conflicts with a vertically overlapping question head only when that head is horizontally closer than the claimed owner; left-column heads therefore cannot reject right-column figures merely because their y ranges overlap.

After preliminary rendering, the first complete-group review receives every crop and every core source page through separate progressive image tools. This lets it detect a page whose questions were all omitted; later crop-only passes receive the cited questions and local source pages. Exact `page-x` tool labels identify source pages even when printed footer numbers differ; zero-based OCR `pageIndex` values are used only for coordinate edits. The reviewer may accept the initial group only after comparing all requested images and matching each independent source problem to one crop. Each verified crop records the visible response that the learner must produce as `answerDemand`, its actual topmost, bottommost, leftmost, and rightmost non-white content, and every required source visual with its visible crop location; numbering or a topic label cannot serve as that evidence. The findings tool accepts one complete `verifiedCrops` and `findings` array submission after image inspection and rejects any crop omitted from both arrays. The compact annotated-sheet path also requires every verified entry to state its exact visible `answerDemand` and visible task evidence; a crop rectangle or Q label cannot substitute, and theory, method, answer, solution, or explanatory content without a learner response is reported with `remove-crop`. This reduces agent-loop round trips without removing per-crop evidence; [the throughput decision](2026-08-26-bounded-parallel-question-cutting.md) owns that trade-off. A worked example with a problem stem requires a crop for that stem even when a printed answer and analysis immediately follow. A page-sized theory or knowledge-summary crop without one answer demand is a spurious question. A whole problem without an independent crop is a source-page defect even when its pixels appear inside a neighboring crop; a complete group replacement can then restore the missing head. A spurious crop uses one crop finding that cites its crop id and declares `remove-crop`; a source-page id may accompany that finding as evidence but is not required. The Host deletes that head while retaining every other group question. A page-only finding is reserved for a wholly missing independent question with no listed crop and requires its visible `missingQuestionHead`. It may name a neighboring crop that contains the missing problem's pixels; distinct missing heads on one page remain separate findings. Content transferred between two crops requires findings for both, which keeps the next pass local to those images. A group whose initial draft contains no questions still enters source-page review with no crop ids; the reviewer either confirms that no independent problem is visible or reports a page-only defect and adds the missing heads. A missing problem, merged neighbor, truncated stem, answer blank or figure, answer, explanation, title, footer, detached lower-page block, or adjacent-column content is a defect. Registration fields, binding or trim lines, vertical page labels, printed page numbers, running headers or footers, QR codes, publisher resource labels, and optional dynamic-demo blocks are furniture unless the stem explicitly requires them; excluding such an image also requires excluding its compact connected caption. A clean review finalizes verified records and never reads OCR. Before a correction is accepted, the child may replace a mistaken finding after closer inspection instead of being forced to invent geometry for a crop it now considers valid. Updating the finding set clears rejected-draft fingerprints because the same correction can become authorized by newly supplied page evidence. The review stage uses the same configurable fresh-child limit as initial segmentation. A run with no recorded defect may recover from an invented token in a fresh child with reset inspection and submission state. Once defects are recorded, an invalid final correction returns those findings as unresolved. If bounded review children stop uncleanly before recording a classification, the Host also returns the listed crops as unresolved. The caller immediately preserves that geometry as unverified instead of repeating unchanged evidence or aborting the complete PDF; only a concrete revision receives a local follow-up pass.

Thin response marks that OCR omits must be confirmed from actual crop pixels, never inferred from the answer demand or source text. A missing edge mark remains a crop-local vertical correction.

The Host derives `visualAttention` records from suspicious source geometry without treating them as semantic verdicts. A crop receives a flag when its rendered output concatenates same-page source slices across more than the configured automatic-ownership gap, erases or clips a recognized source image, samples an unowned strip to the right, or reaches a physical page edge where a running header or footer may appear. The reviewer must resolve every flag against source and crop pixels in `attentionEvidence` before verification. Detached watermarks, publisher marks, answer blocks, and other unrelated lower pixels are crop-specific defects even when a large white gap separates them from the question; an erased diagram, table, or other required visual is a missing-content defect.

Every crop-specific finding declares structural repair intents for expanding or trimming a vertical edge, trimming unrelated source pixels from the right edge, reassigning referenced content, or removing a spurious crop. The Host derives the direction of each submitted edge change from the current geometry and rejects a move that the finding did not authorize. When content was transferred across adjacent crop boundaries, the receiving crop must declare the matching expansion and the contaminated crop must declare the complementary trim; only those cited crops are rerendered.

A crop-specific defect unlocks OCR and a boundary patch keyed by each cited stable source head. The Host adds every unchanged group head while validating the patch, merges only submitted heads into the existing group, and rejects changes to uncited questions or corrections that leave a cited crop unchanged. A crop finding remains local when it also cites a source page as evidence. `removedCropIds` also stays local: each id requires one crop finding that declares `remove-crop`, while its source-page id is optional evidence, and the Host removes only those stable heads before renumbering the retained questions. Only a genuine page-only finding with `missingQuestionHead` for a wholly missing head unlocks candidate-complete group replacement. An attachment-only patch extends the existing region with the validated element boxes instead of rebuilding its ownership interval. It removes white erasures that overlap the explicitly restored attachment while retaining the original neighboring stop and every unrelated erasure. When visible content such as a drawn answer line has no usable OCR element, the reviewer may adjust only a cited source slice's top or bottom in OCR page units. A `trim-right` finding may reduce that cited slice's `rightLimit` no farther than its owned pixels. The Host retains `left` and `right`, keeps the PDF-wide output width fixed, fills the removed source area with white padding, requires the question head to remain complete, and rejects a vertical edit only when the sampled source rectangle crosses another question head; equal-width white output padding does not create a false crossing.

The caller applies at most two local recuts to one defective image. Unaffected crops and their pixels remain outside subsequent review requests; source pages stay read-only context. A crop-local review cannot turn an unlisted visible question into a missing-question finding: the Host rejects page-only findings and complete-group recovery in that scope. A validated spurious-crop removal and every question whose geometry changes join the local follow-up, while an unconsumed page-only finding can still add a wholly missing question through a complete replacement draft. If the second result is still reported as defective, the caller saves that last result instead of failing the complete PDF.

The Web background controller and the conversation-operated Host renderer use the same segmentation request, visual review Remote, group replacement, width calculation, and convergence rule. Navigation may detach the Web progress view but does not interrupt its plugin-owned queue. Conversation cutting retains its separate requirement for an explicit save destination; visual review does not add a default destination.

A head-bearing source slice anchors its left edge at the question head even when an explicit claim reaches into another column. A detached claimed block that extends farther left remains a separate slice, so it cannot move the question's fixed origin. The PDF-wide output width is the largest non-outlier normalized distance from each fixed question left edge to its inset lane limit; [Per-Region Question Crop Origin](../bug-fix/2026-08-24-per-region-question-crop-origin.md) owns the median-relative outlier rule. Each source slice samples only to its own limit and uses white padding for any remainder, preserving raster-only answer lines while excluding gutter and neighboring-lane pixels. Crop labels and review instructions identify that blank white suffix as intentional equal-width padding; neighboring-column content is contamination only when its pixels are visible inside the crop. Only core pages own submitted heads, required semantic decisions, and visual completeness coverage; adjacent inspection pages remain model-visible continuation context, while their detected heads act as automatic ownership stops.

## Alternatives considered

**Use page previews only during the first boundary pass.** This improves semantic interpretation but cannot detect a mismatch between accepted regions and their final rasterization.

**Review only the produced crops.** A crop can look internally complete while an entire source problem is absent. Comparing the complete crop sequence with the source pages is required to detect omissions.

**Rely on prose instructions alone.** A checklist can be skipped while still producing a superficially valid verification record. Geometry-derived attention flags and required structured evidence focus the reviewer without hard-coding source wording or turning a warning into an automatic semantic decision.

**Let the reviewer replace complete pixel rectangles.** Unrestricted vision coordinates would create a second horizontal geometry system and could violate the uniform-width rule. Review corrections therefore use OCR ids for semantic ownership and admit only Host-validated top or bottom edits in the same page units when visible content has no element id.

**Keep fixed head-to-next-head ownership and add more exclusion patterns.** Pattern lists cannot enumerate arbitrary chapter prose, worked solutions, or answer transitions across combined sources. Per-question ends let the agent describe the semantic stop it observed without weakening coordinate validation.

## Consequences

- Question cutting now requires an image-capable configured tool model and incurs page-preview plus crop-review image tokens in addition to MinerU and OCR-source calls.
- Review children and their image attachments increase Session-log and attachment storage, but the complete model-visible decision remains replayable.
- Initial crops and zero-question groups enter visual review before persistence. A visual-review timeout, model error, unavailable vision route, invalid output, or teardown failure retains the current group as unresolved; three identical rejected tool results stop the current child. An unresolved result is saved immediately with an explicit warning, while a concrete correction receives the bounded local follow-up. A confirmed zero-question selection completes without creating an empty batch. Page and candidate limits keep one dense workbook review bounded without reducing ordinary papers to single-page groups.
- An initial-boundary or crop-review child that bypasses its tools may add one fresh model run by default. This costs latency only on invalid output and does not weaken accepted-token validation.
- Structured edge-content and required-visual evidence increases each verification call slightly. Geometry-derived attention is limited to suspicious source relationships, and the reviewer remains responsible for deciding whether the cited content belongs to the question.
- MinerU remains the authority for element identity and page units. Visual review can reinterpret recognized elements and recover vertical whitespace or drawn lines from the source preview, but it cannot invent missing source pixels or alter the Host-owned horizontal boundary rule.
