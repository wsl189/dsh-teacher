# Agent Note: Bundled extensions, AnySearch, image generation, PPT Master, Univer Office, and shared speech input

Status: implemented

English | [中文](2026-08-25-bundled-extensions-and-qq-speech.zh.md)

## Problem

The Windows installer is not a complete product migration if AI image generation, IM, general cron management, skill and MCP management, Office workspace preview, Univer authoring, and the product's presentation workflow still depend on profile-local installation. A new machine could install the EXE successfully yet expose a different interface, tool roster, or skill catalog because those executable dependencies and resources were absent from the application closure. Plugin credentials, bot sessions, schedules, user skill files, MCP configuration, generated-image history, galleries, Univer documents, and worktrees have a different lifecycle: embedding those machine-specific values would leak private state and make an installer overwrite runtime data.

Composer, Teacher Workbench, and QQ voice intake require one provider-neutral Host operation. Keeping ASR transport in the QQ integration would create a second model configuration, couple browser controls to a bot plugin, and prevent supplier-model assignments from governing every voice entry point.

## Decision

The Web and desktop composition includes the MIT `@anysearch/anysearch-dsh` 0.1.4 artifact built from the supplied source and pinned under `third-party/`. It selects AnySearch for `web_search` and `web_fetch`, while base, headless, and SDK defaults remain unchanged. The Web patch disables the inherited `web-search-deepseek` row, so Web and desktop do not register an unused second search provider or expose its settings namespace. The plugin's three advanced tools register globally; a reviewed compatibility patch removes its global `web_fetch` fallback so each session preset retains ownership of standard-tool availability and guidance. Scoped peer overrides keep the tested workspace services as the only implementations. The Web search settings card writes its optional credential through the DSH credential store and its endpoint through the `web-search-anysearch` settings section; the client snapshots both for each operation. The optional `ANYSEARCH_API_KEY` is resolved at each operation; absence means anonymous remote access, not an offline service or an installer-provisioned account. Queries and extraction URLs leave the machine for the configured endpoint, whose quotas and authentication failures remain visible without an automatic provider switch.

`@deepseek-ai/dsh-web-app` directly mounts the reviewed plugins pinned in the [third-party inventory](../../../../third-party/README.md). Image generation, IM, cron, skills/MCP management, Office preview, and Univer authoring are part of the Windows installer. Their credentials, bot state, schedules, documents, worktrees, and caches remain in user-owned directories; image history remains under `~/.dsh/dsh-imagegen`. The [official integration decision](../architecture/2026-09-16-official-release-integration.md) owns sidebar and desktop-control composition.

The same Web composition mounts `@deepseek-ai/dsh-skill-ppt-master`, an immutable provider for the upstream PPT Master 6.4.0 skill. The package retains the complete upstream directory—including scripts, references, layouts, images, sounds, license, sponsor records, dependency declaration, and integrity guard—and derives its `path` and `resourceBase` from the installed package rather than copying resources into `DSH_HOME`. Source builds and the desktop EXE therefore load one fixed `bundled` catalog entry from the same package-relative layout. The installer does not create a Python environment or install workflow-specific packages; operators provide a compatible `python3` runtime and the dependencies required by the selected PPT Master route.

The image-generation compatibility patch resolves the selected model, complete endpoint, protocol, and credential from Models for each task, with explicit OpenAI Images, DashScope, and MiniMax formats. The skill/MCP panel uses the current renderer and session-controller APIs. The Univer repack removes embedded development-license fallback values; only runtime `UNIVER_LICENSE` reaches its processes. Telemetry is disabled. The notices generator records its external and artifact-bundled commercial modules, and browser rendering retains the upstream Chrome/Chromium prerequisite.

Upstream plugins own their operation and state lifecycles. Shared model settings own media routes and credentials; IM owns channels and file delivery; cron owns general schedules; the skill/MCP panel owns its managed profile configuration; Univer owns its editing and review lifecycle. Workbench reminders remain owned by the [workbench document](2026-08-22-mobile-workbench-reminders.md). The distribution retains the Office viewer’s AGPL-3.0 obligations and Univer’s separate commercial obligations.

`@deepseek-ai/dsh-speech` defines a provider-selecting Host capability and the typed `speech.transcribe` Remote. `@deepseek-ai/dsh-speech-model-settings` registers provider `model-settings`. For every recording it reads the current speech assignment from `agent-default-model`, reloads the supplier profile from `llm-pi-ai`, and resolves that route's credential through the credentials service, so changes saved under **Settings → Models** affect the next request without a Host restart. The adapter sends the exact maintained operation format for the selected Zhipu GLM-ASR or Qwen-ASR model and returns only normalized non-empty text plus provider identity. The bundled IM Host passes QQ WAV attachments to the same speech operation; a transcript already supplied by QQ remains local and bypasses the provider. dsh-im owns platform connections and attachment download, not a second ASR configuration or model card. The [supplier-grouped model settings decision](../architecture/2026-09-01-supplier-grouped-model-settings.md) owns route and assignment configuration.

Composer and Teacher Workbench controls share one MediaRecorder hook. Each operation requests microphone access, collects one complete WebM, Ogg, MP4, MP3, or WAV blob, and releases every media track. Standard or WebKit AudioContext samples microphone activity for one shared neutral microphone glyph, whose active outline pulses and whose fill rises with the normalized level. Each audible sample resets one three-second silence timer; expiry stops the recorder and starts transcription, while the explicit control and hold-Space release remain early stops. The same AudioContext decoding then converts non-WAV recordings to 16 kHz mono PCM WAV before canonical base64 encoding and the Host Remote call; a host without that decoder retains the original MediaRecorder container, an empty level, and manual completion. This makes the browser path use the same broadly accepted WAV input as QQ voice attachments instead of assuming that a local OpenAI-compatible ASR implementation can decode Chromium WebM. Recording, preparation, or transcription blocks conflicting submit actions, while accepted text remains editable through the same draft, task, memo, or ledger path as typed text. Audio bytes and provider responses are never persisted or logged.

The supplier speech adapter accepts HTTPS endpoints and loopback HTTP only. It rejects embedded credentials, query strings, fragments, and redirects; bounds decoded audio and response bytes; validates canonical base64, media types, the exact selected provider/model pair, HTTP status, and response JSON; enforces a request deadline; and returns stable diagnostics without provider response bodies, credentials, or audio. Transport failures return `provider-unavailable`, while redirects and non-success HTTP statuses return `provider-failure`; browser Consumers present the latter as a request/settings failure rather than a network outage. These checks keep browser microphones and supplier credentials outside third-party client code even though the selected speech service receives each complete recording.

## Alternatives considered

**Keep the bundled extensions and PPT Master as profile installations.** This preserves a smaller application dependency closure but makes a fresh EXE installation incomplete, lets profile state silently change the shipped UI, tool roster, and skill catalog, and requires a second installation procedure on every computer.

**Infer image generation from a conversation model's image-input capability.** Image input describes vision understanding, not a generation operation. The unified registry therefore uses the fixed image-generation model type plus an explicit generation protocol and complete endpoint, while the image plugin continues to provide the tools, gallery, and result renderer.

**Ship only PPT Master's `SKILL.md`.** Its routes depend on packaged scripts, references, templates, and media, while its attribution guard requires the complete official attribution and execution-gate set. A body-only copy would advertise a workflow that fails as soon as it follows its own resource paths.

**Copy PPT Master into `DSH_HOME` on first launch.** A startup copy would turn versioned application resources into mutable user state and create ownership conflicts between user edits, upgrades, and reinstalls. A package provider keeps release resources immutable and leaves `DSH_HOME` for user-owned skills and configuration.

**Embed plugin configuration and user data in the installer.** Executable code is reproducible build input; tokens, bot sessions, cron records, and local work are mutable private state. Shipping or replacing them would leak credentials and make upgrades destructive. `DSH_HOME` remains the explicit migration unit for that state.

**Retain Web Speech API recognition for application controls.** This delegates provider, retention, language behavior, and browser availability to each browser while QQ already exposes an operator-selected ASR endpoint. One Host capability makes both UI surfaces use the same settings and validation.

**Require a second click and replace the microphone with a colored stop block.** This makes every utterance require another action and gives the composer and Daily Management different recording states. Shared silence completion and one level-driven microphone preserve an explicit stop without making it the normal path.

**Call supplier speech endpoints directly from each browser component or IM channel.** This would expose credentials to renderer code, duplicate provider-specific validation and limits, require cross-origin access, and make provider replacement a Consumer change. The shared Host Remote centralizes transport and keeps Consumers provider-neutral.

**Keep a separate Voice model card or ASR fields inside Connected Platforms → QQ.** Either location creates a second service route for a capability already assigned under Models, and the QQ location also hides a model shared by the composer and Daily Management behind one bot page. One Use cases selector makes the product-wide role explicit and reuses Service access credentials.

**Forward each MediaRecorder container unchanged.** OpenAI's service accepts common browser containers, but compatibility endpoints are not uniform. QQ voice attachments already arrive as WAV, so a local service can recognize the bot while hanging or failing on the browser's WebM/Opus. Browser-side decoding avoids an executable transcoder in the installer and keeps the Host provider independent of browser codecs.

**Infer a speech protocol from the supplier's LLM protocol or retry another model.** Media operation formats are not interchangeable with chat transports, and choosing another model would override the explicit Use cases assignment. The adapter supports exact provider/model pairs with maintained request formats, sends the selected model once, and rejects unsupported assignments before network I/O.

**Bundle the ASR server, MinerU, vLLM, models, and GPU runtime into the EXE.** Those services depend on deployment-specific hardware, drivers, model storage, and update policy. The installer contains their clients and configuration adapters, not the services themselves; service containers and the Windows application remain separate deployment units.

## Consequences

- A standard Web source build or Windows installer exposes the AI image studio, four image-generation tools, IM, general cron, skill/MCP management, Office preview, Univer authoring, and the complete `ppt-master` skill without `dsh plugin add`; the shipped-composition test pins the Host tools, all six client modules, and the bundled skill entry so a composition omission fails before release.
- PPT Master's 12,981-file, 83,654,741-byte logical resource tree increases the application closure and installer input. Installer compression may reduce the artifact size, but release storage and Windows extraction still account for the complete tree.
- Loading the PPT Master instructions works immediately after installation. Executing a route still requires an external compatible Python runtime and any optional packages or executables that route selects.
- Moving the complete working environment still requires copying the intended `DSH_HOME` state and `~/.dsh/dsh-imagegen`, then provisioning reachable image-generation, supplier speech, MinerU, and model services. Installing only the EXE moves application code, not private data or GPU services.
- Models keeps all image and speech routes under Service access and exposes one direct assignment for each under Use cases; the image plugin has no separate configuration card. Connected Platforms → QQ retains bot and workspace settings but has no ASR form; QQ voice attachments use the shared speech assignment.
- Composer and daily-management voice input use the same level-driven microphone and three-second silence completion. Web Audio hosts additionally buffer decoded PCM and one 16 kHz mono WAV before sending it through the Host; hosts without Web Audio retain manual stop, while the 20 MiB audio limit and operation deadline bound the transmitted recording and streaming or partial transcripts remain unsupported.
- A QQ platform transcript can satisfy a bot voice message without contacting the configured ASR service. Browser microphone input is the direct endpoint check, and an unavailable configured model produces the settings/request notice instead of the network notice.
- Office preview introduces an AGPL-3.0 runtime dependency. Repository and downstream distributions must retain its notices and comply with its license; this consequence is accepted to make the requested preview part of the default installation.
- Univer Office keeps commercial distribution rights and local Chrome/Chromium as prerequisites for licensed deployment and browser-rendered Slide operations. The [Viewer evaluation decision](../bug-fix/2026-09-01-univer-viewer-evaluation.md) permits startup without `UNIVER_LICENSE` under upstream limits. The installer contains neither a license value nor a browser executable, and the built-in composition disables Univer telemetry.
- The integration consumes published third-party plugin interfaces and pinned artifact versions. Upgrading those artifacts requires another compatibility, license, tool-roster, and shipped-client audit.

## Testing

The AnySearch integration suite boots the real shipped Web Loader composition against a local HTTP fixture. It requires the AnySearch settings namespace and the absence of the inherited DeepSeek search namespace, then covers anonymous search and extraction, both capability catalogs, advanced search, live settings changes for the endpoint and credential reference, rejected-key handling, partial batch results for quota and rate limits, and credential-bearing redirects. The Plugins-page browser scenario stores the key through credentials without exposing it in the settings document and confirms the saved status on reopen. The recorded Web search session uses the real AnySearch provider, pins the durable capped source list and browser card, and replays without API keys. Payload tests reject every missing AnySearch runtime file; publication checks accept only the reviewed archive path. The supplied source's own typecheck, tests, build, and package-content check also run before the archive is pinned.

Capability tests cover provider selection and disposal, live media-model assignment, supplier profile and credential reads, exact Zhipu and Qwen speech formats, exact OpenAI, DashScope, and MiniMax image formats, endpoint restrictions, cancellation, supported media, size and response limits, transport and HTTP failure classification, JSON failures, and safe diagnostics. Client tests cover MediaRecorder support and teardown, microphone-level projection, three-second silence completion, SSR, PCM WAV headers, stereo downmixing, resampling, decoder selection and cleanup, composer gestures and submit blocking, workbench commands, editable transcripts, and distinct connection and rejected-request notices. The Models browser scenario rejects separate image and Voice model cards, configures supplier routes, assigns image and speech models under Use cases, and confirms credentials stay outside the settings document. The Plugins browser scenario confirms that image-generation configuration is absent there, and the QQ workspace scenario confirms speech fields are absent from Connected Platforms → QQ. A keyless assembled Web scenario records deterministic activity in both the composer and Daily Management, pins the shared active microphone state, waits for silence completion, converts the audio in the real browser bundle, requires the selected GLM-ASR multipart request through the generated Remote, and pins both successful transcripts and rejected-model notices without a model call. The IM bridge test requires QQ WAV download to delegate to the same operation while preserving platform-supplied transcripts. The PPT Master package test loads the real provider and fixes the upstream version, license digest, integrity-gate marker, file count, and logical byte count. The shipped-composition scenario requires the four image-generation tools, IM and cron Host tools, all fourteen Univer tools, all six bundled client modules, and the loadable `ppt-master` catalog entry. The desktop payload tests require the image-generation Host and Client bundles, template snapshot, and license, the skill/MCP package, representative files across the complete PPT Master distribution, and Univer's Viewer, Gateway, workers, skills, commercial assets, and native runtime dependencies before the Windows workflow builds the same production dependency closure into its NSIS artifact.
