# Agent Note: Bundled extensions, AnySearch, image generation, PPT Master, Univer Office, and QQ speech input

Status: implemented

English | [中文](2026-08-25-bundled-extensions-and-qq-speech.zh.md)

## Problem

The Windows installer is not a complete product migration if AI image generation, IM, general cron management, skill and MCP management, Office workspace preview, Univer authoring, and the product's presentation workflow still depend on profile-local installation. A new machine could install the EXE successfully yet expose a different interface, tool roster, or skill catalog because those executable dependencies and resources were absent from the application closure. Plugin credentials, bot sessions, schedules, user skill files, MCP configuration, generated-image history, galleries, Univer documents, and worktrees have a different lifecycle: embedding those machine-specific values would leak private state and make an installer overwrite runtime data.

Composer and Teacher Workbench voice controls also used browser-native speech recognition independently from the QQ integration's configurable ASR service. The duplicated path gave the same installation two speech providers, two language owners, browser-dependent network behavior, and no Host-side validation or resource limits.

## Decision

The Web and desktop composition includes the MIT `@anysearch/anysearch-dsh` 0.1.4 artifact built from the supplied source and pinned under `third-party/`. It selects AnySearch for `web_search` and `web_fetch`, while base, headless, and SDK defaults remain unchanged. The Web patch disables the inherited `web-search-deepseek` row, so Web and desktop do not register an unused second search provider or expose its settings namespace. The plugin's three advanced tools register globally; a reviewed compatibility patch removes its global `web_fetch` fallback so each session preset retains ownership of standard-tool availability and guidance. Scoped peer overrides keep the tested workspace services as the only implementations. The Web search settings card writes its optional credential through the DSH credential store and its endpoint through the `web-search-anysearch` settings section; the client snapshots both for each operation. The optional `ANYSEARCH_API_KEY` is resolved at each operation; absence means anonymous remote access, not an offline service or an installer-provisioned account. Queries and extraction URLs leave the machine for the configured endpoint, whose quotas and authentication failures remain visible without an automatic provider switch.

`@deepseek-ai/dsh-web-app` directly depends on and mounts the reviewed `@dickpy/dsh-imagegen` 1.5.1 runtime repack, `@xmanrui/dsh-im` 1.0.3, `dsh-plugin-cron` 0.1.3, `dsh-skill-mcp-panel` 2.0.1, and `dsh-univer-office` 0.2.12 DSH-rebuild tarballs retained under `third-party/`, plus published `@huanlin/dsh-plugin-better-sidebar-plugin-office` 0.1.2. Image generation contributes its browser studio and four Host tools; the preview package follows the built-in better-sidebar row so it registers DOCX, XLSX, and PPTX viewers against the existing file-viewer registry; Univer separately contributes agent editing tools, bundled skills, a Gateway, a Viewer, and conversation review cards. These packages are part of the ordinary Web production closure and therefore also part of the [Windows desktop installer](2026-08-25-windows-desktop-updates.md); users do not install them into a profile. Image-provider configuration and secrets, IM configuration and credentials, cron records, bot routing state, skill files, MCP configuration, Univer content, worktrees, resource caches, and all other mutable data remain outside the executable closure, so a machine migration copies that state separately when it should move. Image-generation settings use the local settings document, while its history, gallery, and template cache live under `~/.dsh/dsh-imagegen`.

The same Web composition mounts `@deepseek-ai/dsh-skill-ppt-master`, an immutable provider for the upstream PPT Master 6.1.0 skill. The package retains the complete upstream directory—including scripts, references, layouts, images, sounds, license, sponsor records, dependency declaration, and integrity guard—and derives its `path` and `resourceBase` from the installed package rather than copying resources into `DSH_HOME`. Source builds and the desktop EXE therefore load one fixed `bundled` catalog entry from the same package-relative layout. The installer does not create a Python environment or install workflow-specific packages; operators provide a compatible `python3` runtime and the dependencies required by the selected PPT Master route.

The image-generation artifact is a runtime-only repack of the upstream 1.5.1 npm release. It keeps the unchanged compiled Host and Client bundles, 441-case template snapshot, package metadata, bundle patch, README, and Apache-2.0 license while omitting non-runtime screenshots, demonstration video, TypeScript sources, and source map. The repository compatibility patch registers the installed Client card through `settings.models.specialized-model` at order `-10`, titles it **Image generation model**, keeps it collapsed until clicked, and updates Host and Client configuration guidance to **Settings → Models → Image generation model**; it does not register `settings.plugin.item`. Its settings surface still records API keys in the local settings document. Generation requests send prompts and any reference images to the configured OpenAI-compatible service, and the installer contains neither that service nor its models. The skill/MCP release artifact receives a repository patch that replaces obsolete client injections and session lookup with this DSH revision's renderer and session-controller APIs. The Univer artifact is rebuilt from the supplied 0.2.12 source: its embedded development-license fallback is empty, and only `UNIVER_LICENSE` from the application environment reaches the Viewer, Gateway, render process, and unit-content worker. The shipped Univer row sets `telemetry: false`. Its Viewer assets, processes, skills, resource manifest, and Windows x64 native bindings remain ordinary production dependencies so the desktop payload gate can require them explicitly. The Univer wrapper is Apache-2.0, while its executable closure has three external `@univerjs-pro/*` runtime roots and 90 separately licensed modules inlined by its build script—79 `@univerjs-pro/*` and 11 `@univer-cli/*`. The compiled tarball carries neither their individual manifests nor their notices. The generated third-party notices enumerate the declared identities, pin the build-time declaration digest, and require a new review when it changes. A valid commercial license and appropriate production and distribution rights must cover the closure. Chrome or Chromium remains an external prerequisite for Slide operations that perform browser rendering and can be selected with `UNIVER_RENDER_BROWSER`.

The upstream plugins retain their own runtime ownership. Image generation owns provider channels, model catalogs, generation requests, history, gallery, templates, four model tools, and `/edit_image`; IM continues to own platform connections, QQ settings, mobile-notification routing, and `qq_send_local_file`; cron continues to own its general command schedules, history, management surface, and four model tools; the skill/MCP panel owns skill-file operations, its CLI, and the managed MCP block in the selected profile patch; Univer owns its thirteen tools and review lifecycle. Bundling changes availability, not those responsibilities. The [mobile workbench reminder decision](2026-08-22-mobile-workbench-reminders.md) still keeps reminder timers and acknowledgement in the workbench document rather than mirroring them into cron. The [built-in better-sidebar decision](2026-08-23-built-in-better-sidebar.md) still owns the workbench mount and duplicate guard; this decision accepts both the Office viewer's AGPL-3.0 distribution obligations and the separate Univer commercial runtime obligations and keeps them in generated third-party notices.

`@deepseek-ai/dsh-speech` defines a provider-selecting Host capability and the typed `speech.transcribe` Remote. `@deepseek-ai/dsh-speech-qq` registers provider `qq-config`. For every recording it re-reads `integrations/dsh-qq/config.json` and resolves `DSH_QQ_ASR_API_KEY` through the credentials service, so changes saved under **Settings → Models → Voice model** affect the next request without a Host restart. The bundled IM client registers that collapsed card through `settings.models.specialized-model` immediately below Tool model and no longer renders ASR fields under Connected Platforms → QQ. The adapter submits one OpenAI-compatible multipart transcription request with the configured model and language and returns only normalized non-empty text plus provider identity. dsh-im remains the sole owner of ASR endpoint, model, language, enablement, credential input, and persistence; the [durable Teacher Workbench decision](2026-08-17-durable-teacher-workbench.md) no longer owns a speech-language setting.

Composer and Teacher Workbench controls share one MediaRecorder hook. Each operation requests microphone access, collects one complete WebM, Ogg, MP4, MP3, or WAV blob, and releases every media track. Standard or WebKit AudioContext decoding then converts non-WAV recordings to 16 kHz mono PCM WAV before canonical base64 encoding and the Host Remote call; a host without that decoder retains the original MediaRecorder container. This makes the browser path use the same broadly accepted WAV input as QQ voice attachments instead of assuming that a local OpenAI-compatible ASR implementation can decode Chromium WebM. Recording, preparation, or transcription blocks conflicting submit actions, while accepted text remains editable through the same draft, task, memo, or ledger path as typed text. Audio bytes and provider responses are never persisted or logged.

The QQ adapter accepts HTTPS endpoints and loopback HTTP only. It rejects embedded credentials, query strings, fragments, and redirects; bounds decoded audio and response bytes; validates canonical base64, media types, model, language, HTTP status, and response JSON; enforces a request deadline; and returns stable diagnostics without provider response bodies, credentials, or audio. Transport failures return `provider-unavailable`, while invalid settings, redirects, and non-success HTTP statuses return `provider-failure`; both browser Consumers present the latter as a request/settings failure rather than a network outage. These checks keep browser microphones and QQ secrets outside third-party client code even though the selected ASR service receives each complete recording.

## Alternatives considered

**Keep the bundled extensions and PPT Master as profile installations.** This preserves a smaller application dependency closure but makes a fresh EXE installation incomplete, lets profile state silently change the shipped UI, tool roster, and skill catalog, and requires a second installation procedure on every computer.

**Treat an image-capable entry in the ordinary Models provider list as image generation.** That registry describes conversation-model inputs and does not register a generation protocol, provider channel, image tools, gallery, or result renderer. The dedicated Image generation model card exposes plugin-owned configuration without inferring those operations from an LLM provider row.

**Ship only PPT Master's `SKILL.md`.** Its routes depend on packaged scripts, references, templates, and media, while its attribution guard requires the complete official attribution and execution-gate set. A body-only copy would advertise a workflow that fails as soon as it follows its own resource paths.

**Copy PPT Master into `DSH_HOME` on first launch.** A startup copy would turn versioned application resources into mutable user state and create ownership conflicts between user edits, upgrades, and reinstalls. A package provider keeps release resources immutable and leaves `DSH_HOME` for user-owned skills and configuration.

**Embed plugin configuration and user data in the installer.** Executable code is reproducible build input; tokens, bot sessions, cron records, and local work are mutable private state. Shipping or replacing them would leak credentials and make upgrades destructive. `DSH_HOME` remains the explicit migration unit for that state.

**Retain Web Speech API recognition for application controls.** This delegates provider, retention, language behavior, and browser availability to each browser while QQ already exposes an operator-selected ASR endpoint. One Host capability makes both UI surfaces use the same settings and validation.

**Call the QQ ASR endpoint directly from each browser component.** This would expose credentials to renderer code, duplicate multipart validation and limits, require cross-origin access, and make provider replacement a UI change. The shared Host Remote centralizes transport and keeps Consumers provider-neutral.

**Keep ASR configuration inside Connected Platforms → QQ.** That location follows its persistence implementation but hides a model shared by QQ, the composer, and Daily Management behind one bot page. The Voice model card makes the product-wide role visible without changing the persisted document, credential reference, or Host Remote.

**Forward each MediaRecorder container unchanged.** OpenAI's service accepts common browser containers, but compatibility endpoints are not uniform. QQ voice attachments already arrive as WAV, so a local service can recognize the bot while hanging or failing on the browser's WebM/Opus. Browser-side decoding avoids an executable transcoder in the installer and keeps the Host provider independent of browser codecs.

**Infer or retry another ASR model.** OpenAI-compatible model-list responses do not identify speech models uniformly, and choosing a different model would override the operator-owned QQ setting. The adapter sends the configured model exactly once and reports a rejected request so the operator can select an installed model explicitly.

**Bundle the ASR server, MinerU, vLLM, models, and GPU runtime into the EXE.** Those services depend on deployment-specific hardware, drivers, model storage, and update policy. The installer contains their clients and configuration adapters, not the services themselves; service containers and the Windows application remain separate deployment units.

## Consequences

- A standard Web source build or Windows installer exposes the AI image studio, four image-generation tools, IM, general cron, skill/MCP management, Office preview, Univer authoring, and the complete `ppt-master` skill without `dsh plugin add`; the shipped-composition test pins the Host tools, all six client modules, and the bundled skill entry so a composition omission fails before release.
- PPT Master's 12,939-file, 79,496,215-byte logical resource tree increases the application closure and installer input. Installer compression may reduce the artifact size, but release storage and Windows extraction still account for the complete tree.
- Loading the PPT Master instructions works immediately after installation. Executing a route still requires an external compatible Python runtime and any optional packages or executables that route selects.
- Moving the complete working environment still requires copying the intended `DSH_HOME` state and `~/.dsh/dsh-imagegen`, then provisioning reachable image-generation, QQ ASR, MinerU, and model services. Installing only the EXE moves application code, not private data or GPU services.
- Models shows a collapsed Image generation model card immediately below Tool model, followed by the collapsed Voice model card. The former exposes the plugin's channel, model, endpoint, key, prompt-enhancement, and switch settings; Plugins no longer duplicates it. Connected Platforms → QQ retains bot and workspace settings but no longer duplicates the ASR form; existing image and speech values continue to load from their original storage.
- Composer and daily-management voice input behave consistently across browsers that support MediaRecorder. Web Audio hosts additionally buffer decoded PCM and one 16 kHz mono WAV before sending it through the Host; the 20 MiB audio limit and operation deadline bound the transmitted recording, while streaming and partial transcripts remain unsupported.
- A QQ platform transcript can satisfy a bot voice message without contacting the configured ASR service. Browser microphone input is the direct endpoint check, and an unavailable configured model produces the settings/request notice instead of the network notice.
- Office preview introduces an AGPL-3.0 runtime dependency. Repository and downstream distributions must retain its notices and comply with its license; this consequence is accepted to make the requested preview part of the default installation.
- Univer Office keeps commercial distribution rights and local Chrome/Chromium as prerequisites for licensed deployment and browser-rendered Slide operations. The [Viewer evaluation decision](../bug-fix/2026-09-01-univer-viewer-evaluation.md) permits startup without `UNIVER_LICENSE` under upstream limits. The installer contains neither a license value nor a browser executable, and the built-in composition disables Univer telemetry.
- The integration consumes published third-party plugin interfaces and pinned artifact versions. Upgrading those artifacts requires another compatibility, license, tool-roster, and shipped-client audit.

## Testing

The AnySearch integration suite boots the real shipped Web Loader composition against a local HTTP fixture. It requires the AnySearch settings namespace and the absence of the inherited DeepSeek search namespace, then covers anonymous search and extraction, both capability catalogs, advanced search, live settings changes for the endpoint and credential reference, rejected-key handling, partial batch results for quota and rate limits, and credential-bearing redirects. The Plugins-page browser scenario stores the key through credentials without exposing it in the settings document and confirms the saved status on reopen. The recorded Web search session uses the real AnySearch provider, pins the durable capped source list and browser card, and replays without API keys. Payload tests reject every missing AnySearch runtime file; publication checks accept only the reviewed archive path. The supplied source's own typecheck, tests, build, and package-content check also run before the archive is pinned.

Capability tests cover provider selection and disposal, live QQ configuration and credential reads, endpoint restrictions, cancellation, multipart fields, supported media, size and response limits, transport and HTTP failure classification, JSON failures, and safe diagnostics. Client tests cover MediaRecorder support and teardown, SSR, PCM WAV headers, stereo downmixing, resampling, decoder selection and cleanup, composer gestures and submit blocking, workbench commands, editable transcripts, and distinct connection and rejected-request notices. The Models browser scenario requires the collapsed Image generation model card below Tool model and the Voice model card after it, expands the former to require channel controls, saves every ASR field and credential through the latter, and confirms the persisted speech document contains no secret. The Plugins browser scenario confirms that image-generation configuration is absent there, and the QQ workspace scenario confirms speech fields are absent from Connected Platforms → QQ. A keyless assembled Web scenario records deterministic audio in both the composer and Daily Management, converts it in the real browser bundle, requires WAV multipart uploads through the generated Remote to a local QQ-compatible ASR server, and pins both successful transcripts and rejected-model notices without a model call. The PPT Master package test loads the real provider and fixes the upstream version, license digest, integrity-gate marker, file count, and logical byte count. The shipped-composition scenario requires the four image-generation tools, IM and cron Host tools, all thirteen Univer tools, all six bundled client modules, and the loadable `ppt-master` catalog entry. The desktop payload tests require the image-generation Host and Client bundles, template snapshot, and license, the skill/MCP package, representative files across the complete PPT Master distribution, and Univer's Viewer, Gateway, workers, skills, commercial assets, and Windows x64 native bindings before the Windows workflow builds the same production dependency closure into its NSIS artifact.
