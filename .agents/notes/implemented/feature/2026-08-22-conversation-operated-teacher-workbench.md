# Agent Note: Conversation-operated teacher workbench

Status: implemented

English | [中文](2026-08-22-conversation-operated-teacher-workbench.zh.md)

> Extends [Durable Teacher Workbench](2026-08-17-durable-teacher-workbench.md), [Reusable Document Extraction](2026-08-18-reusable-document-extraction.md), and [Agent-loop Question Segmentation](2026-08-21-agent-loop-question-segmentation.md). Their storage, OCR, and semantic-boundary decisions remain current.

## Problem

The teacher workbench and ordinary conversation used separate control paths. A teacher could ask the agent about an OCR upload, but changing a task, timetable, roster, exam, or question library still required reopening the corresponding workbench surface and repeating the operation manually. PDF question cutting had an additional gap: hidden OCR Markdown gave the parent agent readable text but not the original PDF bytes needed to render trustworthy crops.

The conversation path must use the same revision checks, relationship validation, cascade behavior, media storage, and document generators as manual workbench actions. Upload bytes must not enter the textarea, model prompt, or Session log, while a later tool call still needs a durable reference to the exact PDF selected in the browser.

## Decision

`@deepseek-ai/dsh-tool-teacher-workbench` is the model-facing Consumer of `@deepseek-ai/dsh-host-teacher-workbench` and registers seven global tools: `teacher_workbench_read`, `teacher_question_image_read`, `teacher_daily_management`, `teacher_timetable`, `teacher_student_roster`, `teacher_score_analysis`, and `teacher_question_workbench`. The separate `tool-*` package keeps every schema inside the generated tool-catalog completeness check. The section reader returns one selected section and its stable ids. When durable attachments are available, the image reader resolves one stored batch or assignment raster, reports its source dimensions, and returns it as an image attachment only after the current model route declares image input. Mutation tools operate on the authoritative revisioned document, retry compare-and-set conflicts against the latest revision, and return the committed revision, a short summary, and created ids. They use the existing service operations for question media, assignment, and Office generation. The schemas expose explicit action vocabularies while action-specific payloads are validated again before persistence.

Daily Management supports task, memo, ledger-category, ledger-entry, and calendar-item creation, editing, deletion, completion, rescheduling, and calendar import. Its tool routes only from literal request words: `备忘`, `备忘录`, or `memo` selects memos, Today/task words and importance or urgency words select those task lists, billing or insurance words select ledger actions, and calendar words select calendar actions. For every creation, the Host reads direct user text from the current agent turn, derives the route independently of model arguments, and rejects an action that does not match it. A new item without a routing word is not written until the user names its destination. The tool does not infer a list from content, deadlines, tone, or consequences, and edits retain their existing destination. Timetable requires an explicit `week` or `grade` view: Today, Week, and Study use the `timetable` class catalog, while only the explicit Grade view uses `gradeTimetable`. Timetable mutations reject class ids from the other catalog and duplicate class/kind/weekday/period slots within one import, then read the affected ids back before returning a confirmed view and revision. Student Roster supports roster classes and identity-preserving student import. Score Analysis resolves every row to exactly one durable student in the selected roster class before replacing an exam. Question Cutting supports PDF segmentation, folder and media deletion, rotation, source-pixel cropping, sampled-background rectangle erasure, assignment, and Word or PowerPoint generation. Crop and erase replace only the selected stored image; erase accepts at most 32 positive rectangles and validates every bound before committing any replacement. Its local-directory action recursively reads images through the mounted filesystem provider and generates one artifact without creating a student, folder, assignment, or temporary selection. Existing schema validation and deletion cascades remain the final authority for cross-module relationships.

Conversation document intake continues to extract every supported file through the configured OCR provider and injects accepted Markdown as logged `mineru-ocr` context. A PDF upload also calls `teacherWorkbench/stageSource` before Send becomes available. The Host validates canonical base64 and the configured decoded-byte limit, stores the bytes in a private content-addressed object root, verifies the digest on every read, and returns an opaque `sha256:` source id. The logged document context carries that id, display name, and media type; neither the original bytes nor a server path reaches the model.

The question tool resolves a staged PDF by source id, copies selected pages into requests bounded by the selected OCR provider's limits, obtains MinerU geometry, invokes the existing restricted semantic-boundary child under the calling agent, renders accepted regions from the original PDF on the Host, and saves one durable paper batch. It has no default destination: the current direct user request must explicitly name the question-library root or one complete existing leaf path. The model submits the corresponding root choice or durable folder id, and the Host matches it against the logged current-turn text before OCR begins; a missing or guessed destination is rejected with an instruction to ask the user. The Web cutter independently retains its automatic or selected directory behavior. Its Office actions distinguish three sources: an ordinary local directory needs only its filesystem path, stored batch or assignment images use durable target ids, and per-student generation uses assigned or temporary student selections. Omitted per-student source and Word metadata follow the Question Cutting UI: temporary images, an empty title, and no name or date; all assigned images require an explicit source. Every path reuses the Host image normalization, question-number/natural sorting, byte limits, and Office renderer. Outputs are written below a private generated-output root and returned as absolute paths. Opening the browser workbench or changing its active module refreshes its Host document so conversation mutations replace a cached snapshot.

## Alternatives considered

**Teach the agent to imitate browser Remote calls.** Browser orchestration contains transient review state and assumes a mounted UI. Model tools need stable action schemas and Host validation, not instructions to reproduce client control flow.

**Put all five modules behind one unrestricted document replacement tool.** A complete arbitrary state payload increases token cost and lets one mistaken call erase unrelated data. Section reads and semantic actions constrain each mutation while retaining the existing whole-document atomic write underneath.

**Place the original PDF bytes in conversation context.** Base64 would enlarge every request and Session log, expose private source bytes to the model provider, and still require decoding and validation at tool time. A logged opaque id preserves replayable intent while private Host storage retains the bytes.

**Reconstruct question images from OCR Markdown.** Markdown does not preserve page geometry or original pixels. The existing MinerU-layout and Host-derived crop authority remains necessary.

**Default to the configured question-library root.** This avoids creating a directory but still chooses a destination the user did not request and mixes unrelated papers at the root.

**Reuse the Web cutter's automatic source-name directory.** A conversation request has no save-directory control, so creating a folder from an implicit UI default adds an unrequested hierarchy.

**Stage an arbitrary image directory under a student before generating it.** This invents a roster relationship that the user's source does not have and makes a one-file directory conversion depend on mutable assignment state. The local-directory action keeps source images ephemeral and uses the same generator without changing workbench data.

**Poll the workbench continuously for agent changes.** The workbench replaces the center conversation surface, so opening it or selecting a module is the synchronization point. Those bounded reads observe tool mutations without a permanent browser timer.

## Consequences

- Ordinary conversation can perform the five requested workbench workflows, while manual and agent actions share one authoritative revision and validation path.
- A timetable action cannot report a Week import after writing the Grade catalog or silently collapse repeated morning and afternoon period numbers; the model must correct the destination or period mapping before persistence succeeds.
- Roster, timetable, and score imports consume the hidden OCR context already admitted with the user message. Multimodal models may read attached images directly and then call the same mutation tools.
- A stored-question image read adds one durable image attachment to the tool result and later Session history. Text-only routes fail before reading or attaching the raster; image-capable routes receive both source dimensions and any attachment-preview scaling needed to submit source-pixel edits.
- Conversation PDF cutting cannot begin until the current user request names its save destination; choosing a root or complete leaf path may therefore add one clarification turn.
- PDF sources persist independently of Session retention below `sourcesRoot`. Content addressing deduplicates identical uploads, but automatic expiry and garbage collection remain deferred.
- Agent-generated Office files are private Host artifacts below `generatedRoot`. The tool reports their paths; browser download handoff remains deferred.
- Local-directory generation can read nested images outside the session cwd when the mounted filesystem provider permits it. It rejects paths escaping the selected directory, cycles, oversized inputs, and more than 120 images; source bytes remain ephemeral.
- Seven additional tool schemas increase every ordinary Web model request prefix. Question cutting additionally incurs MinerU extraction and one semantic child per configured page group.
- The workbench document is deployment-global today, so source and generated roots follow the same single-workbench deployment scope rather than introducing a separate user-authorization model.

## Testing

Host tests pin all seven registrations, section reads, image-capable and text-only route handling, durable image result rendering, valid and out-of-bounds rectangle erasure, semantic create/edit/delete/import actions, Week/Grade catalog separation, duplicate-slot rejection, timetable read-back confirmation, score identity resolution, conflict retry, question-folder and image operations, assignment, local-directory Office generation, per-student browser-compatible defaults, explicit assigned-image selection, output storage, content-addressed source integrity, missing or guessed question-save destination rejection, and an actual PDF-to-question-batch flow with deterministic OCR geometry and semantic boundaries. Conversation tests pin parallel PDF extraction and staging, Send gating, and logged source metadata. API tests pin the prompt framing and wire schema. Client component tests pin a fresh Host read when the workbench opens or changes modules. A keyless assembled Web snapshot pins the seven model-visible tool names, stored-image read description, timetable routing instruction, and Question Cutting action descriptions alongside the existing semantic question-segmentation child.
