# Agent Note：后台试题切割队列

状态：已实现

[English](2026-08-24-background-question-cutting-queue.md) | 中文

## 问题

PDF 版面提取、语义分割、题图渲染与持久化原本由已挂载的试题切割组件持有。上传入口会一直阻塞到完整流程结束，教师无法继续提交下一份 PDF。离开模块后，唯一进度界面会被移除，后续重新挂载的界面也无法观察已经接受的工作。

试题切割还依赖浏览器持有的 `File`、PDF.js、canvas 渲染、当前父会话、所选目录和接受任务时可见的设置。可跨导航的设计必须保留这些值，同时不能让后续会话或变化后的界面选择改投已有任务。

## 决策

客户端插件在完整生命周期内持有一个 `QuestionCuttingController`。控制器是与 React 兼容的 observable，按上传顺序提供不可变进度行。入队时锁定浏览器 `File`、所选页码、目标目录、渲染设置、页码面板中的思考选择，以及已经绑定当前父会话和该思考选择的分割与裁剪复核执行器。每个执行器都会在所有 Host 请求中携带锁定值，由 Host 用它覆盖可变的插件默认值，以完成题界识别、视觉复核与修复阶段。挂载组件只提交请求并投影 observable；工作进程的执行不归组件挂载与卸载所有。

一个顺序工作进程依次处理已接受的 PDF。版面提取、语义分割、题图渲染与保存会按具名阶段发布单调递增的整数进度，同时报告已保存图片数和最终错误。等待行的计时保持为零；中间工作区用工作进程开始时间与最终结束时间计算活动与终态计时。确认页码面板后会立即清空本地选择，因此活动行继续处理时可以读取并加入下一份 PDF，后续任务以等待状态显示。

大文件采用内存有界路径。PDF 超过 OCR 提供方单文件上限时，会通过临时 Blob URL 打开，而不是整体复制成一个 JavaScript `ArrayBuffer`；一个可复用 PDF.js 文档把所选页面逐页栅格化为独立 OCR 请求，并立即释放各页画布。语义题界识别只消费 OCR 几何，不会长期保留整份文档的 Base64 页面预览。随后由第二个可复用 PDF.js 文档逐语义组完成复核、渲染、分片和持久追加。内存中只保留当前组的检查页与题图，进度行会显示已完成组数和总组数。

插件释放时会停止接收任务，丢弃尚未开始的工作，移除观察者，并等待活动任务结束后再释放控制器。队列与浏览器持有的源文件不会跨完整页面刷新或应用关闭持久化；已提交的图片分片仍是 Host 所有的持久数据。

## 考虑过的替代方案

**把队列保留在组件 state 或 ref 中。** 这种方案只能在同一组件保持挂载时支持重复上传，切换模块或会话仍会丢失所有权与进度投影。

**把每次切割做成持久 Host 作业。** 这需要为完整源 PDF 增加新的上传与恢复协议，或者把 PDF.js 与 canvas 裁剪流程移出浏览器。当前所需生命周期是 Web 插件持续运行期间的界面导航，因此只有未来明确要求跨刷新或进程退出恢复时才引入这项更大能力。

**并发运行全部已接受 PDF。** 并发 PDF.js 栅格化、OCR 请求、语义子会话和文档修改会提高内存消耗与资源争用。顺序执行仍允许连续提交，并为每个等待行提供明确位置，同时不会阻塞无关工作台操作。

## 结果

切换工作台板块或对话不会取消、永久隐藏或改投已经接受的切割任务。返回试题切割后会观察同一组进度行、百分比、组计数与计时。连续 PDF 可以采用不同的思考选择；修改持久化默认值只影响后续页码面板，不能改变已经接受的任务或其后续复核阶段。较长队列会在浏览器内存中保留源 `File`，并且每次只执行一份 PDF；活动 PDF 的图片内存则被限制在一个语义组内。每个非空组都会在下一组开始前提交，因此后续失败不会丢弃先前已保存图片。最终状态行在当前插件生命周期内保持可见，完整刷新后则从空队列开始。

## 测试

控制器覆盖会保持第一份 PDF 的版面提取未完成，再以相反的思考选择接受第二份 PDF，验证两组执行器都取得各自不可变的值，移除订阅者，并确认任务按顺序结束；它还验证一份 PDF 失败后不会阻塞下一任务，以及多个语义组会通过同一个可释放栅格器按顺序复核并保存。栅格覆盖验证通过 Blob URL 加载且不复制源字节、超限源文件逐页流式 OCR、较小源文件按提供方上限生成 PDF 批次，以及基于画布的题图渲染。组件覆盖固定中间区域的百分比、组计数、阶段与计时投影，并验证确认目标目录时会把所选思考值加入队列且不会禁用下一次上传。Host 覆盖验证显式分割与复核值会覆盖配置默认值。组装 Web 场景会挂起真实 MinerU 响应，提交两份 PDF，记录两行进度，再切换板块与对话，并确认这些进度行仍属于持续运行的插件。
