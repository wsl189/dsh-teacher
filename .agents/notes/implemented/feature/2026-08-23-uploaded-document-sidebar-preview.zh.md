# Agent Note: 在 better-sidebar 中预览上传文件

Status: implemented

[English](2026-08-23-uploaded-document-sidebar-preview.md) | 中文

## 问题

MinerU 提取期间，输入框会把上传文件保留为浏览器 `File`，但文件行只显示名称、提取状态和移除控件。用户无法在发送前检查所选文件。工作区查看器不能直接解决该问题，因为它们接受 Host 文件系统路径，而未发送的上传文件没有工作区路径，也不应只为呈现而创建路径。

## 决策

`ui-conversation` 通过现有 `conversation.input.attachments` owner share 传递仅运行时存在的文件记录、浏览器文件解析器和移除控件。没有附件呈现插件占用该 slot 时，InputBar 保留不可交互的文件行回退。

`ui-attachment` 可选注入 `betterSidebar`，并注册隐藏的 `dsh:uploaded-document` 标签页类型。选择输入框文件卡片会记录其浏览器来源并打开会话定向的标签页，从而展开右侧面板；同一草稿文件已有标签页时，系统会聚焦该标签页。控制器把 `File` 保存在内存 map 中，而不是持久化标签页元数据。移除记录、成功接收提示词、停用插件，或重载后恢复的标签页缺少浏览器来源时，系统都会关闭该标签页。

预览会直接读取不可变的浏览器文件。PDF 使用浏览器原生查看器，常见图片使用 Blob URL，DOCX 使用 `docx-preview`，PPTX 使用 Office Kit 并清理 SVG 输出，XLSX 则渲染经过 React 转义且最多 200 行、50 列的表格。每个来源都提供 Blob URL 下载操作。动态客户端构建会把 `fflate` 与 JSZip 映射到浏览器入口，因为工厂产物采用 CJS 输出，不能保留 Node 核心模块请求。该能力只覆盖输入框上传文件；工作区 Office 文件仍由[内置工作台决策](2026-08-23-built-in-better-sidebar.zh.md)所述的外部查看器负责，工作区产出文件则继续采用[移除产出文件预览的决策](../simplification/2026-08-22-remove-web-produced-file-preview.zh.md)中的原生打开行为。

预览不会在工作区暂存副本、调用 Host 文件读取路由、改变 OCR 上下文或新增会话事件。文件只在未发送草稿记录的生命周期内可用。

## 验证

conversation 测试固定通过附件 slot 传递的文件记录与文件解析器。附件组件测试固定点击、移除与对账行为；控制器测试固定隐藏标签页注册、定向打开、去重身份与过期标签页关闭；预览测试固定格式路由、Blob URL 渲染、下载与 URL 回收。附件客户端组合包会以内联 Office 渲染器且不含 Node 核心模块导入的方式完成构建；Web 组合则在 Chromium 中上传真实文件并打开其右侧栏标签页。

## 考虑过的替代方案

**把每个上传文件暂存到工作区并复用文件查看器。** 这种方案会仅为临时读取操作增加文件系统写入、命名策略、清理生命周期和用户可见的工作区残留。

**要求外部 Office 查看器接受浏览器 Blob URL。** 已安装的查看器拥有工作区路径，并通过 better-sidebar 的 Host 路由读取。让输入框依赖该可选 AGPL profile 扩展，会使标准 Web 组合缺少所需操作，并把草稿生命周期耦合到第三方组件约定。

**恢复通用产出文件预览 RPC。** 浏览器已经拥有上传字节，因此 Host 整文件读取与产出文件选择状态只会增加授权和生命周期工作，不能为该调用方带来收益。产出文件与未发送上传文件继续保持不同的所有权和释放规则。

## 后果

标准 Web 用户可以直接从文件卡片检查 PDF、DOCX、XLSX、PPTX 和常见图片上传文件，即使 OCR 仍在运行也可以，而且不需要外部 Office 查看器。附件客户端组合包会携带 Office 解析器与渲染器依赖，复杂 Office 布局可能与 Microsoft Office 不同；该预览只用于辅助阅读，不是编辑或像素级保真界面。浏览器保留的字节始终为临时数据，并随草稿消失。
