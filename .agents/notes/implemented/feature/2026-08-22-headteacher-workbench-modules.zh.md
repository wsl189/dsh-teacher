# Agent Note: 持久化班主任工作台模块

Status: implemented

[English](2026-08-22-headteacher-workbench-modules.md) | 中文

## 问题

班主任分组已经显示家校沟通、班级记录、谈话记录、排座位和班级总结入口，却没有完整工作区。教师无法在 dsh 内编写可复用家校通知、保存三类跟进记录或为班级名册排座位；只在浏览器中实现还会在重载后丢失工作，并让多个窗口的修改静默冲突。

## 决策

版本 8 的 `teacher_workbench` 文档持有 `noticeTemplates`、`notices` 与 `seatingLayouts`，并把可复用记录模板类型扩展为包含 `class`、`talk` 和 `summary`。家校沟通初始提供八种可编辑校园场景模板，根据明确填写的称呼、时间、事实与署名生成仍可由教师修改的微信群初稿，并持久化已保存草稿供后续复用。生成初稿包含隐私与事实复核提醒，且不会自动发送。

班级记录、谈话记录和班级总结共用一套记录实现，同时分别筛选独立模板类型。每一类初始提供三种学校实务模板，并支持新建、编辑、复制和删除模板，以及新建记录、设置跟进日期、切换状态和后续编辑。共用存储与界面代码不会合并三套可见模板库或记录。

排座位复用名册班级与学生，可经共享文档提取路径导入名单，支持 3–8 排、4–10 列、随机分配、拖拽交换、手动腾空、重置和教师视角图片导出。每个名册班级只持有一份持久化座次。Host schema 要求座位数等于 `rows * columns`，拒绝其他班级学生和重复安排；删除班级会移除座次，删除学生会清空该生座位。

所有已接受修改都通过生成的 `teacherWorkbench` Remote 和现有整份文档比较后写入修订完成。模板选择、未保存草稿、拖拽状态和已打开编辑器仍只留在浏览器中。

## 考虑过的替代方案

**保留导入工作台的 Local Storage 模式。** 这种方案会绕过已配置的存储后端、跨窗口冲突处理、Host schema 校验与班级／学生级联规则。

**把通知和座次表示为通用记录。** 通知需要可复用消息文本，座次需要带学生引用的固定网格。把两者编码成自由记录字段，会让精确校验、拖拽更新与图片导出依赖文本解析。

**为三类记录分别实现一套界面。** 编辑、模板、状态和跟进机制完全相同。共用实现可让这些机制保持一致，持久化类型判别仍能维持独立模板库。

## 后果

存储 domain 格式从 7 增加到 8，并按预发布策略拒绝旧媒介而不迁移。家校初稿、记录和座次可跨重载保留，并与工作台其他数据一样参与明确的修订冲突处理。排座位仍是由教师控制的安排工具，不推断学生特征、成绩或行为。

聚焦的 Host、控制器与组件测试覆盖初始模板、schema 拒绝、级联行为、数据修改、通知生成、记录编辑器与座次持久化。无密钥 Web 快照通过交付 Web 传输保存家校通知、在每一类中新建一条记录、随机分配基于名册的座次，重载应用并核对 Host 状态。
