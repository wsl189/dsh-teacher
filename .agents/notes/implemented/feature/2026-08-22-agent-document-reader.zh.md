# Agent Note: Agent 通过 OCR 自主读取文档

Status: implemented

[English](2026-08-22-agent-document-reader.md) | 中文

## 问题

对话上传会在用户提交提示词前提取文档，但 agent 在工作时也可能通过路径发现 PDF 或 Office 文件。没有面向模型的文档读取器时，agent 可以列出或定位文件，却无法让已配置的 OCR 提供方读取它。直接使用 Node 文件系统会绕过既有 `read` 与 `read_image` 工具采用的会话工作区解析和文件系统提供方。

浏览器上传路径仍然必要，因为浏览器本地文件没有 agent 可读取的工作区路径。基于路径的自主读取是同一 `ctx.ocr` 能力的独立消费方，不取代上传状态、隐藏提示词上下文或教师复核。

## 决策

`@deepseek-ai/dsh-tool-fs` 只在 `ctx.ocr` 已挂载时注册 `read_document`。它唯一的模型参数是 `file_path`，接受 PDF、DOCX、PPTX、XLSX、PNG、JPEG、WebP、BMP 与 TIFF 扩展名。工具通过 `ctx.fs` 相对调用会话工作区解析路径，要求目标是普通文件，取得所选 OCR 提供方的解码字节上限，并先以该上限调用 `ctx.fs.readBytes`，再生成规范 base64。随后调用同进程操作 `OcrRuntime.extractAbortable(request, exec.signal)`，使取消能够到达所选提供方。

规范工具值包含后端展示路径、媒体类型、提供方 id、阅读顺序 Markdown 与截断标记。Native 渲染把 Markdown 包装在文档信封中。提取成功后发送 `fs/observed`；不支持的格式、文件系统失败、提供方选择失败与提取失败保持为结构化工具错误。并发调用是安全的，因为它们读取相互独立的不可变输入，并且只在成功后更新同步观察记录器。

`read_document` 归属文件系统工具包，因为模型从工作区路径开始，必须获得与相邻文件读取器相同的逐会话解析、普通文件校验、取消、观察和读取展示意图。OCR 提供方选择仍归属 `ctx.ocr`；工具不导入或点名 MinerU 行为。Web 组合包中的 `ctx.ocr` 显式选择提供方 id `mineru`，因此每个标准 Web agent 都获得由 MinerU 支持的 `read_document`。没有 `ctx.ocr` 的组合不会获得文档工具或相关提示词指引。

现有[可复用文档提取决策](2026-08-18-reusable-document-extraction.zh.md)继续拥有浏览器上传、隐藏对话上下文和带复核的工作台导入。该决策否决的是用模型工具替代这些人类输入流程；基于路径的工具是补充方案，无法访问仅存在于浏览器中的 `File`。

## 已考虑的替代方案

**让每个 OCR 提供方注册自己的工具。** 面向模型的名称和 schema 会随提供方组合改变，并在已有提供方无关服务负责选择的情况下暴露供应商身份。

**通过 Node API 读取文档字节。** 这只适用于本地主机，还会绕过 `ctx.fs` 路径身份、远程后端、会话 cwd 处理、类型化错误和观察策略。

**在没有 OCR 服务时仍挂载 `read_document`。** 一个始终报告提供方不可用的永久可见工具会增加 schema 成本，并诱使有意省略文档提取的 Headless 或自定义组合发起失败调用。

**用 `read_document` 替代浏览器上传。** 浏览器所选文件没有工作区路径，名册、成绩与日历导入也要求在持久化前提供可见提取状态和复核。模型工具无法提供这些人类控制项。

**创建独立的 `tool-ocr` 包。** 当前操作完全属于文件系统读取，并共享既有文件读取器机制。独立包会在没有独立输入类别时复制这些机制；若 OCR 将来接受 URL、附件 id 或已保留文档句柄，独立包仍可能合适。

## 后果

- Web agent 可以自主读取受支持的工作区文档，无需要求用户再次上传；更换已配置 OCR 提供方不会改变工具 schema。
- 所选 OCR 端点会在 `ctx.fs` 强制执行提供方公布的字节上限后收到完整文件。工具不持久化源字节，普通持久工具调用与渲染后的 Markdown 结果会进入会话日志。
- 提供方的 Markdown 字符上限与截断标记限制提取输出。后续工具结果保留或对话压缩可能缩短旧结果，因此需要持久派生事实的 agent 必须通过普通任务操作进行总结或存储。
- 基于扩展名的路由拒绝旧版 DOC/PPT/XLS、音频、视频、未知扩展名和 URL。`read_document` 不下载远程资源，也不检查仅存在于浏览器的上传。
- 新提示词段和工具 schema 只在挂载 `ctx.ocr` 的作用域内改变模型请求前缀。

## 测试

OCR 运行时测试固定取消传播。文件系统工具测试固定条件注册与 dispose（资源释放）、受支持媒体路由、提供方字节上限、规范 base64、MinerU 形式的成功输出、结构化失败和纯读取卡片。生成的工具目录固定 schema。无外部依赖的组装快照挂载确定性 OCR 提供方，让回放模型对工作区 PDF 调用 `read_document`，并验证持久提取结果。
