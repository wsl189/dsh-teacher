# Agent Note: 按供应商分组的模型设置

Status: implemented

[English](2026-09-01-supplier-grouped-model-settings.md) | 中文

## 问题

Models 设置页把两种不同任务混在同一纵向列表里：配置提供方连接，以及为产品使用场景选择模型。每个提供方都暴露自己的卡片，添加提供方表单又在下方重复相同概念，协议、端点、凭据、模型目录与模型能力没有形成统一层级。订阅产品还使这种歧义变得不安全：同一供应商的标准 API、Coding Plan 与 Token Plan 可能使用相似的模型 id 或域名，却要求不同的 Key、端点、协议与使用限制。把供应商当作一份配置，会静默地把凭据与错误的计费线路配对。

## 决策

**Models 拆分为「使用场景」与「服务接入」两个面板。**使用场景只消费存活且已配置的线路，并为默认对话、后台工具、生图与语音识别各提供一项直接分配。服务接入持有提供方配置。每个展开的内联编辑器都有固定高度范围、在内部滚动并阻止越界滚动传递，因此模型目录长度不会驱动父级 Settings 滚动区。这种分离明确表达了依赖关系，又不会把提供方字段复制到每个使用场景里。

**供应商是展示概念，接入方式才是被配置的线路。**产品把智谱、Kimi、DeepSeek、阿里云百炼／Qwen 与 MiniMax 归入同一供应商导航。每个供应商包含一个或多个标准 API、Coding Plan 或 Token Plan 线路预设。每条线路保留已有的 settings namespace 与路径，派生自己的凭据引用，并独立保存。切换接入方式选择器会改变被寻址的线路，而不是对一个共享 profile 应用套餐开关。五个预设之外的已安装提供方与手工声明的 pi-ai 路由仍保留在工作区下方。

**协议与 API 密钥在线路级同级。**选择协议后，页面会套用与该协议和接入套餐配对的官方地址，同时允许继续编辑完整请求地址。模型类型词汇固定为对话／推理、视觉理解、语音识别与图像生成；Coding Plan 与 Token Plan 表示接入方式，不是额外模型类型。对话／推理与视觉线路使用已安装的 LLM 适配器，图片输入能力按模型声明。即使 DeepSeek 公共服务支持其他协议，其原生适配器仍保留固定的 OpenAI Chat 传输，因为暴露不受适配器支持的设置会产生无法执行的 profile。产品持有的预设数据由精确端点测试覆盖，因此上游变化必须经过显式编辑。

**模型目录按模型记录输入能力。**每个模型行都可以独立声明仅文本或文本加图片输入。已安装 pi-ai catalog 中缺失的产品线路只会在用户保存时获得完整初始 profile； catalog 线路在编辑前继续继承适配器持有的模型元数据。协议变化更新线路端点，模型类型与按模型的输入能力则说明哪些模型可以使用它。

**媒体线路可编辑，但仍由能力专属适配器执行。**`model-service-settings` 保存每个提供方准确的语音识别与图像生成 URL、协议适配器、模型目录及共享凭据引用。预设提供方和自定义提供方都能增加或编辑这些模型；「使用场景」读取同一 namespace，因此保存的媒体行会成为直接分配选项。一项媒体分配会在 `agent-default-model` 中保存提供方 id 与能力模型 id；它不会把提供方的 LLM 适配器变成媒体适配器。发行版 `speech-model-settings` 提供方会为每次录音读取实时分配与分类线路，再按已存 OpenAI 转写或 Qwen 音频协议分发。对话、日常管理与 QQ 语音附件共用这项操作。内置生图提供方同样会为每项任务读取实时生图分配、完整线路与凭据，再按 OpenAI Images、DashScope 生图或 MiniMax 生图协议分发，同时继续持有工作室、工具、历史与画廊。MiniMax 只获得图像生成默认值：其官方语音目录提供语音合成、音色复刻与音色设计，没有转写端点，因此这些 TTS 模型不会被标成语音识别。

## 曾考虑的替代方案

- **每个供应商只有一份凭据和 profile，再加一个 Coding Plan 开关。**否决，因为套餐 Key 通常不能与标准 Key 互换，一个布尔值也无法识别多种订阅产品及其协议专属端点。
- **每个模型一份协议覆盖。**否决，因为协议、凭据与 Base URL 共同识别接入线路；把它们复制到各模型行会产生互相矛盾的配置，并重复机密。
- **把生图与语音模型存成普通 LLM 线路。**否决，因为 LLM 适配器无法执行这些操作专属端点，会留下看似有用却实际无效的配置。
- **在「使用场景」的「更多设置」中保留适配器选项。**否决，因为负责分配已配置线路的面板不应再为同一操作配置第二条提供方路径。
- **保留一个不分类的提供方列表。**否决，因为它隐藏供应商关系，还让已安装提供方的添加流程在视觉上与第一方线路竞争。

## 后果

客户端持有五家国内供应商的可维护预设目录。官方 LLM 与能力端点、受支持的协议、线路隔离与初始模型目录都是测试的直接输入，供应商修改接口时必须同步更新它们。供应商分组与接入方式选择仍是提供方 profile 之上的投影；媒体线路持久化在 `model-service-settings` 中，`agent-default-model` 保存成对的生图与语音分配。语音与生图提供方会执行已存协议具有已安装适配器的所选线路，并在网络 I/O 前拒绝不兼容线路。浏览器通道覆盖仅含直接选择的「使用场景」面板、「服务接入」扩展位置、有界编辑器滚动、带受管密钥和不带受管密钥的 MiniMax 线路配置、协议与完整 URL 编辑、模型发现、分类自定义提供方创建与删除，以及媒体分配；组件与能力测试覆盖五家供应商目录、精确完整 URL、套餐隔离、四种固定模型类型、预设与自定义媒体分配、按模型图片输入、实时媒体设置与凭据解析、请求编码、资源上限和失败分类。
