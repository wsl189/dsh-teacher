# Agent Note: 桌面安装、更新与启动延迟的归属

Status: implemented

[English](2026-09-03-desktop-install-update-startup-latency.md) | 中文

## 问题

Windows 桌面载荷包含由数千个小文件组成的资源树，NSIS 安装成本除字节解压外还包括逐文件创建与杀毒软件检查。桌面启动路径还会先完成启动卡片加载，再创建后端，并在主窗口出现前加载更新提供方。更新安装会等待普通的 8 秒后端关闭时限，Electron 随后才能退出，因此停滞的插件 disposer 会延迟进入安装器的可见转换。

## 决策

桌面 `afterPack` 钩子把包含 12,939 个文件的完整 PPT Master 分发存为经过排序的 `resources/ppt-master.tgz` 归档，并移除安装载荷中的散文件副本。NSIS 把 `.tgz` 视为预压缩文件。载荷校验器会读取归档，并检查精确的逻辑文件数、字节数、归属文件、脚本、参考资料、布局、二进制样本和禁用 artifact。

桌面启动器把归档路径传给 `@deepseek-ai/dsh-skill-ppt-master`。归档支持的发现过程不会解压资源。首次加载 skill 时，提供方会计算归档哈希、共享并发工作，把内容解压到 `$DSH_HOME/cache/bundled-skills/ppt-master` 下的临时同级目录，校验必需归属文件，再以原子方式发布按内容寻址的目录。后续加载会复用该目录。散文件 Node 分发继续直接访问 `assets/ppt-master/`。

Electron 会在无脚本启动卡片加载期间开始创建后端。它只在应用窗口可见后才导入 `electron-updater` 并检查 release；后端则保留既有的 Windows-MCP 调度方式，在 profile 就绪后启动。启动失败与关闭过程仍负责清理隐藏窗口；即使关闭取代了启动，后端 rejection 也会被观察。

显式更新安装会立即隐藏窗口，并给后端 1 秒时间释放插件树。Electron 会终止超过更新专用时限的后端，然后调用已校验的安装器。普通应用退出继续使用 8 秒正常关闭时限。

## 考虑过的替代方案

**使用 ASAR 归档整个 Electron 应用。** Host 会向插件包、子进程入口、worker、原生 addon、脚本和外部工具提供真实路径。全面转换为 ASAR 需要完整审计可执行路径并制定选择性解包策略；仅归档资源可以消除已知的小文件热点，同时不改变这些路径。

**只使用 store 模式的 NSIS 压缩。** 存储整个应用可以减少解压 CPU，但会增大首次下载，而且不会消除逐文件文件系统与杀毒软件工作。预压缩资源归档会保留差分更新元数据，并直接针对文件数成本。

**每次退出都立即终止后端。** 普通退出可以为会话持久化与插件清理提供较长时限。只有用户确认的更新路径使用较短时限，因为下载的安装器已经提交，并将替换运行中的应用。

**在安装或启动期间解压 skill。** 这两个时点都会把同一项高文件数工作放到延迟敏感路径上，即使用户从未调用演示文稿创作也会执行。首次使用时实体化可以让发现与应用就绪不依赖该可选资源树。

## 后果

安装与版本替换会写入一个 PPT Master 归档，而不是 12,939 个散文件。该归档仍属于经过签名与 SHA-512 校验的更新载荷，载荷门禁也继续证明完整的带归属分发。一次本地归档检查把 79,496,215 个逻辑字节压缩为 53,351,037 字节；运行时实体化测试重建了全部 12,939 个文件。

首次加载归档版 `ppt-master` 时，会在 DSH 缓存中承担解压与杀毒软件检查成本。一次本地实体化检查耗时约 1.65 秒，进程内复用可立即完成；Windows 计时仍由已打包冒烟与 release 观测负责。内容变化会创建新的 digest 目录，卸载应用不会删除旧缓存项。

更新路径可能终止无法在 1 秒内达到静止状态的插件树。持久化存储必须保留自身的写入保证；当用户需要更长清理时限时，仍可使用普通关闭路径。

聚焦测试覆盖确定性归档暂存、惰性且原子的 skill 实体化、启动重叠、有界后端终止、更新器顺序、运行时环境路径和载荷拒绝。Windows 桌面工作流继续负责真实 NSIS 安装、已安装更新与打包启动计时。
