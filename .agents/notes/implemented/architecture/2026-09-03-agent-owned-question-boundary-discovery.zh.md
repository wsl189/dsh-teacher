# Agent Note: Agent 自主发现题界

Status: implemented

[English](2026-09-03-agent-owned-question-boundary-discovery.md) | 中文

> 本决策只取代[有界并行切题](../feature/2026-08-26-bounded-parallel-question-cutting.zh.md)中的候选默认紧凑题界协议；其中的分组、并发、图片归属、输出预算与降级决策仍然有效。
>
> 受保护候选的降级规则与非题目内容块归属由 [Agent 判定的题外边界](2026-09-03-agent-classified-outside-question-boundaries.zh.md)部分取代；完整来源发现、不透明 OCR id、必需工具调用与 Host 几何所有权仍然有效。

## 问题

MinerU 保留了安全切题所需的来源文本和几何，但 OCR 损坏会让真实标签无法进入 Host 题头候选。原紧凑题界协议把受保护候选默认当作题目，并把其余候选清单声明为准确集合，因此指示子 agent 只返回例外。即使子 agent 从完整 OCR 中正确识别出更多题目，也会被阻止提交。同一白名单还进入完整分组视觉复核：只有 Host 候选规则已经预测到漏题的页面，复核者才能报告整题缺失。因此，包含多道独立题目的裁剪可能被当成一项集合式学习任务通过。

## 决策

边界子 agent 根据完整 MinerU 证据负责语义发现。其 `questions` 参数是按来源顺序排列的完整独立题目清单，不是例外覆盖清单。核心页上的任意语义 OCR 元素都可以作为已提交题头，即使它不在 `possibleQuestionHeadIds` 中。子 agent 必须拆开可独立作答的编号题、例题和变式，不能把一个包含多道题的裁剪描述为集合式作答要求。

只有完整序列化 OCR 分组不超过 `maxQuestionCompactBoundaryCharacters` 时，才使用紧凑内联证据；此时 Host 会把每个元素都放入 `inlineSource`。更大的分组使用有界来源与页面预览工具，因此语义发现不会基于候选附近的截取子集。两条路径都保留现有的分组、元素、字符、图片与提交次数限制。部署可另外设置子 agent 墙钟截止时间，但 Web 组合默认不设置。

每个边界、视觉复核与修复子 agent 都会把逻辑 `toolChoice: required` 策略记录进请求 header，并依次保留显式开启的推理强度，或选择模型公布的已开启默认强度、最低已开启强度、提供方默认值。适配器会把工具策略映射为提供方协议支持的最强值。因此，Z.ai 兼容补全路由会发送 `auto`，但模型仍只能看到证据工具与 Host 校验工具，未进行一次已接受提交的步骤也仍会被 Host 拒绝。Web 组合不设置子 agent 墙钟截止时间；部署可将 `questionSegmentationAgentTimeoutMs` 设为正值。工具限制与 Host 校验决定哪些调用存在，以及哪些已提交草稿成为权威结果。

Host 候选检测继续作为可疑回忆提示、窄范围矛盾校验以及边界 agent 失败后的确定性降级。每个提示候选仍必须得到题目或非题目显式判定，具有来源作答要求证据的候选不能被降级。这些校验不会再把子 agent 未提交的候选加入一份成功草稿。紧凑纯 OCR 运行仍通过确定性几何归属未列出的图片，因为图片语义由后续标注视觉复核判断。

首次完整分组视觉复核可以在任意学习者核心页报告独立漏题。建议的未覆盖题头只是非穷尽提示。即使一道题的像素位于已有洋红区域内，只要该区域把多道题合并成一个裁剪，它仍属于漏题：复核者记录漏题头，并把合并裁剪标记为内容重分配。只有恰好包含一项独立作答要求的裁剪才能通过。局部重切仍不能添加未列出题目或替换整个分组。

Host 继续拥有来源身份与几何。它校验不透明元素 id、核心页归属、来源顺序、候选显式分类、受保护的作答要求证据、内容归属、语义停止位置与裁剪坐标。Agent 不能虚构题头或边界框；语义发现失败后，系统仍先降级到确定性候选，再执行视觉复核。

## 考虑过的替代方案

**扩充题头正则。** 更多模式可以修复已知 OCR 字符串，但会让召回率依赖无穷尽的出版社格式与识别错误清单。模式继续用于提示和兜底，不作为语义事实来源。

**保留候选默认，再让视觉复核拆分宽裁剪。** 这会让修复阶段补偿一份被刻意限制为不完整的初始草稿，而且当同一套候选规则没有预报漏题时，视觉复核仍无法报告它。

**让 Agent 返回坐标。** 模型坐标不是 MinerU 事实。不透明来源 id 能保留语义灵活性，而无需转移几何权威。

**只依赖提示词要求提交。** 模型可能正确分析出每道题，却仍把整个子 agent 运行用于叙述计划而不调用提交工具。请求策略把工具使用变成执行属性，同时仍由 Host 决定是否接受草稿。

## 后果

- 紧凑边界提交可能更大，因为它包含全部发现的题目。32,768 token 边界配额与有界分组大小负责容纳完整草稿。
- 完整 OCR 超过紧凑字符上限的分组会消耗来源工具轮次，而不是收到更短的聚焦摘录。
- 候选规则仍可拒绝矛盾或提供降级输出，但 Agent 使用新的文档惯例前，不再要求 Host 先增加匹配模式。
- 完整分组视觉修复在合并裁剪内发现漏题时可能替换更多边界；现有完整草稿校验保证替换覆盖完整来源。
- 必需工具选择会使用提供方可用的最强表示。最强表示为 `auto` 的协议依赖同一受限工具集、已接受提交校验与有界降级，而不会收到不受支持的协议值。
- 开启推理可能增加延迟，但 Web 子 agent 没有墙钟截止时间；提供方请求超时与调用方取消仍然有效。

## 测试

Host 测试提交三个未进入 `possibleQuestionHeadIds` 的 OCR 损坏括号题头，并要求三题全部被接受。测试还要求内联提示与工具 schema 请求一份完整 `questions` 草稿，保留提示候选的显式判定，完整内联证据超过字符上限时回退到来源工具，允许完整分组漏题报告不受提示清单限制，从合并裁剪中拆出漏题，继续禁止局部重切期间的纯页级恢复，把带有已开启推理的 `toolChoice: required` 传给边界、复核与修复子 agent，并保留无截止时间默认值。适配器与循环测试固定请求 header 重建以及 DeepSeek 和 pi-ai 的协议映射，包括 Z.ai 的 `auto` 工具选择。组装后的 Web 试题分割测试通过发布组合运行完整草稿 schema。
