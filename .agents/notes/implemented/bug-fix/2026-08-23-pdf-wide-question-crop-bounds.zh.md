# Agent Note：整份 PDF 共用试题横向裁切边界

Status: implemented

[English](2026-08-23-pdf-wide-question-crop-bounds.md) | 中文

## Problem

如果每张题图使用各自试题框的横坐标，把图片适配到同一内容宽度的消费方就可能把窄题显示得比宽题更大。长 PDF 还会分多个语义组执行切题，因此各组独立的坐标无法让整份来源 PDF 保持统一比例。

## Decision

所有语义组合并后，`teacherWorkbench/segmentQuestions` 会计算整份 PDF 共用的归一化横向裁切边界。左边界取全部已接受区域中最小的 `region.left / region.pageWidth`，右边界取最大的 `region.right / region.pageWidth`；这些坐标来自为试题选择的可信 MinerU 版面区域。空结果携带中性的整页边界。

浏览器与普通对话渲染器采用与参考实现等价的两遍裁切：先计算整份 PDF 共用的左右边界，再在这对横坐标之间直接裁取每个原页面切片，同时保留该题自己的上下坐标。来源与目标像素尺寸相等。跨页题会纵向拼接并左对齐各切片。浏览器会在渲染任何保存组前拿到完整 PDF 的边界，因此传输分组不会改变图片宽度。对话工具 `segment_pdf` 使用同一份服务结果与 Host 渲染器；边界子 agent 无法为单题选择倍率或宽度。

该决策细化了[试题分割工作台](../feature/2026-08-19-question-segmentation-workbench.zh.md)，应用在 [Agent-loop 试题分割](../feature/2026-08-21-agent-loop-question-segmentation.zh.md)定义的语义分组之后，并约束[对话操作教师工作台](../feature/2026-08-22-conversation-operated-teacher-workbench.zh.md)引入的 `segment_pdf` 路径。

## Alternatives considered

**把每个紧致裁剪缩放到同一输出宽度。** 重采样会改变不同题目之间字体与图形的视觉比例。

**把每个紧致裁剪放到共享白色画布。** 补白能保持比例，却会漏掉单题紧致框与整份 PDF 共用坐标之间的原页面像素，因此没有实现参考项目的来源裁切。

**按语义组或保存组分别计算边界。** 组内边界可能让同一 PDF 的图片宽度不同，并让传输分组影响文档输出。

## Consequences

- 来自相同尺寸来源页面的题目具有相同输出宽度，并保持来源栅格倍率；不同尺寸页面仍保持该倍率，像素宽度随页面尺寸变化。
- 共用横坐标之间的所有原页面像素都会进入题图。对于分栏试卷，如果另一栏内容与该题的纵向范围重叠，也可能被一并裁入。
- 更宽的直接裁切可能增加已存图片字节，但现有的解码字节保存分片仍会限制每次请求。
- 模型继续负责语义元素归属，Host 负责整份 PDF 共用的裁切坐标与栅格倍率。

## Verification

聚焦 Host 测试覆盖跨语义组的整份 PDF 边界与中性空结果。客户端栅格测试证明两道题使用相同的来源 `x0`、`x1` 与宽度，且不缩放、不做横向补白。普通对话测试覆盖不同单题框产生相同已存图片宽度。组装后的无密钥快照记录返回边界与 `segment_pdf` 面向模型的保证。
