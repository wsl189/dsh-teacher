# Agent Note：内置 IM 渠道的现代 Host 连接

状态：已实现

[English](2026-09-05-im-modern-host-connection.md) | 中文

## 问题

内置 dsh-im 1.0.3 客户端向 Web 服务器发送旧版 HTTP RPC 封装。当前 Host 使用连接身份验证保护这些浏览器路由，并暴露了不同的 Typert API，因此所有平台共用的健康检查都会在渠道运行时启动前失败。连接平台页面只把该失败显示为“连接未就绪”。已保存的微信令牌还可能独立过期，但启动响应没有被校验，可操作的平台错误也被同一条通用消息替换。

## 决定

Web 组合固定 dsh-im 4.11.0，并为全部九种机器人平台与 Office 使用其现代 Host 同进程适配层。本地渠道直接调用当前 Host 服务；明确配置的外部 `harnessBaseUrl` 继续使用 HTTP。发行补丁保留桌面工作区默认值与 QQ 共享语音线路。它校验微信启动响应，并保留 `stale-token` 及“移除账号后重新扫码”操作指引。

已保存的机器人配置、凭据、工作区与渠道状态仍位于包压缩档之外，并保留现有格式。这次升级不会把浏览器凭据复制到插件、降低 Web 路由身份验证强度，或重写已保存的平台数据。

## 考虑过的替代方案

**为旧版回环 HTTP 调用添加身份验证。** 浏览器凭据属于浏览器连接，而且这种做法无法修复旧版方法名、封装、历史记录与交互流。

**只修复健康检查。** 后续工作区、会话、提示、审批与问题调用使用同一套已退役协议，因此启动成功只会隐藏更多失败。

**删除并重建所有账号。** 这会丢弃有效的平台凭据与工作区，但不会修复共享 Host 集成。只有平台凭据无效的账号需要重新授权。

## 结果

全部内置渠道共用一套当前 Host 集成，不再需要九套协议兼容层。平台仍可能因自身令牌或密钥无效而离线；微信页面现在会区分扫码令牌过期与 Host 连接失败。重新扫码必须由用户执行，因为自动替换已保存的账号凭据不安全。

## 测试

[内置 IM 测试](../../../../packages/bundle/web-app/tests/im-workspaces.spec.ts)要求同进程健康检查不使用 HTTP，保留显式远程 HTTP 选择，覆盖所有桌面工作区默认值与 QQ 共享语音，并把微信 `-14` 响应固定为 `stale-token`。真实 Web profile 启动证实一个已配置 QQ 账号可通过新适配层进入已连接状态，而已保存的微信账号返回令牌过期诊断。
