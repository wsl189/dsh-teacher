# Agent Note: Correctable question boundary decisions

Status: implemented

English | [中文](2026-09-04-question-boundary-corrections.zh.md)

## Problem

Repeated complete-draft submissions changed unrelated classifications while trying to repair one rejected element. Array-index-only diagnostics obscured the offending identity. OCR theory tables were rejected as outside markers, earlier outside blocks incorrectly prohibited attachments to later questions, and automatic image retention contradicted image-headed questions. These failures exhausted the [bounded review budget](2026-09-04-bounded-question-crop-review.md) without making progress.

## Decision

The [boundary and visual-repair submission tools](../../../../packages/host/teacher-workbench/README.md) retain their latest complete drafts. A later call can replace individual element decisions through `corrections`, preserving every unlisted decision. Each replacement selects one role and removes conflicting classifications of the same element. Question replacements supply their complete attachment and stop fields. Corrections can also replace or explicitly clear the retained document-final stop without replacing question decisions; an empty correction array is valid only for that edit. A retained invalid final stop must be repairable through the correction-only recovery tool rather than surviving every fresh child. The Host validates the resulting complete draft, including candidate coverage, core-page ownership, protected answer demands, authorized repairs, and geometry; corrections cannot bypass these checks or reset the failed-call budget. Identical rejected boundary drafts retain their original diagnostics, and terminal failures include the latest diagnostic. Descriptive `headConvention` metadata is optional because it does not decide crop ownership.

OCR source, repair-context, and preview reads are idempotent. Re-reading valid evidence does not consume the rejection budget; previews reuse the same stored attachment, including concurrent requests. Invalid chunk indexes, unknown ids, duplicate ids within one image request, and uninspected required evidence still fail validation. Child deadlines continue to bound read loops.

Compact visual reviews separate core and context pages into labelled sheets, with the exact PDF page id and scope repeated above each image. The text-only repair child receives core-page indexes, candidate and image ids, and current heads. A missing-question finding requires a complete group replacement; crop findings remain local. Context pages can supply continuation evidence, not new question heads owned by this group.

Compact crop-local repair has a separate flat tool and persona. Each repair row identifies an existing cited crop, uses exact page labels for optional coordinates, and delegates content and geometry changes to the same complete validator. Complete-group fields are unavailable in this phase. This avoids making the model reconstruct a whole question list and several nested geometry objects to adjust one crop. Fresh local recovery retains the same flat draft. Page-only missing-question findings omit meaningless repair intents and retain the complete-group path; existing-crop findings still require their intended directions.

Trim, reassignment, and removal contexts include the entire sampled crop OCR in bounded required chunks. Edge-only excerpts cannot locate an unrelated block that begins in the middle of a long crop. A recorded vertical trim authorizes explicit outside-block decisions, and a recorded trim or reassignment authorizes explicit unrelated image-and-caption exclusions. Coordinates alone never reclassify learner content or silently drop a required image. Full validation and subsequent visual review remain necessary.

Removing an unrelated block can eliminate an entire leading or trailing source-page slice. That removal satisfies the corresponding vertical trim intent even when no same-page rectangle remains to compare. A redundant coordinate on the removed slice is checked against its original sampled bounds and may only trim within the page; an unknown original slice, expansion, or out-of-page coordinate is rejected. Semantic ownership and required-content checks still decide whether the slice can disappear. This avoids forcing a model to recreate removed content merely to satisfy a coordinate validator.

Source size controls transport, not visual authority. Compact serialization can fit the inline limit even when expanded OCR would require several chunks; the complete inline source satisfies inspection of all those chunks. When compact evidence exceeds its limit, chunked OCR without page previews retains automatic image ownership and excludes pixel-deletion fields. Requiring preview-backed image decisions in a child with no previews creates unsupported classification work solely because the document contains more text. Image-bearing full-classification tests explicitly supply and inspect previews; OCR-only tests keep complete-source inspection and later visual review mandatory.

Chunked and inline OCR evidence label each page's scope. The chunked-read persona, like the inline persona, requests direct tool submissions rather than a prose analysis. Rendered crop headers repeat the source annotation's Q label alongside the crop id. Each boundary or compact repair child has a bounded repeated-diagnostic allowance. The first actionable diagnostic is normalized so changed indexes and element-number suffixes remain one failure category; repeating that category exhausts the allowance, while reaching a different diagnostic resets its repeat count. Schema failures use the same normalization and all forbidden tools share one category. Child deadlines and output limits still bound alternating failures. Exhaustion can use the remaining `maxQuestionBoundaryAgentRuns` recovery runs, with the rejected draft and diagnostic in a fresh context. The new child must inspect the evidence again, cannot withdraw recorded visual findings, and must obtain full validation. Persistent boundary failures stop after the configured children instead of retrying indefinitely because no crop geometry exists. Once preliminary crops exist, visual-review failures follow the [question-local fallback](2026-09-05-question-local-repair-fallback.md): complete findings retain only cited Host-validated crops as unverified, while a pre-finding failure retains the current safe review scope.

Outside markers accept text-bearing semantic elements and tables, including tables without extracted text. OCR representation does not make a theory table part of the preceding learner task. An explicit outside marker blocks an attachment only when it lies after that question's head and before the attached element. A selected image head is already owned by its question and does not receive a second automatic retained-image classification. No filename, page number, publisher, or textbook-specific condition controls these decisions.

Compact finding submissions report all conflicting, missing, duplicated, and unknown classification references together. Invalid-reference submissions do not update the draft. Valid partial submissions that fill missing classifications, attention evidence, or image checks return `INCOMPLETE` without consuming the failed-call allowance; treating progress as failure could exhaust that allowance before the final check. Follow-up calls can omit unchanged arrays, including `verifiedCrops` for check-only updates. No-progress repeats and invalid evidence remain rejected. A page-only missing-question finding whose own evidence says that no independent learner problem or answer demand exists is rejected before defects are recorded; a clean core page with no questions uses an empty findings list. The run-specific tool guard charges forbidden calls before they can perform filesystem or other side effects; blocked image reads cannot loop outside the budget until the deadline. All crop and check coverage is still required before acceptance, and child deadlines continue to bound the run. Exhausted compact visual children use the remaining configured recovery runs with validated draft rows and the latest diagnostic, not malformed calls. Every source sheet is attached again; new evidence is still required to finish missing checks. Recorded defects cannot be cleared by classification recovery. Tests cover more partial submissions than the rejection allowance, rejection of a duplicate without progress, a contradictory missing-question finding, and check-only calls through the assembled Web loop. Crop metadata includes a bounded OCR head excerpt to match source annotations and rendered crops; only actual pixels can establish completeness.

When a boundary recovery retains a draft, only a dedicated correction tool and required evidence readers are callable. The correction tool exposes no complete-draft fields and delegates to the same validator. Its short persona describes element replacements rather than repeating the initial complete-segmentation assignment. Recovery cannot accidentally replace unrelated decisions by mixing complete lists with corrections.

Repeated OCR delimiters preserve generic tagged heads, citation-only labels, and subordinate-item markers. Qualified solve instructions protect the parent task; a bracket-prefixed subpart cannot become an independent head merely because OCR inserted another opening delimiter. Context-head errors include exact omit corrections rather than asking the child to invent a replacement role, and compact schemas omit unsupported pixel exclusions. A validated content-reassignment repair uses declared outside blocks consistently for ownership and required-text preservation; coordinates and exclusions alone do not authorize removing learner text. Outside decisions also prevent the attachment-only optimization from restoring the contaminated crop geometry. Tests retain unfamiliar-label cases to prove that discovered heads are not limited to parser hints. Selected heads cannot be claimed as another question's attachment. This prevents an attachment from stealing the head's ownership while crop limits clip that same head out of the claimant, producing an empty citation crop and a headless learner crop.

An explicitly retained image in a crop-local repair keeps its known existing owner, including an image ordered before the head. The Host converts this decision into an attachment before full validation, not an unchecked geometry expansion afterward. Duplicate or conflicting decisions remain invalid; omitting the required image still fails the preservation check.

Element replacement removes stale attachments as well as root classifications; a retained-image correction cannot leave its previous explicit owner in conflict. Compact and separate-image reviews require the same four actual crop-edge observations and required-visual evidence. The Host no longer fills these fields with the answer-demand evidence, which could verify a recognizable question in the middle while overlooking unrelated material elsewhere in the image.

Visual attention explicitly identifies sampled tables and unfinished OCR response tails. The reviewer must first establish that a table belongs to the learner task rather than a theory summary, then inspect its last row and bottom rule. When previews arrive with segmentation or the initial full review, a raster-confirmed nearby horizontal response rule can extend an unfinished OCR tail; source blocks and other crops bound the search, and empty, thick, or vertically dispersed pixel regions do not extend it. The browser sends its first previews during review, so this path completes the full-group classification before returning revised geometry for a new local visual acceptance. This preserves actual pixels rather than synthesizing a line or trusting a model's assertion. Later explicit visual repairs remain authoritative. Review sheets contain one row of at most two images, avoiding large multirow montages that providers shrink until edge details disappear.

Interleaved OCR ordinals do not define same-page column stops. The owner evaluates all relevant stops geometrically in the content's column; a stop at another column's head does not remove its own remaining subparts or figure. A detached score label or recognized question prefix with no independent owned demand cannot be split from its following unnumbered stem. Explicit attachments cannot steal another same-column question's body; diagnostics identify the attachment and both heads, rather than inviting removal of an emptied citation label. Independent parenthesized response questions following a section transition are explicit candidates even inside theory material; the response demand can occur in continuation lines before the next sibling, and their next same-level item terminates ownership, including text-bearing OCR table headings and repeated opening delimiters. Existing parent questions still retain subordinate parts.

Image exclusions apply after the final coordinate edits. Computing erasures only against the natural OCR rectangle can omit an excluded image just beyond that rectangle, then restore its pixels when a repair chooses a larger bottom. The final sampled rectangle determines which explicitly excluded source boxes are erased, while boxes overlapping owned learner content remain protected. The assembled Web repair covers an excluded image-and-caption block outside the natural rectangle but inside the submitted bottom.

Local repairs intersect newly derived geometry with previous crop edges and preserve previous erasures unless an authorized expansion or explicit restoration requires the pixels. Removing an unrelated page slice cannot reconstruct a resource block removed in an earlier review. Full-group discovery remains separate from this crop-local preservation rule.

Protected learner candidates cannot be discarded as outside content in OCR-only classification, including compact runs where caller previews exist but are not delivered to the child. Pixel-backed review can still remove a genuine false positive. This trades a reviewable extra crop for an otherwise invisible omitted task. Short outline headings without learner requests stop prior ownership without a publisher-specific phrase list, and sibling stops prevent a plain definition from borrowing the next item's response demand.

Visual review distinguishes cutting defects from source defects. A watermark, stamp, or scan blemish overlapping required source text or graphics must remain because erasing its rectangle would destroy learner pixels. This is not permission to retain a separate resource code or unrelated block, overlook missing content, or claim that an obscured original has been restored. Both review paths receive the same source-fidelity instruction, and geometry tests preserve overlapping learner content while removing separable furniture.

Source-page context and actual output have distinct visual labels. Readable unsampled context receives a translucent gray wash; actual crop pixels remain unchanged. Host-calculated image sampling accompanies the sheets so a source-only image cannot be cited as inside a crop. Every sampled image in a verified crop has an explicit role and evidence. Missing image checks remain repairable draft omissions, unrelated images require a defect instead of verification, and detached images cannot be excused as source overlays. This prevents a verifier from describing a resource as unrelated while still accepting the crop. Tests cover missing checks, source-only references, required content, overlapping overlays, and contradictory verification followed by a real repair.

OCR type does not decide whether recognized words form an independent task or a section heading. Text-bearing image and table elements participate in semantic candidate detection while their original raster boxes remain intact. Continuation scanning recognizes a single Chinese response underscore before punctuation without treating mathematical subscripts or image option labels as a new demand. This preserves question text that OCR categorizes as a figure and blocks an image-based chapter banner from joining the preceding crop.

The detached-prefix check includes the selected head's own text even when OCR labels it as an image or table. Otherwise candidate validation can require two independent questions while ownership validation simultaneously requires merging them. Recognized standalone response heads do not receive the unrecognized-promotion warning; ordinary subject knowledge from preceding theory items does not by itself make a later self-contained fill-in a subordinate fragment. Truly unrecognized heads still require that check.

Missing-content diagnostics distinguish learner answer-demand clauses, response marks, and requested solution sets from supplied answers and worked solutions. These terms do not alone prohibit an expansion, but required visual evidence, authorized directions, and neighboring-head protection still apply. A finding that also requests a supplied answer or worked solution remains invalid.

A trim finding may identify unwanted content relative to a valid stem or subpart. Mentioning that learner content in the evidence does not mean it is the removal target; the Host must not reject the finding solely on those words. Subsequent repair validation still rejects clipped required OCR, silent image removal, uncited changes, and unauthorized directions. An explicit outside decision is required to reclassify an unrelated text block, and saving requires a new visual acceptance.

Compact and separate-image reviews share the visual-ownership rule: optional resource images are not required task content merely because they are nearby. A valid defect takes precedence when the same submission also calls that crop verified; its verification and attention check are discarded, not the defect. The crop must still be repaired and reviewed again once the complete classification records it. Unknown references, invalid findings, and invalid remaining verifications reject the submission without updating the draft; valid rows lacking only complete coverage can remain an unaccepted draft.

Question-processing tools decode JSON-encoded array fields according to their declared schemas before strict argument validation. Real tool-capable model calls can otherwise repeat a complete classification several times solely because an array was encoded as a string. Decoding is lossless and local to these tools: malformed JSON, non-array values, invalid nested items, unknown references, and missing required fields still fail. Evidence strings remain strings, and no omitted classification is inferred.

Bare parenthesized figure captions cannot borrow a later same-number question's answer demand or act as a sibling content stop. A text-bearing following item can end demand scanning even when a bare caption is indented under a figure. This keeps the labels and complete figures with their owner instead of creating a duplicate diagram-only crop. Open conditional conclusions remain learner-blank evidence without enumerating every possible requested quantity; a completed conclusion is not protected by that rule. Boundary and review instructions explicitly preserve supplied reference appendices through their final line, distinct from worked answers.

Image sampling metadata includes OCR text and exact question-head membership. An OCR image box can be the complete text of a question rather than a separate illustration. Its retained head must have the required-content role; an unrelated or source-overlay classification is rejected before recording a destructive crop defect. A retained-image reference to a non-image is a reference error whose diagnostic names the exact id, actual element type, valid core-page image ids, and the non-image attachment alternative. Reference-summary headings prevent their parenthesized procedural subpoints from borrowing an incidental solve verb as a standalone learner task. A justified remove-crop finding can discard an OCR-protected false positive only when pixel evidence names its non-task category and explicitly says no independent learner answer demand is visible; vague denial still preserves the crop. Findings that still request checking or confirmation are not visibly confirmed defects. Diagnostics identify unrelated roles as the reviewer's classification, not a Host finding that the reviewer must obey. Forbidden-tool errors name the exact allowed tools to recover from a truncated run suffix without accepting aliases or widening access. A multi-target context read with no target returns the exact available ids without consuming a failed call; a supplied invalid id still fails. Direction errors provide the current and submitted coordinates with the authorized directions instead of requiring the repair child to rediscover them from a large context.

## Alternatives considered

**Increase the rejection allowance.** More retries cannot repair contradictory Host rules and increase latency when the model repeats its draft.

**Automatically reclassify every rejected candidate.** Candidate hints are fallible. Guessing would hide missing questions or promote theory and solutions into crops; explicit agent decisions and visual verification remain required.

**Require complete replacement drafts for every correction.** This repeats valid decisions and creates avoidable omissions and conflicting array entries. Per-element replacements retain full-result validation without requiring that repetition.

## Consequences

Model classifications remain nondeterministic. Structural checks can reject missing decisions, inconsistent ownership, unsupported image roles, and invalid geometry; they cannot prove every visual judgment correct. Real-model verification uses the Web upload and queue with the configured Ollama model and reasoning disabled, then compares saved crop pixels with source pages, including wrapped response lines, theory-embedded tasks, supplied reference formulas, and mixed text/figure layouts. A successful queue status alone is not acceptance evidence, and these protocol checks do not guarantee correct segmentation for arbitrary model output.

The operation keeps one complete draft and a bounded cache of rejected-draft diagnostics. A patch can still be semantically wrong; no acceptance guarantee is made for arbitrary model output. Visual review remains mandatory for verified status; any visual-stage fallback after preliminary crops is saved only with an explicit unverified warning. Focused tests cover tables with and without text, attachments on either side of a transition, protected-head and complete-group repair corrections, image heads, repeated evidence reads, scope-labelled sheet pixels, fresh-context recovery, persistent boundary rejection-budget exhaustion, and crop-specific exhaustion returning an unresolved cited id. The assembled Web scenario records both a per-element correction from retained recovery state and a cited-crop fallback through the real child loop.
