# Agent Note: 逐区域保留试题裁切起点

Status: implemented

[English](2026-08-24-per-region-question-crop-origin.md) | 中文

> 本决策细化[试题切割工作台](../feature/2026-08-19-question-segmentation-workbench.zh.md)的裁切几何规则。

## 问题

通过校验的试题区域会保留各自的左、上、右、下坐标，但两套 PDF 渲染器都会把每个区域的横向坐标替换为整份 PDF 的最小左坐标与最大右坐标。双栏试卷会让这段距离接近整页宽度，因此左栏试题会带入右栏内容，每张已保存图片也会接近整页宽度。

## 决策

所有语义页组合并后，Host 会把全部已接受试题区域中最大的 `(right - left) / pageWidth` 记为 `maxQuestionWidthRatio`。切题结果把这一项归一化宽度同时交给两套渲染器。

Host 还会为每个页面片段记录 `rightLimit`：它是纵向重叠且不属于该题的右侧内容中最近的左边界；不存在这类内容时则取来源页面右边缘。该值是不受区域内容右界 `right` 影响的来源像素硬上限。

浏览器 PDF.js 渲染器与普通对话 Host 渲染器都会保留每个区域自己的左、上、下坐标。渲染器从该区域的左边界向右最多采样一份最大归一化宽度，并受 `rightLimit` 限制。未缩放的来源像素会放入仍使用最大归一化宽度的白色画布。跨页试题会先对每个页面片段分别应用同一规则，再把片段纵向拼接。

## 已考虑的替代方案

**使用整份 PDF 的最小左坐标与最大右坐标。** 这种方式能让相同尺寸页面只产生一种宽度，但会丢失栏目归属，并导致本决策修复的整页宽裁切。

**保留每个区域原来的右边界。** 这种方式能保留栏目，但会产生不同的输出宽度，也不满足工作台统一使用最宽已接受试题的要求。

**只在来源页面右边缘截断。** 这种方式会保持统一输出宽度，但只要 PDF 其他位置存在较宽试题，共用宽度仍会采样相邻栏目。

**裁剪前完整识别页面栏目。** 安全要求并不需要完整栏目模型。纵向重叠且不属于该题的最近元素已经能给出局部像素上限，无需假设栏目数量或宽度固定。

## 后果

不同栏目的试题会保留不同的横向起点，并在相同尺寸页面上获得一致的输出宽度。受到页面边缘或相邻栏目限制的区域会在右侧留下白色空间，而不会取得无关来源像素。

一项确实较宽的已接受试题会增大所有裁切图片使用的画布宽度，但无法覆盖其他区域的来源上限。已经保存的图片不会被重写；用户需要重新切割来源 PDF 才能应用该几何规则。客户端与 Host 回归测试使用横向分离的区域，同时断言局部裁切起点及 `rightLimit` 之后不存在相邻栏目像素。
