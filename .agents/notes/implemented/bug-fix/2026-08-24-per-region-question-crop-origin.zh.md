# Agent Note: 逐区域保留试题裁切起点

Status: implemented

[English](2026-08-24-per-region-question-crop-origin.md) | 中文

> 本决策细化[试题切割工作台](../feature/2026-08-19-question-segmentation-workbench.zh.md)的裁切几何规则。

## 问题

通过校验的试题区域会保留各自的左、上、右、下坐标，但两套 PDF 渲染器都会把每个区域的横向坐标替换为整份 PDF 的最小左坐标与最大右坐标。双栏试卷会让这段距离接近整页宽度，因此左栏试题会带入右栏内容，每张已保存图片也会接近整页宽度。

## 决策

所有语义页组合并后，Host 会把全部已接受试题区域中最大的 `(right - left) / pageWidth` 记为 `maxQuestionWidthRatio`。切题结果把这一项归一化宽度同时交给两套渲染器。

浏览器 PDF.js 渲染器与普通对话 Host 渲染器都会保留每个区域自己的左、上、下坐标。渲染器从该区域的左边界向右使用一份最大归一化宽度，并在来源页面右边缘截断。跨页试题会先对每个页面片段分别应用同一规则，再把片段纵向拼接。

## 已考虑的替代方案

**使用整份 PDF 的最小左坐标与最大右坐标。** 这种方式能让相同尺寸页面只产生一种宽度，但会丢失栏目归属，并导致本决策修复的整页宽裁切。

**保留每个区域原来的右边界。** 这种方式能保留栏目，但会产生不同的裁切宽度，也不满足工作台统一使用最宽已接受试题的要求。

**单独检测页面栏目。** 已接受区域的左坐标已经标识其横向起点。增加栏目分类器只会引入更多版面假设与失败方式，不会改变所需计算。

## 后果

不同栏目的试题会保留不同的横向起点；在相同尺寸页面上，它们通常获得一致的像素宽度。靠近页面右边缘的区域可能更窄，因为页面外不存在来源像素。

一项确实较宽的已接受试题会增大所有裁切图片使用的宽度。已经保存的图片不会被重写；用户需要重新切割来源 PDF 才能应用该几何规则。客户端与 Host 回归测试使用横向分离的区域，并断言两套渲染器都从区域自身的左坐标开始裁切。
