# Agent Note: 隔离年级课表班级

Status: implemented

[English](2026-08-20-isolate-grade-timetable-classes.md) | 中文

## 问题

课程表 OCR 与手动新建班级原本把所有班级写入同一个共享集合。年级课表中识别出的标签因此会出现在今日课表、本周课表、早晚自习、班级名册、成绩分析和试题切割的可选项中。节次或组合表头等 OCR 结构文本也可能被当作班级，并扩散到这些无关模块。

预期关系更窄。今日课表、本周课表与早晚自习描述同一份普通课程表，可以共用班级。年级课表导入的是独立的全年级投影，其中的班级必须只留在年级课表。名册、考试与试题切割则使用由在册学生支撑的第三个目录。

## 决策

版本 6 的 `teacher_workbench` 文档要求每个 `TeacherClass` 具有一个 `usage`：`roster`、`timetable` 或 `gradeTimetable`。今日课表、本周课表和早晚自习只选择 `timetable` 班级；年级课表只选择 `gradeTimetable` 班级；班级名册、成绩分析和试题切割只选择 `roster` 班级。状态 schema 会拒绝班级不属于名册目录的学生与考试，也会拒绝班级属于名册目录的课程表条目。三个目录可以分别用独立标识保存同名班级。

课程表命令依据用途、名称和年级解析已有班级。即使调用方提供另一个用途的班级标识，新条目也不会关联到该班级。删除仍按班级标识级联，因此只会移除该目录中的从属记录。

OCR 复核解析器只在规范化班级名称以“班”结尾时默认选中识别行。不符合该规则的班级列原始文本会被丢弃，而不是提升为持久化班级；批量导入命令再次执行相同校验，使调用方无法绕过复核界面。该行仍会显示，并可在导入前编辑。

## 考虑过的替代方案

**只在可见菜单中筛掉其他班级。** 被拒绝，因为控制器直接调用、按教师筛选的课程表投影与未来消费方仍可通过共享标识关联条目。持久化所有权与 schema 必须表达这项规则。

**只标记 OCR 创建的年级课表班级。** 被拒绝，因为手动添加的年级课表班级仍会扩散，而实际规则适用于该视图持有的每个班级。

**为本周课表与早晚自习分别建立目录。** 被拒绝，因为它们是普通课程表的两个视图，应当复用同一个普通班级标识；只有年级课表需要独立。

**复核后接受任意非空班级名称。** 被拒绝，因为教师尚未发现问题时，OCR 结构标签就会被默认选中。要求可见的“班”后缀可以提供确定性准入规则，同时保留手动修正能力。

## 后果

- 同一个显示名称可以分别拥有名册、普通课表与年级课表标识及课程安排。
- 年级课表识别与手动新建班级都不能填充其他模块；本周课表与早晚自习仍通过普通课表目录保持关联。
- 项目仍处于发布前阶段，旧班级记录又没有足够的所有权信息可供无歧义转换，因此版本 5 文档会被拒绝，而不是迁移。
- 不以“班”结尾的 OCR 班级名称必须先在复核面板中修正，才能导入。

## 测试

Host schema 测试会拒绝跨目录的学生、考试与课程表引用。控制器测试在三个目录中创建同名班级，证明早晚自习复用本周课表的普通班级、年级课表获得独立标识，并在批量导入时拒绝结构性班级标签。课程表、名册、成绩与试题切割组件测试会断言各自的目录过滤。解析器测试覆盖保持未选中的“第一节”与“星期班级早读”，并接受“五班”和“高三（11）班”。
