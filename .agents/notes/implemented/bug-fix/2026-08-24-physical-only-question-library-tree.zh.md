# Agent Note: 仅显示物理目录的试题库树

[English](2026-08-24-physical-only-question-library-tree.md) | 中文

Status: implemented

## 问题

试题切图是所选试题库目录中的直接文件，但 Web 层级会把每个持久化试卷批次渲染成以 PDF 命名的子行。该行的外观和行为都像目录，磁盘上却没有对应路径。只折叠名称与目录相同的文件系统批次，无法覆盖持久化上传，也无法处理同一目录保存多份 PDF 的情况。

## 决策

试题切割的试题库层级只包含物理目录标识。持久化目录与文件系统目录继续使用普通目录行；配置的试题库根目录中存在直接图片时，使用一个明确的“试题图片库根目录”行。试卷批次不会创建层级节点。

每个目录行持有图片直接存放在该目录中的全部持久化批次与文件系统批次。选择该行会在一个扁平图片抽屉中打开这些批次的全部图片；展开控件仍然只表示物理子目录。批次元数据继续负责续传保存、图片可修改性、分发资格与 Host 删除，但不再属于目录展示概念。该展示规则取代原始[试题切割工作台](../feature/2026-08-19-question-segmentation-workbench.zh.md)决策中的独立批次行。

## 已考虑的替代方案

**只折叠一个同名批次。** 这种方式能移除扫描得到的纯图片目录中的重复行，但持久化上传、名称不同的外部文件以及包含多个批次的目录仍会显示虚假的 PDF 子行。

**创建 PDF 同名物理目录。** 这种方式能让原层级符合磁盘，但会推翻直接保存到所选目录的规则，也会阻止多次上传共享同一目标目录。

**隐藏批次行并只打开最新批次。** 这种方式能让目录树符合物理结构，却会使同一目录中的旧图片无法访问，因此目录选择会聚合全部直接批次。

## 后果

目录名称与图片数量会对应文件系统目录树，其中包括配置的根目录。向所选目录上传一份或多份 PDF 只会更新该目录的图片数量，不会增加 PDF 同名子节点。Web 目录行不再提供整批删除操作；单张图片删除与物理目录删除仍然保留，Host 与模型操作继续支持按准确批次删除。

## 测试

客户端回归测试会在同一目录挂载两个持久化 PDF 批次，断言层级中没有任一批次名称，并通过目录行打开两份图片。组装 Web 场景会把持久化批次保存到嵌套物理目录，证明 PDF 名称与批次 id 目录都不存在，等待同一个目录行显示图片数量，再在没有批次子行的情况下打开图片。
