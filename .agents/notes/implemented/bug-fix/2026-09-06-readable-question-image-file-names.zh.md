# Agent Note：可读的试题图片文件名

状态：已实现

[English](2026-09-06-readable-question-image-file-names.md) | 中文

## 问题

试题裁剪元数据包含 `第1题.png` 这样的可读名称，但持久化批次和带元数据的学生分发会用生成的 id 写入物理文件。因此，应用显示正确题号，而教师直接打开同一目录时只能看到不透明名称。通过文件系统扫描发现的分发路径已经保留可读名称，所以结果还取决于来源和目标是否具有持久化元数据。

## 决策

每张新持久化裁剪图片和学生副本都会把经过校验的显示文件名同时用作物理文件名。全部保存和分发路径共享同一条独占名称分配规则；批次文件以同一根目录中待定文件的完整硬链接进入所选目录，分发文件则使用独占复制。如果首选名称已经存在，或者被同一试题库目录中的既有持久化图片保留，Host 会在扩展名前追加第一个可用的数字后缀。最终名称会写入元数据和分发相对路径，使应用显示和直接文件系统访问指向同一个文件。

不透明 id 继续作为记录身份，不再作为存储名称。批次读取和当前根目录扫描会先解析可读名称，再为本次修改前写入的记录接受旧的 id 文件名。该兼容读取不会重命名或覆盖既有文件。本决策只取代原始[试题切割工作台](../feature/2026-08-19-question-segmentation-workbench.zh.md)决策中有关物理不透明文件名的说明；原记录继续负责媒体层级与生命周期。

## 已考虑的替代方案

**只重命名学生副本。** 教师也会直接打开试题库目录；如果批次裁剪继续使用不透明名称，同一问题仍会存在于来源端。

**启动时重命名既有文件。** 批量修改可能与应用外新增的文件冲突，也会让启动过程承担规模不确定的迁移。读取兜底无需修改既有目录即可保留访问能力。

**复用可读名称并替换既有文件。** 重复分发以及同一目录保存多个批次都是有效工作流。替换会无提示地破坏更早的裁剪图片，因此名称分配使用独占创建。

## 结果

新试题库文件和学生文件在应用外仍然容易辨认。重复副本依次获得 `-2`、`-3` 等后缀，应用显示最终选定的准确名称。既有 id 命名文件仍可读取、编辑、扫描发现和删除，并保持原名称，直到教师替换或重新保存。

本记录保持活跃，因为今后的媒体持久化和迁移工作必须维持显示名称与物理名称一致、独占且不覆盖的行为，以及旧文件的查找顺序。本次活跃记录审计未发现被这项聚焦存储规则完整取代的更广泛记录。

## 测试

Host 集成测试保存包含第 1、2、10 题的一个批次，并在物理试题库目录中断言对应的准确名称。测试会分发这些图片两次，要求第 1 题的第二份副本使用 `第1题-2.png`，并校验全部学生文件名。随后，测试把一张来源文件改为旧的不透明 id 形式，证明直接读取和当前根目录扫描仍会保留该图片。
